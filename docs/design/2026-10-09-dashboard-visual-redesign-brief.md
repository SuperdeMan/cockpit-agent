## 0. 一页速读

**结论**：可观测台的数据底座是对的：会话 / 轮次 / span / LLM / 日志按 trace 贯通，SQLite 持久，读写要运维令牌。问题在前端：一张「深空 HUD 演示屏」的皮，套在一个每天用来排查 badcase 的工作台上。字太小，判语不准，时间线的画法对不上真实数据，而且三端里只有它的视觉不同源。

**五个主要问题**（证据见 §2）：

1. **字太小，装饰太多**。
   - 5 个视图里 4 个有 92–100% 的字符小于 12px，日志是 100%。CSS 里有 17 种字号，最小 7.5px。
   - 网格、角饰、扫描线和呼吸点常驻，后两者一直在循环。没有 `prefers-reduced-motion` 分支，也没有键盘焦点样式。
2. **判语不准**。
   - 列表和详情的第一判语是管道状态 `status`，显示成绿色「成功」。
   - 最近 1000 轮里，`status=ok` 的有 7 轮规划失败、3 轮执行失败、8 轮缺权限、83 轮已取消；1000 个会话的「错」计数全是 0。
   - 真正的终态账本 `outcome`（8 类 37 种）只是详情里一枚灰色小标签。
3. **信息架构与数据形态对不上**。
   - 每个会话的轮数中位数是 1（P90 是 2，94% 是 e2e），所以「会话 → 轮次 → 详情」三栏里，中间一栏几乎永远只有一行。
   - 只能按文本搜，不能按结局、来源、时间、分歧筛。
   - 面板右上角的「50 / 100 / 300」是请求上限，不是总数。
   - 请求失败被吞成「暂无数据」。
4. **时间线的画法对不上数据**。
   - 真实 span 里 61% 时长为 0，没有一条带父子关系，64% 落进兜底灰色。
   - 节点色和状态色撞色：端侧绿与成功绿相同，挂起琥珀与警告琥珀相同。
   - 每行都挂一枚「OK」。
   - LLM 调用不在时间轴上：截图里 6.4 秒的那一轮，3 次 LLM 调用共 4.8 秒，一根条都没画。
   - `llm.call.meta` 这种伪 span 占 14%。
5. **几处不诚实或越界的表达**。
   - 车况 26 个键里 6 个以英文键名落进「其他」。
   - `Dynamics.tsx:16` 在 UI 里写死「车速 > 120」，是 VAL 判据的第二份。
   - R / N / D / S 挡位按钮的文字对比度只有 1.1:1，看不见。
   - LLM 用量把「未上报」画成 0。

**目标**：
- 桌面工作台的尺度；
- 先给结局，再给管道状态；
- 时间线按真实数据的形态来画；
- 深浅两套主题同权；
- 与 HMI v2 同源；
- 所有视觉值都进 Figma 变量，并对应到代码 token。

**推荐方向**：B「同源控制台」（§4）。
- 品牌原色、语义色、字体方案与 HMI v2 同名同值。材质换成桌面工具的：不透明的色调分层、一层细线，不用玻璃，也没有装饰动画。
- 以「轮次」为主线：扁平的轮次流，加一个检查器（时间线 / 规划 / LLM / 日志 / 原始 JSON）。
  - 会话降为上下文条和分组开关。
  - 收藏并入为一个预设筛选。
  - 重放对照用同一个检查器分成双栏。
- 时间线按泳道分组：
  - 位置表示所在的层；
  - 条形用单一颜色，只有失败和挂起才上状态色；
  - 时长为 0 的画成标记；
  - LLM 调用与日志放进同一条时间轴。
- 实况保留为演示台：指令 → 链路 → 车况联动。模拟环境收进单独的调试区，和车况回显在视觉上分开。

**不变的东西**（§3.2）：
- collector 接口与 WS 帧的语义；
- 安全边界：不直接写车控，调试只设环境量，令牌只存本页会话；
- 内容采集门控；
- 观测通道尽力而为。

要补的接口单列在 §13，都不改表结构。

**Figma 侧前提**：2026-10-09 跑 `whoami`，账号是 Pro 计划 + Full 座席，可以写画布。HMI v2 文件已有可对照的 Foundations。本稿新建一个独立文件，不改 HMI 文件。

## 1. 产品与使用情境

### 1.1 谁在用、做什么

| 任务 | 频率 | 现在怎么做 | 卡在哪 |
|---|---|---|---|
| T1 排查一轮（badcase） | 每天 | HMI 开发者模式复制 trace → 粘进搜索直达 → 往下翻详情 | 判语是「成功」；时间线看不出时间花在哪；标注、badcase、导出挤在头部 |
| T2 扫一批找问题（发版、e2e、QA 轮之后） | 每周数次 | 在会话列表里逐个点 | 不能按结局 / 来源 / 时间 / 分歧筛；e2e 会话淹没真实会话；「错」计数恒为 0 |
| T3 演示 / 对照实验 | 演示时 | 在总览页发一句，看链路和车况「刚变」 | 链路区是 30 条 trace 的长列表；车况面板在 1440×900 下只露出空调一组；模拟滑块和车况回显是同一种皮 |

| T5 翻日志 | 排查时 | 日志视图过滤 | 全是 10.5px 等宽字；截图里一轮有两条 WARNING 交替各出现 3 次；长消息在 1000 字处截断 |

- 用户是你（运维 / 开发者），偶尔有演示观众。
- 界面里没有车主。这是运维工具，主体是运维者（[调试面访问](2026-10-03-v2-collector-access.md)）。

### 1.2 屏幕与视距

- 主场景：桌面显示器 1920×1080，视距约 60cm。
- 次场景：笔记本 1440×900（1536×864 归同一档）。
- 宽屏：2560×1440，多一栏。
- 演示：同一页投屏或共享屏幕，观众在 2–4m 外。
  - 所以需要一档放大（§10）。
  - 不靠浏览器缩放：缩放会改变断点，把栏挤掉。
- HMI 的车机尺度（正文 24px）不适用。这里信息密度优先，起点是正文 13–14px、元信息 12px，与 Linear、Grafana、Datadog 这类工具同一密度带。

### 1.3 与 HMI v2 / Android v3 的关系

- **同源的部分**：
  - 交互蓝 `#46D6E0` / `#0369A1`；
  - 深空底 `#06080F` / 晨雾底 `#EDF1FA`；
  - 文字三级，警告 / 危险 / 成功色；
  - 字体方案：Inter + JetBrains Mono 自托管，中文用系统字体栈；
  - 24 格、1.8 描边的线性图标；
  - 两条规则：语义色同时给文字或形状；UI 只投影服务端判据。
- **不同的部分**：
  - 尺度是桌面级；
  - 材质全部不透明，因为背后没有舞台可透；
  - 极光不用于数据，只留在产品标识里（§5 P3）；
  - 没有光球；
  - 浅色是工作日白天的常用档，不只是阳光档。
- 三端仍然不共享 UI 组件。共享的只是图标数据和 token 值，用测试对账（§12）。

- **单测**：8 个测试文件覆盖令牌、瀑布、链路、车况、LLM 视图。

### 2.2 问题（按影响排序，附证据）

**H1 尺度与装饰：演示屏的皮套在工作台上**

- 渲染字号（headless Edge，按可见字符计）：

| 视图 | 小于 12px 的字符占比 | 主要字号（px） |
|---|---|---|
| 会话（未选中） | 94% | 11.5 / 9.5 |
| 会话下钻 | 96% | 10.5 / 11.5 / 9.5 |
| 总览 | 54% | 12 / 9.5 / 11 |
| 日志 | 100% | 10.5 / 9.5 / 9 |
| LLM | 93% | 10.5 / 11.5 / 9.5 |
| 收藏 | 92% | 11.5 / 9.5 |

- CSS：`font-size` 声明 81 处、17 种取值，其中 50 处 ≤11px。最小的是 7.5px（「刚变」角标，`styles.css:212`），其次是 8px（分组英文、Agent 种类标签）。
- 字体：
  - 标题用 Chakra Petch，数据用 Space Mono，都走 Google Fonts（`index.html:11-16`）。
  - 两者都没有中文字形，中文回落到系统字体。
  - 按字符计，各视图里 Space Mono 占 38–99%（日志 99%），日志里的中文也排在等宽体里。
- 装饰：
  - 网格底纹、7.5 秒一周的扫描线、面板角饰、连接呼吸点（`styles.css:76-96`、`:112-116`、`:132-134`）；
  - 常驻 2 个循环动画（扫描线、呼吸点；离线时呼吸点换成闪烁），没有 `prefers-reduced-motion` 分支。
- 每个面板标题都配一行大写英文（`SESSIONS`、`TURN DETAIL`、`REQUEST TRACE`），页脚是 `OBSERVABILITY CHANNEL · BEST-EFFORT`。这些只是重复中文，不提供信息。

**H2 判语：「成功」不等于这一轮成了**

- 列表与详情的第一判语是 `status`（`SessionsView.tsx:38`、`TurnDetailPanel.tsx:177`）。
- 最近 1000 轮的 `status × outcome` 交叉表：

| status | outcome | 轮数 |
|---|---|---|
| ok（显示为绿色「成功」） | completed | 745 |
| ok | cancelled | 83 |
| ok | pending_slot | 41 |
| ok | permission_missing | 8 |
| ok | planner_failure | 7 |
| ok | unresolved_object / no_plan / failed / partial / cancel_unresolved / 空 | 5 / 4 / 3 / 2 / 1 / 2 |
| need_confirm | pending_confirm | 84 |
| rejected | not_addressed | 11 |
| clarify / cancelled | clarify / completed | 2 / 2 |

- 会话列表的「错」只数 `err`、`timeout`、`empty` 三种状态（`db.py:338`）。结果 1000 个会话里没有一个显示有错。
- 终态账本 `outcome` 有 8 类 37 种（`runtime/outcome.py:39-84`）。界面只把种类原样显示成一枚小标签，并用正则猜要不要标黄（`TurnDetailPanel.tsx:195`）。
- 截图里有一轮的话术是「地图服务暂时不可用，没查到『海岸城』」，头部是绿色「成功」加 `completed`。
  - 终态账本按机制记账：Agent 返回 OK 就记 completed（`runtime/outcome.py` 头注「只记机制，不猜语义」），所以结局本身也是「已完成」。
  - 能看出这一轮其实降级了的，只有同一轮里 6 条高德配额耗尽的 WARNING，而它们排在详情的最底部。
  - 所以新设计除了结局，还要把「有告警」作为一等标志放进列表行和判语行（§6.2、§6.3）。

**H3 信息架构与数据形态对不上**

- 会话：
  - 最近 1000 个会话里，每个会话的轮数中位数 1、P90 2、最多 9；
  - 943 个是 `e2e-`，51 个是 `cloud-release-`，6 个是 `app-`；

- 失败被吞：6 处 `.catch(() => set…([]))`（`SessionsView.tsx:67,73`、`LogsView.tsx:28`、`LlmView.tsx:31`、`BadcasesView.tsx:20`、`TurnDetailPanel.tsx:117`）。401、500、断网都显示成「暂无数据」。

## 3. 目标、不变量与非目标

### 3.1 目标

- **G1 桌面工作台尺度**：
  - 正文 13–14px，元信息 12px，11px 只给徽标和坐标轴；
  - 控件高 32px，紧凑行 24–28px；
  - 演示档整体 ×1.25。
- **G2 先给结局，再给管道状态**：任何列表和检查器的第一判语都是终态账本的分类与种类，`status` 降为次要信息。
- **G3 排查三步内**：粘贴 trace 或点一行之后：
  - 首屏能看到原话、话术、结局、规划落域、时间分布、失败点和告警日志；
  - 从列表到失败的 span 不超过 3 次点击。
- **G4 时间线按数据形态来画**：泳道分组，时长为 0 的画成标记，LLM 调用和日志进同一条时间轴，颜色只给异常和焦点。
- **G5 诚实**：
  - 显示真实数量；
  - 失败和「空」分开表达；
  - 未上报不写成 0；
  - 模拟数据标「模拟」；
  - 内容未采集要标出来；
  - 写明观测通道是尽力而为的。
- **G6 同源**：品牌原色、语义色、字体方案、图标与 HMI v2 同名同值，用测试对账；深浅两套同权。
- **G7 可维护的设计源**：Figma 里颜色、字号、间距、圆角、尺寸全部绑定变量，code syntax 填 `--obs-*`。
- **G8 安静**：没有常驻的循环动画；实时更新只做一次性淡入；减少动效时全部静止。

### 3.2 不变量（本次不重开）

- **数据与接口**：collector REST 与 WS 帧（`api.ts`、`types.ts`）现有字段的语义不改。新增的派生字段只在 §13 列出，都不改表结构。
- **安全**：
  - dashboard 不直接写车控；
  - 指令与重放只走 Edge Gateway，车控仍经 VAL，确认仍由服务端驱动；
  - 调试只设环境量；
  - 令牌只存本页会话，只发给 collector。
- **内容门控**：`OBS_CONTENT_CAPTURE=off` 时只显示长度与指纹。设计要画出这一形态，不尝试补全。
- **观测尽力而为**：事件可能丢，界面不能暗示数据完整（例如不写「全部链路」）。
- **技术栈**：React 18 + TS + Vite + 全局 CSS。不引入 Tailwind、shadcn、图表库、动效库，也不用 Google Fonts。
- **共享边界**：不和 HMI、mobile 共享 UI 组件，只共享图标数据与 token 值。
- **单一声明源**：
  - 节点到泳道的映射只有一份（`spanMeta.ts` 的继任者）；
  - 结局分类来自服务端 `runtime/outcome.py`；
  - 来源分类来自 collector 里的一张前缀表（§13 C2）。

### 3.3 非目标

- 这个阶段不写代码；实施计划在设计定稿后另立。
- 不做时间序列图表。collector 没有时序接口；Prometheus / Grafana profile 维持现状。
- 不做多车切换。collector 支持 `vehicle_id`，但当前只有 `v1`。`App.tsx:83` 写死的 `v1` 等有第二辆车时再改。
- 不做账号和角色；访问仍用运维令牌。
- 不做 1024px 以下的布局，只写规则。
- 不修 §2.4 的数据问题。

## 4. 设计方向

| | A 保留 HUD，只修系统 | **B 同源控制台（推荐）** | C 中性通用后台 |
|---|---|---|---|
| 视觉 | 深空 HUD（角饰、扫描线、Chakra Petch） | HMI v2 品牌原色 + 桌面工具材质：不透明、细线、无装饰 | 中性灰蓝，像 Grafana / Datadog |
| 信息架构 | 五个视图不动 | 轮次主线 + 检查器页签；收藏并入；实况重做因果链 | 多面板仪表盘 |
| 时间线 | 只修颜色 | 泳道 + 单色条 + 异常上色 + 事件标记 | 未定 |
| 与 HMI / Android 一致 | 低（第三套视觉） | 高（同名同值） | 低 |
| 能修到 H1–H8 | H1 与 H6 的一部分 | 全部 | 只有视觉部分 |
| 工作量 / 风险 | 小 / 小 | 中 / 中（IA 改动 + 少量接口） | 中 / 中 |

**推荐 B 的理由**：

- 问题不止在皮。判语（H2）、架构（H3）、时间线编码（H4）、实况因果链（H5）都是结构问题，A 修不到。
- 「工程感」不该靠装饰。HUD 角饰和扫描线在演示时好看，排查时是噪音。可信感来自准确的数字、清楚的判语和稳定的对齐。
- HMI v2 与 Android v3 已经把品牌层定好了。可观测台是同一个产品的后台，再起第三套视觉只会继续漂移。
- C 丢掉了品牌，工作量也没有更少。

**B 的具体主张**：

1. **轮次是主线**。默认页是扁平的轮次流，最新的在上，每行是一句话的完整判语。会话变成分组开关，以及检查器里的上下文条。
2. **检查器分页签**：
   - 概要头常驻：原话、话术、结局、落域、分歧；
   - 下方页签：时间线 / 规划 / LLM / 日志 / 原始；
   - 标记 badcase、标注落域、导出、重放都收进动作条和弹层。
3. **结局徽标**：色调由服务端分类决定，文字与图标由种类决定（附录 C）。
4. **泳道时间线**：见 §6.4。
5. **收藏 = 预设筛选**：
   - 收藏页签直接打开「已标 badcase」筛选；
   - 重放对照就是检查器分成双栏，共用一把时间刻度。
6. **实况演示台**：
   - 只画当前这一句的链路；
   - `val.execute` 的 diff 与车况「刚变」联动；
   - 模拟环境放进带斜纹标识的调试区。
7. **材质**：
   - 层级：页面底 → 面板（不透明 surface/1）→ 抬起层（surface/2，用于弹层和选中）；
   - 一层 1px 细线；
   - 不用 `backdrop-filter`、光晕和角饰。
8. **两档尺寸**：工作台 / 演示，用 Size 变量的两个模式实现。

## 5. 设计原则（每条都有判据）

| # | 原则 | 判据 |
|---|---|---|
| P1 | 排查优先 | 1920×1080 下选中一轮，不滚动就能看到原话、话术、结局、落域、时间线前 10 行和失败点 |
| P2 | 先给结局，再给管道状态 | 列表行与检查器头的第一枚徽标是结局；`status` 只作次要标签 |
| P3 | 颜色只给状态与焦点 | 条形和标记默认单色；状态色只给失败、挂起、警告；交互蓝只给可点和选中；极光不进数据区，只用在产品标识上 |
| P4 | 状态不只靠颜色 | 每个状态色都配图标 + 文字。实测红色盲模拟下，绿与琥珀的色差只有 ΔE 4.7 |
| P5 | 诚实 | 数量写「最近 N 条」或真实总数；空、失败、未授权、断连、未采集、已过保留期六种形态各有画面；未上报写「—」；模拟数据标「模拟」 |
| P6 | UI 只投影服务端判据 | 不写车速阈值；结局分类、来源分类来自 collector；前端只做显示映射（附录 C） |
| P7 | 可读的密度 | 正文 ≥13px，元信息 ≥12px，11px 只给徽标与坐标轴；正文与元信息对比度 ≥4.5:1 |
| P8 | 深浅同权 | 每屏、每个组件都有深浅两版，两版都满足 P7，图形 ≥3:1 |
| P9 | 安静 | 常态没有循环动画；实时到达只做一次 200ms 淡入；「刚变」高亮 2.5 s 后褪去；减少动效时全部静止 |

  - 落域（`intents`）；
  - 端云分歧：`edge_nlu` 带 `!=` 时显示「≠ 端侧初判 X」；

  - 从 `cloud.planning.attrs.plan` 解析出步骤表（id / agent / intent / slots / depends_on）；

  - LLM 原始输出默认折叠。

- **泳道**：
  - 固定顺序：端侧 → VAL → 规划·LLM → Agent → 外部服务 → 云端编排 → 语音 → 其他 → 日志；
  - 只画有内容的泳道；
  - 节点到泳道的映射见附录 D，代码里只有一份（`spanMeta.ts` 改为 `laneOf`）。
- **泳道头**：
  - 图标 + 名称 + 条数；
  - 可折叠，折叠后显示摘要：次数 · 合计时长 · 失败数；
  - 外部服务默认折叠，因为每轮常有 6–8 次 provider 调用。
- **条形**：表示有时长的 span 和 LLM 调用。
  - 尺寸：高 12（演示档 16），圆角 3，最小可见宽度 4px；
  - 颜色：默认单色 `data/bar`，悬停加亮，选中用交互蓝；
  - 文字：名称在条左侧，放得下才放进条内；时长在条右侧（`mono-sm`）。
- **标记**：表示时长为 0 的 span。
  - 普通事件：8px 实心圆 + 2px 面板色描边；
  - shadow 判定（`nlu.shadow`、`decision.shadow`）：空心圆，表示「只观测、不影响执行」；
  - `cloud.outcome`：旗形，带结局种类。
- **状态**：只给异常上色。
  - `err` / `error`：危险色条或标记 + ✕；
  - `wait` / `need_confirm` / `need_slot`：挂起色描边 + ⏱；
  - `ok`：不画任何状态。
- **日志道**：每条日志一个刻度。
  - WARNING 用警告色 ▲，ERROR 用危险色 ✕，INFO 是小灰点；
  - 悬停看消息；点击跳到日志页签并定位到这一条。
- **轴**：
  - 范围从 `turn.ts` 到 `turn.ts + duration_ms`；
  - span 的 `ts` 近似当作结束时刻，起点 = `ts` − 时长（与现有实现、OTel 桥是同一个近似）；
  - 落在轮次之外的部分用灰底，并标「轮次外」；
  - 刻度用 `mono-xs`，竖向细网格线。
- **选中详情**：在时间线下方；宽度 ≥1680 时改为右侧 360px 的抽屉。
  - span：泳道、状态、时长、相对起止、attrs（KV 表，长值折叠，可复制）；
  - LLM 调用和日志：与 LLM、日志页签的展开态相同。
- **表格视图**：时间线右上的「列表」可切换成按时间排序的表（时刻、泳道、名称、时长、状态）。它是这张图的无障碍等价物。
- **实时形态**（实况页用）：新 span 到达时轴向右延伸，新行 200ms 淡入；减少动效时直接出现。

- **指令台**：
  - 输入框 + 发送键（「发射」改为「发送」，交互蓝实色）；
  - 快捷指令芯片，最多 5 个，键盘可达；
  - 回复区：状态（空闲 / 连接中 / 执行中 / 完成 / 失败 / 连不上网关）+ trace 短 ID（点击在轮次页打开）+ 流式话术；
  - 这里的「完成」只表示请求拿到了最终结果，不是结局，所以用中性色；
  - 证据另给一枚「车身变化 N 项」芯片，数据取自 `val.execute` 的 `changes`。
- **本句链路**：
  - 只画当前这一句，用 §6.4 组件的实时形态；
  - 之前的 trace 收成一行行摘要（原话 · 结局 · 耗时），点开去轮次页；
  - 端侧本地轮没有终态账本，摘要徽标写「ok · 无账本」（§8.3）。
- **端侧本地轮实测**（2026-10-09，云端 collector 最近 2000 轮（取数上限），其中 12 轮走本地，全是 e2e；span 抽看 4 轮）：
  - 回复耗时 7 轮在 1.5–4 ms，5 轮在 280–330 ms；
  - `val.execute` 0.1–0.4 ms，`route.local` 紧随其后、零时长；
  - `nlu.shadow` 在轮次结束之后约 5–25 ms 才到，落在「轮次外」；
  - 所以实况轴用 ms，并随影子判定向右延伸；
  - `changes` 可能是空列表（车本来就是那个状态），这时芯片写「无变化」，车况不高亮。
- **因果联动**：
  - `val.execute` 标记带 diff 芯片，例如 `hvac_temp 24 → 26`；
  - 车况里对应的格子高亮 2.5 s，名称后标「刚变」；格子高度不变，实况里不跳动；
  - 变化前后的值看 diff 芯片，trace 短 ID 放进悬停提示；
  - 悬停 diff 芯片时对应格子描边，悬停格子时对应芯片描边。
- **车况**：
  - 按组排紧凑格（图标 + 名称 + 值），保留空调、氛围灯、媒体三个聚合格；
  - 值写成文字（开 / 关、已锁、70%），**不画成开关**；
  - 读不到的信号画「读不到」格，不留空、不填 0；
  - 未建模的键放在「其他」里，显示原键名 +「未建模」标签；
  - 头部常驻来源标签，取自 v2 观测元数据。
- **模拟环境**（默认收起）：
  - 标题条带斜纹底 +「调试」标签，说明写「只改模拟器的环境量（车速 / 电量 / 挡位），不经 VAL，不是车控」；
  - 车速、电量用滑块，挡位用分段控件（P / R / N / D / S）；
  - collector 返回 `debug disabled` 时整块置灰，写「调试写入已关闭（非开发环境）」；
  - 去掉 UI 自己算的「armed」和 120 这个数字，换成一句提示：「超速时开窗等指令会被 VAL 拦下：拖动车速后发一句『打开车窗』，看链路里的拦截」。
- **Agent**：
  - 网格小卡：名称 · 种类 · 健康 · 调用次数 / 平均时延 / 错误率 · 熔断与降级徽标；
  - 没有指标时写「启动后无调用」；
  - 有异常的排在前面；
  - `last_seen` 用相对时间。

### 6.6 日志

- **筛选行**：
  - 级别芯片：全部 / INFO / WARNING / ERROR，带计数；
  - 服务多选（18 个）；
  - 按内容搜；
  - 「只看带 trace」；
  - 条数：最近 300 / 1000。
- **表格列**：
  - 时刻（`mono-sm`）；
  - 级别（图标 + 文字）；
  - 服务（`mono-sm`）；
  - 消息：单行省略，点击展开全文；像 JSON 的消息展开后用代码块显示；
  - trace：短 ID，点击在轮次页打开。
- **不折叠**：全局日志保持时间顺序，不合并重复；合并重复只在检查器的日志页签里做（§6.3）。真实数据里重复的消息是交替出现的，按「连续相同」折叠几乎不会生效。
- **跟随**：默认跟随最新；用户往上翻时自动暂停，底部浮出「12 条新日志 · 回到最新」。

### 6.7 LLM 用量

- 筛选行：时间窗 1 小时 / 24 小时 / 7 天 / 30 天。
- 数字卡（主值用比例数字，不用表格数字）：
  - 调用次数；
  - tokens（入 / 出）；
  - 错误；
  - **未归属调用**：应为 0。大于 0 时用危险色 + ✕，标「归属盲区」；
  - **未上报用量**：tokens 为 0 的成功调用数。大于 0 时用警告色 + ▲。
- 表格：
  - 列：调用方 · 模型（mono）· 次数 · 输入 · 输出 · 占比（按 tokens 的单色条）· 错误 · 平均时延 · 最近调用；
  - 「(未归属)」行置顶，左侧加危险色条和文字标签；
  - tokens 为 0 的格子写「— 未上报」。

### 6.8 收藏与重放对照

- 收藏页签 = 轮次页 +「已标 badcase」预设筛选。这个筛选不受时间窗限制，因为 badcase 豁免保留期清理。行的第二行显示备注，不显示话术。
- 重放对照：
  - 检查器分成两栏：原轮 | 重放轮，两栏的概要头对齐；
  - 结局、落域、`plan_mode`、耗时、话术不同时加「不同」标记；
  - 两条时间线共用一把时间刻度；
  - 重放轮还没完成时显示进行中形态。
- 宽度 ≥2400 时，对照可以作为第三栏常驻。

### 6.9 访问与连接

### 8.6 数据可视化规则（按 dataviz 方法）

- 先定形式，再定颜色：
  - 时间线 = 泳道甘特；
  - LLM 用量 = 数字卡 + 表格 + 单色占比条；
  - 不做饼图，不做双轴。
- 条形不超过 24px，端点 3–4px 圆角；网格和轴用实线细线，比面板深一档，不画虚线网格。
- 标记 ≥8px，带 2px 面板色描边；命中区 ≥24px。
- 文字不用数据色：数值、名称、图例一律用文字色；颜色只出现在条形、标记和色块上。
- 每张图都有表格视图。悬停提示只做增强，不独占信息；键盘聚焦时显示同样的内容。
- 刷新时保持原画面、降低透明度，不闪骨架屏；只有首次加载才用骨架行。

  - 用顶栏的「演示」开关切换，状态存在本机 localStorage，读写包 try/catch。
- 投影仪会把暗部压得很厉害，所以投屏建议用浅色。设计两档都出。

## 11. 无障碍

- 对比度见 §8.2：正文与元信息 ≥4.5:1，图形与焦点 ≥3:1，深浅两版都核。
- 键盘：
  - 所有可点元素都是真按钮或链接，焦点样式统一；
  - 页签、分段控件、筛选芯片支持方向键；
  - 列表用 ↑↓ 移动、Enter 打开。这一条是行为新增，实施时再确认。
- 不以颜色作为唯一的信息载体：结局、日志级别、span 状态、连接状态都带图标 + 文字。
- 减少动效：没有常驻循环动画；新行淡入和「刚变」褪色在减少动效时取消。
- 读屏：
  - 图标按钮标注名称；
  - 时间线有表格视图；
  - 数字卡有完整读法，例如「未归属调用 397 次，应为 0」。
- 不嵌套交互元素（修 `BadcasesView.tsx:54-91`）。

## 12. 技术边界（设计必须能落地）

- **技术栈**：
  - React 18 + TS + Vite 8；全局 CSS + 新的 `tokens.css`；
  - 没有组件库、图表库、动效库，落稿时也不得引入；
  - 时间线用 DOM + CSS 画（条形是绝对定位的 div，或者一个 SVG），不用 canvas。
- **数据**：
  - 只能用 §2.3 与 `types.ts` 里的字段，加上 §13 列出的派生字段；
  - 样例数据取自真栈出过的形态（e2e 原话、真实节点名、真实 `plan_mode`），按最长形态排版；
  - 需要编造的（离线 Agent、熔断、ERROR 日志）标注「示例数据」。
- **共享**：
  - 图标数据从 HMI 共享表读取，经 Vite 别名还是构建期复制，实施期再定；渲染组件各写一份；
  - 品牌原色同值，由测试对账 `hmi/design/visual-v2.tokens.json`。
- **字体**：自托管 Inter / JetBrains Mono 的 latin 子集，与 HMI 同文件、同许可证；中文用系统字体栈。
- **URL 状态与夹具**：实施时要加：
  - `?view=&trace=` 深链；
  - 离线夹具 `?fixture=<名>`：不连 collector，从 JSON 渲染。

  没有这两样，就没法与 Figma 截图对照（落稿规则 §3.4）。
- **Figma 端**：
  - `use_figma` 单次返回不超过 20KB，必须严格串行，出错时整次回滚；
  - 不能导入图片，现状截图走 `upload_assets`；
  - 其余坑见落稿规则 §8.5 与 HMI v2 的记录。

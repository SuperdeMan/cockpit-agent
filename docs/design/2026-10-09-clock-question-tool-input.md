# 时钟问句：内置时间工具按这一步的用户原话作答（2026-10-09）

> 状态：已上线（`7035ef68`，随 `ff9bce82` 部署）。来源：核心旅程冻结 P1 读数（[`2026-10-09-v2-core-journey-freeze.md`](2026-10-09-v2-core-journey-freeze.md) §11.2，P06）。

## 0. 结论

- 「现在几点 / 今天几号 / 今天星期几」是系统自己持有的事实。判据收进 `runtime/clock_question.py`，作为全仓唯一的一份，
  由闲聊整句直答和内置 `datetime.parse` 共用。
- 规划器把这类问句派给 `datetime.parse`，却漏给槽（`{}`）或只给 `now` 时，工具改读**这一步的用户原话**
  （`step_raw_text`，派发经 `step_call_context`），逐分句认问句，按墙钟直答。
  槽是正常的时间表达（「明天19:30」）时，行为不变。
- 不改能力描述，不改规划器，不动 manifest（目录与契约指纹不变）。

## 1. 证据

- 核心旅程 P06（云端 `6280cdb0`）：「打开充电口，顺便告诉我今天几号」。规划器原始输出两步的槽都是 `{"$text": "{}"}`，
  装配时丢掉未声明的键，`datetime.parse` 拿到空槽，回「这个时间我没能换算出来，换个说法再试一次」。
- collector 90 天共 3426 轮，`datetime.parse` 派发 3 次，没有一次是正当的归一化：
  - 上面的 P06；
  - 真实用户在手机端问「what time is it now」，槽是 `{"text": "now"}`，听到的是同一句失败话术；
  - Q07「不要开空调，告诉我空调怎么开」，规划器自己加了一步 `{"text": "今天"}`，多播一句日期（不在本次范围，见 §3）。

  整句的「现在几点了」4 次都正确落到闲聊直答。
- 判据现在有两份：
  - 闲聊的 `_CLOCK_RE / _DATE_RE / _WEEK_RE` 是整句正则；
  - 工具里有一张精确匹配表（「今天几号 / 今日日期…」），是 2026-06-20 为「规划器把问日期派给工具」加的。

  两份覆盖面已经不一致：工具认「今日」和「日期」的写法，闲聊不认。

## 2. 设计

### 2.1 `runtime/clock_question.py`

- `bare_question(text)`：去掉礼貌前缀和语气尾词。闲聊的身份问句也用它，语义与迁移前逐字相同。
- `clock_question(text)` 返回 `"time" / "date" / "weekday" / ""`：
  - 整句判定，再去掉「告诉我 / 帮我看下 / 查一下」这类引导语，然后用 `^…$` 锚定；
  - 中文沿用闲聊既有的三条正则，补齐工具表里「今日」「日期」的写法；
  - 英文只认锚定的「what time is it (now)」「what's the date」「what day is it」。带地点的问法（「what is the time in London」）
    不认，因为换算时区不是这个判据能答的。
- `clock_question_in(text)`：按 `runtime.clause_split.SPLIT_MARKERS`（全仓唯一的分句）逐分句判定，取第一个命中。
- `spoken_time(now)` / `clock_answer(kind, now)`：口语化时刻和三种答句，从闲聊原样迁来，答句逐字不变。
  英文问句也答中文，与 Android N-01 的拒绝话术一致。

### 2.2 工具与派发

`datetime_parse(slots, now_fn, utterance)` 按下面的顺序处理：

1. 槽本身就是时钟问句 → 直答；
2. 槽为空，或只是「现在 / now」这类表示当下的词 → 按用户原话逐分句认问句 → 直答；
3. 否则按原逻辑归一化。另补一条：「现在 / now」归一化成当前时刻；
4. 仍然不行 → 原来的拒绝话术。

注册表把 `ctx.raw_text` 交给处理函数。派发对工具步改传 `step_call_context(step, ctx)`，与 Agent 步用同一份「这一步的原话」裁决：
续接轮里的下游步读自己的起点原话，不读「确认」。

### 2.3 闲聊

`_clock_answer = clock_answer(clock_question(text), now)`。

- 既有句式的行为逐字不变；
- 新增覆盖：「今日…」「…日期」的写法、引导语开头（「告诉我现在几点」）、锚定的英文问句。

## 3. 边界与不做

- 授权：这是只读工具，读原话不涉及授权，也不进 prompt。
- 不改 `datetime.parse` 的能力描述：那是软知识，改了要 A/B。规划器怎么派，都由确定性的一侧兜住。
- Q07 那类「规划器编出一步用户没问的日期」不在本次。如果槽不是用户说过的话就拒绝，用户会听到一句「没能换算」，
  比现在多播一句日期更差。留作观测。

## 4. 验证

- runtime 判据做两向用例，含劫持对照：「明天几点有比赛」「几点提醒我」「伦敦现在几点」「what is the time in London」。
- 工具用例：
  - 空槽，原话在问日期；
  - 槽是 `now`，原话是英文问时间；
  - 正常归一化不变；
  - 续接轮读起点原话。
- 闲聊既有用例不改动，全部通过。
- 变异：撤掉「按原话补」、撤掉英文、把逐分句改成整句，对应用例都应变红。
- 真栈：P06 × 5、R07 × 5，加上原句「what time is it now」。

# AR10：固定包整体 UX 验收方案

> 状态：**草案，未开始招募、设备操作或正式验收**；日期：2026-09-09。
> 交付对象：QA/UX 研究、mobile/后端工程、产品负责人。对应 R12，综合核验 R01～R14，并总核 R15。
> 入口：[接续路线](2026-09-09-android-ar06-ar11-execution-roadmap.md)、[原评审](../reviews/2026-09-07-android-ux-full-review.md)、[AR01～AR11 状态表](2026-09-07-android-review-remediation-batches.md)。

## 1. 验收要回答什么

对一份明确候选给出“哪些用户任务、设备和状态已通过，哪些仍不通过或未验”的可审核结论。通过单测、制作材料、完成修复与外部用户成功使用分别记账。

**完成一次验收可以得到不通过报告；“UX 完整通过”必须满足全部采用的签收条件。** 本批不在测试中途修包继续拼接全绿表，修复返回原责任批，形成新候选后重开受影响范围及必要的整体回归。

## 2. 入场条件与候选冻结

### 2.1 入场表

| 条件 | 要检查的证据 | 不满足时 |
|---|---|---|
| AR01～AR05 关键操作/采集/契约修复已汇合 | 实际代码、原方案未完成子项；尤其 AR05 §9.5 | 可做准备和受控回归；不可直接开始“完整通过”签收 |
| AR06 release 验证可用 | 固定 lint/tsc/Jest、中文输入、02/06 前提、真实验包 | 先修仪器；人工辅助明确记录 |
| AR07/08/09 采用方案固定 | 参数、声学路径、时延/UI 指标及剩余问题 | 未达项带入判定，不能由“AR 开发完成”推定通过 |
| 特殊反例可执行 | 受限 token、旧服务端、Redis 恢复、多 operationId 场景 | 由原批准备隔离反例或所需具体授权，不临时破坏生产来造错 |
| 五位外部测试者与设备范围明确 | 匿名编号、参与意愿、可用时段、设备覆盖 | 不凭开发者自评补人数；缺少支持格保留未验或用户明确缩范围 |

本批先用风险可控的测试环境完成否定/多操作用例，普通真人任务默认只读、取消或拒绝。真实商户写、最终付款、真实车控不作为普通 UX 测试素材。

### 2.2 冻结清单

保存：完整源 SHA、APK SHA-256/签名/versionCode/内嵌 build/设备 build、云端完整 release、实际 provider/model/音色、模型指纹、设置指纹、网络、工具版本、协议版本及 UI 素材版本。只保留非敏感配置。

两机同一 APK；Xiaomi 对照结果独立列。验收中途源码、APK、服务器、provider、KWS/端点或关键设置改变即记录新轮；字体/网络等计划内矩阵变化属于该 case 的前提，不能静默变化。旧历史证据保留原 SHA，只用于定位和构造回归。

## 3. 五人状态识别与真实任务

### 3.1 参与者与执行方法

五位未参与本次实现、同意测试的真人，编号 P01～P05；角色分工只指定 UX 主持、观察记录与技术支持，不编造人员姓名、报名或已授权联系。招募材料可提前写好，本次与后续 Agent 均不自动向他人发邀请，除非用户明确授权发送。

状态识别先于操作教学，随机化材料顺序；主持不解释光球颜色/按钮用途。任务只给目的，允许用户自然探索；卡住后可按预定时间给予提示，但将“独立完成”和“提示后完成”分开。

| 状态材料 | 用户需要识别的事实 |
|---|---|
| idle | 当前没有收音/等待动作；知道怎样开口 |
| armed | 正在本地监听唤醒，不等于云端持续 ASR；使用当前真实材料 |
| listening | 正在收取用户输入，知道如何取消误录 |
| thinking | 已发送、正在处理；麦是否仍开以采集提示为准 |
| speaking | 正在播报，知道只停止声音的入口 |
| attention | 在等当前指定操作的确认/补槽，知道对象与后果 |
| offline/degraded | 连接/服务受限与恢复入口可理解，不能误以为业务成功 |

图片/短视频从本轮候选实际状态获取；画廊只能补说明，不替真实状态证据。armed 没有真实材料就该格 NOT_RUN，不能沿用 B5 七图分母。

### 3.2 任务脚本与成功定义

| ID | 给用户的任务 | 独立成功判据 |
|---|---|---|
| U01 | 第一次找到入口并问一个天气/事实问题 | 找到入口、发出正确请求、读懂回答/来源或真实降级 |
| U02 | 误触开始收音后取消 | 采集停止、无迟到上传/请求，不把“停止声音”当取消录音 |
| U03 | 长回答尚在播报时只让它安静 | 一步只停播、不开始新采集；final 先到仍能操作 |
| U04 | 有多项待处理，只取消第二项 | 指定 operationId 正确，其他项保持；本地定位征询不截走 |
| U05 | 拒绝位置授权并继续提问 | 无定位调用/坐标上行，后续给定城市问答仍可用 |
| U06 | 断网后恢复并处理排队请求 | 分清排队/失败/成功；取消的未发送请求不复活，未取消请求不重复 |
| U07 | 需要补充信息时补槽、换题后再找到原任务 | 真实 slot/held 输入，知道补什么；chips/归属/关闭行为正确 |

U04 先用无执行副作用的受控完整链路，随后在获准的真实确认→取消场景对账；样本卡按钮 no-op 不算任务成功。U06 的系统网络变更只在 OPPO、按具体授权执行，恢复回读；Xiaomi 不跑改设备状态探针。

### 3.3 建议计分

状态识别按每状态≥4/5 正确，整体不能掩盖单个状态；任务按每项≥4/5 独立完成。所有错误/提示记录原始人数，5 人只用于形成性可用性结论，不支持用户总体成功率推断。

安全和控制判据不能平均：U02～U05 发生任何错对象、误执行、取消后复活或未授权采集，直接未通过。建议记录首次找到入口/总耗时/错误点击/提示次数，U01～U07 预设 120s 独立探索窗；超窗失败后仍可继续观察，不能抹掉首次失败。门槛在正式测试前冻结。

## 4. 设备、系统与无障碍矩阵

| 设备/条件 | 角色与范围 | 签收证据 |
|---|---|---|
| OPPO PEUM00 / Android 14 | 默认测试机；默认兼容窗、外/内屏、经授权全屏 | 实际 window dp、布局 mode、物理 display、截图/操作；不能假设展开就双栏 |
| Xiaomi MIX Fold 4 / Android 16 | 用户主用对照机；同包同语料、可达的 driving-landscape/折叠形态 | 对照数据分列；不改系统状态、不打断用户会话 |
| 普通直屏 | 至少一台处于最终支持范围内的实际直屏设备 | 紧凑窗口、键盘、200% 字号、读屏；借不到写 NOT_RUN |
| 真平板 | 仅当保留平板交付承诺时列为必要 | 双栏、横竖屏、多窗口/触控；折叠内屏不能代替 |
| 最低/最高承诺 Android | 启动时从 APK manifest 和依赖读取实际 min/target SDK，再对照原 Android 10+ 承诺 | 不能为兑现旧说法强行降 minSdk；不匹配交产品决定支持范围 |

设备不足时可用模拟器补纯逻辑/布局辅助证据，但本工程当前 ARM ABI 与模拟器兼容要先核，且不能替代真实音频、OEM 生命周期或实际设备支持结论。范围缩减必须明确被用户采用，不能通过标 N/A 自动完成。

无障碍至少覆盖系统 200% 字号、长中文摘要、多待办、横屏、键盘、TalkBack 焦点/朗读/可操作、Scanner 的核心触控/对比度问题，以及减少动效。读屏验证包含停止、确认、取消、拒绝定位、补槽和返回；动态文本不反复夺焦点。工具扫描与真人/人工检查互补，见 [Android 无障碍测试指南](https://developer.android.com/guide/topics/ui/accessibility/testing)。

不能拿 App 内“大字档”替代系统 200% 字号。系统设置写入或工具安装若需额外权限，在材料与预期结果就绪后按红线处理；已有拒写记录不能永久当作所有设备都不可验。

## 5. 生命周期与业务组合

全排列会使规模失控。本批先覆盖每个关键状态，再固定以下高风险交叉；其余普通项按成对覆盖，生成明确 case_id，不只列“已测前后台”。

| ID | 必测组合 | 观察 |
|---|---|---|
| X01 | 定位/视觉准备中取消、离线队列取消再回网 | 真实帧、取消代际与零迟到副作用 |
| X02 | 三个服务端挂起 + 本地定位、过期/重排时选择末项 | operationId、截止时间、剩余台账 |
| X03 | final 后仍播报 × 横屏 × 200% 字号/键盘 | 两个停止出口与 Dock 可达，不能先收层才操作 |
| X04 | 提醒到达 × 对话/设置/地图/后台/Keyguard | received/presented/handled/ACK 分清；回前台一次呈现播报 |
| X05 | 收音/播报/补槽中切页、折叠、分屏及回前台 | 采集与声音撤回符合范围，草稿/文字终态/待办不串不丢 |
| X06 | OS 麦/摄像头/定位权限撤回 × 免唤醒/S2S/视觉 | 事实提示一致、不会迟到上传，恢复后至少三轮可用 |
| X07 | 多段/mixed/S2S/主动消息 × 停播/继续对话 | 全文与声音一致、不漏段、不误开麦；由真人完成盲听 |
| X08 | 网络切换/鉴权失效/旧服务端/部分成功 | 恢复入口正确，旧请求/旧账号不重放，不把已执行改写未执行 |
| X09 | keep-awake × 前后台/锁屏/省电 | 系统实际窗口状态、采集边界与偏好恢复；release 下取证 |

AR05 受限 token、Redis 恢复、旧协议故障另建子项，优先在隔离环境执行；不为验证删生产数据或重启别人正在用的服务。隔离结果与真实生产证据分列，不互相冒充。

## 7. 执行阶段与交付物

1. **准备**：回填入场条件、未签收子项、匿名参与者模板、任务脚本、设备/权限前提、冻结清单。
2. **工程预检**：固定包 smoke、业务与生命周期反例先跑，已知会误执行/采集的缺陷未处理前不交外部用户。
3. **用户测试**：逐人任务与状态识别、误操作/提示/耗时原始记录；不由 Agent 代填用户答案。
4. **组合矩阵**：OPPO 主验、Xiaomi 对照、所承诺其他设备和无障碍，记录原始测试与恢复。
5. **汇总与处置**：拟新增 `docs/reviews/<执行日期>-android-ar10-fixed-release-ux-acceptance.md`；列总评、逐格结果、未达项、明确支持范围、回流批次和复验范围。测试中换候选另建轮次。
6. **当前入口**：依据报告生成带日期 Android handoff，更新 mobile/设计索引/AGENTS 的短指针，向 AR11 交付真实基线。

验收记录只用 `PASS/FAIL/NOT_RUN/BLOCKED`；N/A 需写不适用依据及采用的范围决策。报告附每项 case 的包/云端/参与者/前提/证据/台账，不能只填“通过”。结束恢复本批占用的设置与测试数据状态；涉及删除的数据只按已有明确授权处理并保存归零证据。

## 8. Goal 文本与完成条件

执行方式以[工程交付与集中验收安排](2026-09-10-android-goal-delivery-and-acceptance-plan.md)为准。下面两种目标在启动时选择；默认采用工程交付目标，本文完整验收矩阵仍保留。

### 工程交付 Goal（默认）

> 按 AR10 方案完成验收工程准备及自动验证：核对前序子项与当前候选，落地完整任务/状态材料、计分与版本冻结表、组合矩阵和报告模板；先执行所有已具备条件且安全的自动用例，发现产品失败返回原批修复并形成新候选。五人测试、指定设备/无障碍与必要外部权限集中后置，交付每项可直接执行的步骤、所需人员/条件和成功判据。准备目标完成不代表正式 UX 通过。

### 正式验收 Goal（另行启动）

> 按 AR10 方案准备并完成固定候选的整体 UX 验收：核齐前序关键条件，冻结 APK、云端、模型和设置，完成五位外部用户状态识别与真实任务、设备/无障碍/生命周期高风险交叉，逐项记录原始证据并给出通过/不通过/未验结论。发现问题返回原批修复，换包开新轮；不借旧包读数、不虚构用户或缺失设备结果。交付正式验收报告及当前 Android handoff，再把实际基线交 AR11。

本目标若按“完成验收并交付报告”执行，允许结果不通过；若用户要求“让 UX 通过”，则相关失败与缺失的必要格解决之前目标未达成。两者必须在 Goal 原文中区分。

# 唤醒后连续对话的拒识：续问窗收进人人对话

- 状态：落地中（2026-10-10，用户授权提交、推送、部署与真栈验证）
- 交付对象：云端编排（`orchestrator/cloud`）、共享语音状态机（`hmi/src/voiceLoop.mjs`）、HMI、Android
- 关联：`orchestrator/cloud/admission.py`、`orchestrator/cloud/engine.py`、`hmi/src/voiceLoop.mjs`、
  `hmi/src/handsFreeController.ts`、`hmi/src/App.tsx`、`mobile/src/core/voice/handsFree.ts`、
  `mobile/src/core/session/store.ts`；R4.4 拒识母卡 `2026-07-07-r4.4-rejection-and-clarification.md`；
  受话 shadow 读数 `2026-10-04-jev-decide-integration.md` §11–§14

## 1. 问题

用户原话（2026-10-10）：「打开免唤醒连续对话后的拒识不足，常常把一些无意义的人人对话收录进去，让体验很差」；
补充：场景是**喊唤醒词叫醒之后直接接着说**（续问窗），不是全时免唤醒。

续问窗里收到的话在系统里标 `meta.input_source = voice_followup`（播报中插话是 `voice_bargein`）。
它们和唤醒词那一轮走同一条受话判定，拿不准一律判「对助手说的」。

## 2. 证据

### 2.1 线上（collector，近 14 天 126 个语音轮，只读）

核心旅程 F12 按 `voice_followup` 发的 6 句非受话句，7 趟：

| 句子 | 拒掉 |
|---|---|
| 妈你到哪了，我们在停车场等你 | 7/7 |
| 他昨天跟我说那个项目黄了 | 7/7 |
| 据央视新闻报道，今日多地迎来强降雨天气 | 5/7 |
| 下一站人民广场，请从后门下车 | 1/7（其余被规划成行程导航、地点搜索） |
| 喂，听得到吗，我在开车呢 | 0/7（闲聊回「听到啦，开车小心」） |
| 接下来为您播放一首经典老歌 | 0/7 |

合计 20/42 ≈ 48%。真实会话里还有：续问窗里的「你好小周。」被当成挂起导航的目的地（判定超时按受话放行），
「小周小周。」被闲聊回「我在呢」。

### 2.2 客户端把人人对话「收录」的三个机制

1. **拒掉的句子留在对话记录里**：两端都只把助手占位标灰（「已忽略疑似环境人声」），用户那条气泡——也就是乘客说的原话——原样留着。
2. **拒掉之后又开一个完整续问窗**：拒识轮按「无声终态」收尾，状态机 `THINKING → FOLLOWUP` 重新计 8 秒。
   乘客在聊天，每句都被收进来、上云、再开窗，麦一直是热的。HMI 有连续拒识收紧（`rejectPolicy.mjs`），Android 没接。
3. **噪声续命**：续问窗里一句语气词 / 空定稿 / 回声被本地丢掉后也重开 8 秒，嘈杂车厢里窗口可以一直不关。

### 2.3 离线评测（本机直连云端同款快档 MiniMax-M3，关思考、温度 0，每句 3 次）

语料进仓：开发集 `test/eval_corpus/followup_admission_cases.yaml`（57 正 / 39 负 / 8 两可）、留出集
`followup_admission_heldout.yaml`（48 正 / 32 负 / 10 两可；句子与提示词示例、开发集都不重叠，离线自检会查），都带「助手上一句」。
运行器 `test/eval_followup_admission.py`。前三行是调提示词阶段的读数（助手名还写在 system 里），最后一行是落地实现本身
（`admission.judge_continuation`，名字移进 user 消息）；那一趟的留出集还含后来因与提示词示例「停」重复而移出的「停。」（3/3 判受话）。

| 判定 | 开发集 误拒 / 拦下 | 留出集 误拒 / 拦下 |
|---|---|---|
| 现有轻量判定（`admission`，来源 `voice_followup`） | 1.8% / 61.9% | 4.1% / 65.6% |
| 续问窗专用判定，单次 | 5.8% / 96.6% | — |
| 续问窗专用判定 + 判否复核（两次都判否才拒） | 0.0% / 94.9% | 1.4% / 83.3% |
| **落地实现**（`judge_continuation`） | **0.6% / 95.7%**（1/171、112/117） | **0.0% / 85.4%**（0/147、82/96） |

单次判定的误拒是随机翻转（每句 3 次里错 1 次，分散在不同句子上）；复核把它压掉，负例几乎不受影响（真负例两次都判否）。
留出集漏掉的多是「接着助手的话题对别人说」（「我们晚上吃火锅怎么样」紧跟火锅推荐、「好的我记下了明天上午十点是吧」紧跟提醒），
只看文字本来就分不清，这是纯文本拒识的天花板。

## 3. 主流做法对照

- Google Continued Conversation：判断用户不再对它说话就结束本次会话，静默约 8 秒也结束。
- Amazon Follow-Up Mode：设备指向性模型（声学 + 识别结果 + 当前与上一句的语义）判断后续语音是不是对 Alexa 说的。
- Apple（ICASSP 2024）：多模态设备指向检测（声学 + ASR 置信 + 文本）比纯文本等错误率相对降最多 39%。
- 理想同学：「无效文本拒识」区分对理想同学说的话与车内交谈、打电话；多音区声源定位。
- 小鹏小P：双音区锁定——一场连续对话里谁唤醒就只和谁对话，别人无法插话。

共同点：① 续问窗是一次性的，判出「不是对我说」就结束会话、不续窗；② 续问窗的先验比唤醒后低，拿不准倾向不接；
③ 拒掉的话不进对话记录；④ 声学 / 说话人一致性是比文本更强的信号。

## 4. 方案

### 4.1 云端：续问窗专用受话判定（`admission.py` + `engine.py`）

- 来源分两类：`voice_followup` / `voice_bargein` 是**没喊唤醒词**的续说（新判定）；`voice_wake` / `ptt` 不变。
- 新判定只用于新请求那条路（规划路径）：与规划**并行**发起，先回来且判否就取消规划、立即静默拒识（拒识通常约 2 s 落地，
  不等规划）；判受话则照常等规划，规划自己的 `addressed=false` 仍然拒。判不出（超时 / 调用失败）回落规划器的判定（原行为）。
- 判据住在 `admission.py`，与唤醒词那一轮的判据**刻意不同**：先验是「这几秒里很多不是对你说的」，拿不准时——一句完整的、要车载助手办的事判受话，
  其余判不受话；认得助手自己的名字（`assistant_name`，缺省「小舟」，识别可能写成同音字）。判否再问一次，两次都否才拒。
- 挂起续接（确认 / 补槽 / 澄清选择）沿用原来的宽松判定：助手刚问了问题，这一句大概率就是答案，误拒的代价是挂起卡住。
- 观测：`cloud.voice_admission` span 加 `exit=continuation`、两次判定结果与耗时；拒识 span 带 `judge`。

### 4.2 共享状态机：拒识结束会话、噪声不续窗（`voiceLoop.mjs`，两端同一份）

- 新入口 `turnRejected()`：云端判非受话 ⇒ 结束这次连续对话，回 `ARMED`（只听唤醒词）；不再开续问窗。
- 续问窗有固定截止时刻：从助手答完那一刻起算。续问窗里收进来、又被本地丢掉的语气词 / 空定稿 / 回声 / 短噪声，
  只回到续问窗的**剩余**时间，到点就回 `ARMED`。唤醒词那一轮被本地丢掉时仍开一个完整的窗（不因一声「嗯」把刚唤醒的用户踢走，原 P4 判据）。

### 4.3 客户端：拒掉的话不进对话记录

- 两端：免唤醒语音被拒 ⇒ 用户那条气泡和助手占位一起从记录里删掉，不再留灰色「已忽略」气泡；
  只给一条会自己消失的提示「刚才那句不像是对我说的，已忽略；需要我时先喊唤醒词」。按住说话（Android `ptt`）被拒仍保留原来的灰色留痕——那是用户按了键的。
- 续问窗 / 插话来的那句在云端判定期间先以**待定**样式显示（变淡），第一帧受话回答到达即转正，被拒即消失。
- 状态机按 4.2 在拒识时回 `ARMED`；Android 补接这一路（此前拒识轮只当无声终态，会重开续问窗）。

### 4.4 刻意不做（本轮）

- 说话人一致性（唤醒的人才能续说，对标小鹏双音区锁定 / 小爱说话人一致）：要在端上或网关算声纹嵌入并比对，
  而项目红线规定「声纹只用于个性化」——用于拒识需要用户先拍板，另立项。
- 语义打断：播报中别人说话会直接打断播报（VAD 300 ms），被拒后答案已经停了。要先压低音量、判定后再决定停不停，另立项。
- S2S 挡位：自答轮不经云端规划，不在本方案覆盖面内。
- 声学特征（能量、距离、ASR 置信）：需要标注数据，先把 `voice_followup` 轮的判定结果留在 span 里攒数据。

## 5. 验证

- 单测：`admission` 判据与复核、引擎并行判定（先拒取消规划 / 后到 / 判不出回落 / 挂起续接不走新判定）、
  状态机 `turnRejected` 与续问窗截止、两端拒识删除气泡与待定样式。
- 离线评测：`test/eval_followup_admission.py`（开发集 + 留出集，`--live` 直连同款模型），读数登记在本文 §6。
- 真栈：部署后按 `voice_followup` 发 F12 六句非受话句 + 正例对照，各 3 次；HMI 在浏览器里走一遍「唤醒 → 回答 → 续问窗收到人声 → 拒掉、气泡消失、回 ARMED」。

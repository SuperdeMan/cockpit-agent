# 决策卡：复合句里的「接送某人」人称解析失效

- **状态**：**已落地并收口**（2026-08-20，实施记录见 §6）。真栈 10/24 → **41/45**；一#5 与一#1 均由稳定红转绿。⚠ **§2/§3 保留立卡时的原文不改**——其中三处定性被 §6.2 的真栈取证推翻了，两版并排着看才知道「卡上怎么写」也要拿真栈验
- **来源**：[双档复跑报告 §5](../reviews/2026-08-15-eva-dual-provider-rerun-and-fixes.md)
- **性质**：**存量缺陷**（不是 E1–E5 批引入的），两个 provider 都红 ⇒ 系统缺口非模型方差

---

## 1. 现象（真栈原文）

| 语料 | MiniMax | DeepSeek |
|---|---|---|
| 一#5「接爸妈去吃饭。」 | 「暂时无法确定「接爸妈去吃饭」对应的具体地点。」 | 「您还没有设置「家」的位置，请告诉我家的地址。」 |
| 一#1「带我去接孩子放学，顺便帮我找一家麦当劳，5点我要到学校。」 | 导航到**济南**市南山实验小学（2004km、37 小时） | ✅ 鼎太小学 5.9km |

对照组（**同一套记忆、同一坐标**）说明能力本身是在的：
- 「去接我爸。」→ 两档都给教学问「我还不知道你爸爸平时在哪，你说个地方我就记住了」✅
- 三§3「接孩子，顺路买杯咖啡，5点前到学校。」→ MiniMax 走通（鼎太小学 + 沿途候选 + 逐家 ETA）

**所以断的不是「人称→地点」这条链，是它的入口判据。**

## 2. 机制（已定位到行）

`agents/navigation/src/agent.py`：

```python
person_word = _person_destination(dest) or _person_destination(raw_text)   # :425
```

`_person_destination` 的判据是 **「去掉人称词与填充词后还剩不剩实质内容」**——
这条判据对**槽值**是对的（「孩子的学校」→ 剩空 → 解析；「孩子学校旁边的星巴克」→
剩「旁边星巴克」→ 不解析，用户已给具体地点）。但把同一条判据套到**整句原话**上就天然失效：

- 「接爸妈去吃饭」→ 剥人称与填充词后剩「吃饭」→ **非空 → 不触发**
- 「带我去接孩子放学，顺便帮我找一家麦当劳，5点我要到学校」→ 剩一大段 → **不触发**

**复合请求必然有剩余内容**，于是 raw 兜底那一路对多目标句形恒不生效。

第二个独立成因（一#1 专有）：planner 把记忆里的「**深圳市**南山实验小学」转述成
「南山实验小学」填进 destination 槽，navigation 拿这个**无城市的专名**走全国检索，
命中济南同名校。关系边里存的是全名（`女儿 --place_of--> 深圳市南山实验小学`），
**是转述那一跳丢了城市**——同「planner 改写 query 是不可信指代通道，指代解析只信 raw」
（sports 批既有判据）的又一例。

## 3. 修法候选（未拍板，按「先取证」纪律列出）

**A. 接不到地点时再回退人称**（落点已找到，最小改动）
`agent.py:545` 那个 `暂时无法确定「{dest}」` 兜底之前插一步：原话含接送人称模式
（`接X` / `送X`，X ∈ 人称词）→ 走 `ctx.resolve_person_place`，查得到就用、查不到给
**教学问**（与「去接我爸」同一句话术）。
落点紧挨着 D4 的先例（「比『暂时无法确定』多给一步」），形态一致。
- 好处：不动既有触发判据、零回归面；错了最多是多问一句。
- 边界：一#1 那条**不走这个分支**（它接到了 POI，只是接错城），要靠 B。

**B. 专名跨省兜底重搜**（治一#1）
目的地是专名、命中结果距当前位置 > 阈值（如 300km）、且原话无任何异地/城市线索
→ 用「{当前城市}{专名}」重搜一次，命中就用近的。
- 与接地卡 D2「区县级就近合理性收窄（≤150km）」同族，是它在**POI 名字匹配**分支的镜像。
- ⚠ 必须留「用户确实要去外地」的出口（原话含城市名/「去北京」类线索时不收窄），
  否则会误伤真实长途。

**C. 让 planner 别丢城市**（不推荐单独做）
prompt 里要求转述地点必须带城市——软路径，且与「指代解析只信 raw」的既有判据相悖。
只能作为 A/B 之外的补充。

## 4. 接手取证清单（动码前先做）

1. **先建红绿迷你集**（接地卡 R1 二期的做法）：接送人称 × 复合句形 × 有/无该人地点记忆，
   每格 2 条，跑真栈记基线——**别拿单条语料证明修好了**。
2. 确认 `_PERSON_WORDS` / `_PERSON_FILLER_RE` 当前覆盖面（「爸妈」这类**对偶称谓**
   是否在词表里、`_KIN_PAIR` 那套是 nearby 的、navigation 侧是否等价）。
3. A 方案要验**反向**：给了具体地点的复合句（「接孩子后去万象城」）**不得**被改写。
4. B 方案要验**反向**：真实长途（「导航去上海外滩」）不得被就近收窄。

## 5. 刻意不做

- 不在 `planning.py` 加正则兜底（R2.1 已把历史硬编码全部机制化）。
- 不为此扩 `route_hints`（修落域 badcase 的默认产物是范例与知识，不是硬路由）。
- 不动 `_person_destination` 对**槽值**的既有判据——它是对的，别为了复合句把它放宽。

### 6.1 先建红绿迷你集（卡 §4.1）

`scripts/probe_qa_regression.py --group pickup`：人称接送 × 单句/复合句 ×
有/无该人地点记忆，每格 2 条 + 两条反向对照（§4.3 / §4.4）。三条新判据原语
**都不是关键词排除**：

- `follow_up_any` —— 匹配**我们自己代码里的确定性 `follow_up`**，即「这一轮走了
  哪条分支」的签名（教学问那串 vs「请补充城市、所在区域」那串）。判 `speech` 不行：
  那一句会被聚合改写，`follow_up` 不会。
- `navigate_within_km` —— 拿 **navigate 动作 payload 里的目的地坐标**与探针固定位置
  算球面距离。不写死地名（换一座同名城市就漏），也不依赖哪张卡赢了聚合。
- `navigate_named_any` —— 「真发了导航就得去对地方」，但**不要求本轮必须发导航**。

**这套尺子自己红过三次，每一次都改了判据形态**（§4.3「尺子写错必须改」）：

### 6.2 取证改了三处定性

**① 「接孩子接到济南 2004km」不是高德乱返回，是我们自己那条去偏置全国重搜捞上来的。**
云端直连高德（同一把 key、同一坐标）：

```
'南山实验小学' near=当前位置 → 鼎太小学 4km / 深湾小学 3km / 海滨实验小学 2km …（全是深圳）
'南山实验小学' near=None     → 济南市南山实验小学 1579km（**只有这一条**）
```

链条：`_dest_matches("南山实验小学","深圳市南山实验教育集团鼎太小学")` 因中间的
「教育集团」不构成连续包含 ⇒ 严格校验拒掉 4km 外的正主 ⇒ 掉进「R1 去偏置全国重搜」
⇒ 捞回逐字同名的济南那条 ⇒ 严格包含通过 ⇒ 返回。**与「虹桥机场／上海虹桥国际机场」
逐字同构**，而那一族的修法（类目锚词 + 主干匹配）2026-08-14 就写好了，
**只是锚词表里没有校园**。

⇒ 修法：`_DEST_CATEGORY_ANCHORS` 增校园族，**并且候选集内双匹配从 `results[1:]`
改成 `results`**——上面那道 `top_named` 用的是严格包含、而 `_grounds_to` 还认主干匹配，
把 top1 排除掉等于**让排第一的候选受一条比后面所有候选都严的判据**，
而它恰恰是就近序最靠前的那个。零额外 API、不新造阈值、不新增误伤面。

**② `resolve_person_place` 对「女儿」「孩子」返回 None——一跳解析对这两个称谓早已
永久失效。** 云端真实调用（不是推理）：

```
女儿  persons=['女儿','小雨']        -> None
孩子  persons=['孩子','女儿','小雨']  -> None
老婆  persons=['老婆']               -> {'place': '深圳湾万象城'}   ← 只有从没起过名字的这个还活着
```

`女儿--family-->女儿` 是**无名的人**的表示法（`relation.normalize_candidate` 的 family
自环例外，2026-08-16 已因此推翻过一次「自环边零信息」的定性）；用户后来说「我女儿叫
小雨」，再存 `小雨--family-->女儿`。库里于是**两个 subject 指向同一个人**，旧判据数成
两个人 ⇒ 判歧义。**「用户给这个人起了名字」不该让能力退化。**

⇒ 修法只动**人的分组**：占位（subject 本身就是该称谓族的亲属词）不算独立的人、
具名主体 ≥2 才是真歧义、地点在合并后的实体上取并集。⚠ **安全性没被放松**——
最后那道「地点必须唯一，否则返回 None」一个字没动，两个具名孩子两所学校仍然是 None
（有专门的反向对照断言）。

**③ 卡上写的「planner 转述记忆地点时丢了深圳市」不成立——丢城市的是记忆本身。**
云端 planner 日志逐字：

```
memory recall for u1: 3 items ['person.child', 'place.home', 'person.family']
LLM plan toolcall args: {"steps":[{"slots":{"arrive_by":"五点","destination":"南山实验小学"}, …
```

当时 live 的那条 `person.child` 就是「用户的女儿在**南山实验小学**上学」（无城市）。
`memory_relation` 里的「深圳市南山实验小学」是对的，**planner 根本没读到它**。
history §48.3 那个悬案（「究竟召回了哪一条边」）到这里才真正闭合：
**召回的不是边，是 `memory_item`。**

### 6.4 落域那一半：范例，不是正则

一#5「接爸妈去吃饭」修前三次取样**全部只答「吃饭」那半**（落成纯 `nearby.search`），
而它答得相当好——甚至用上了记忆里「父母腿脚不方便」按停车便利排序，
**所以话术层完全看不出缺了一半**。按既定纪律补范例：

- 「接爸妈去吃饭」→ `destination=爸妈` + `stop_category=吃饭`（与既有「接孩子放学，
  顺路买杯奶茶」同形）⇒ PU3 **0/3 → 3/3 `[det]`**。
- 同一批里「先去接我儿子，再找家川菜馆」**仍稳定 0/3**（三次逐字相同地只答川菜那半）
  ⇒ 补该句形的第二条范例 ⇒ **0/3 → 3/3 → 4/5**。
  **「补上 X」与「补上 X 就能修」是两个命题，第二个得单独证**——上一条范例只治了
  它示范的那个形。
- 第二条触发了跨域边界门禁（↔「找家川菜馆」IDF-Dice 0.492），按要求登记
  `boundaries.yaml`：判据是**有没有接送人称**。**这正是那张台账存在的理由。**

⚠ **中途自己报过一次错读数**：加第一条范例那一跑 PU5 2/3、PU6 1/3，看起来像被新知识
拖累；同一份代码 n=5 复跑得 PU5 **5/5**、PU6 3/5 ⇒ **是采样噪声，不是回归**。
n=3 的翻面不足以支撑「知识有害」这个结论。

### 6.5 两处卡上没有的缺口（都已修）

**① 接送人称要胜过「未设置的常用地点别名」。** planner 把「接女儿放学，路上买杯咖啡」
压成 `destination=学校`，别名分支抢在人称之前命中 ⇒ 真栈答「您还没有设置「学校」的
位置，请告诉我学校的地址」，而库里那个人的地点明明在（PU6 5 次取样稳定占 2 次）。
与 raw 兜底同一形态——**接不着地点时回退人称**，只是这里的「接不着」是「没设过」。
**只在没设过时才让位**：用户明确配过「学校」就是把它当地址簿用（反向对照断言钉着）。

**② 接人目的地的就近合理性闸。** 上面两道都是**判据面**的修法、各自只覆盖自己那条路：
修完之后 PU5 七次取样**仍有一次**把车导到 1582km 外的济南同名校，而取证到此是一条断链
——planner 那一轮下发的是「深圳南山实验小学」、**全部容器日志里「济南」零命中**、
直连高德复测该词两档都只返回深圳的学校，只有 `memory_item` 里新写的那条轨迹能证明车
确实被导了过去。⇒ 加一道**不重搜不改写、只问一句**的闸：原话是接送句 + 有定位 +
命中结果 >100km ⇒ 报出距离并反问。**来源查不清不等于不能防**——它不依赖那一跳从哪来，
只问一个产品问题：接人接到这么远，合理吗。三条反向对照都写成了断言
（本地不受影响 / 「导航去上海外滩」原话无接送人称⇒闸根本不该被执行到 /
无定位就不判、**认不出就不判**，不回落成拒绝）。

### 6.6 迷你集的两处调整（都留痕）

- **PU4 换人**。原话「先去接我妈…」当时占「无地点记忆」那一格；同日泓舟裁定
  **妈妈住苏州**之后这个人**有**地点了，格子的定义不再成立 ⇒ 换成「儿子」
  （family/place 边一条都没有）把格子保住。**不是为了让读数好看换语料**
  ——格子的定义是「无该人地点记忆」，人变了就得换人。
- **PU9 新立**，收原话掀开的另一个问题：数据裁定生效后 planner 召回「妈妈住苏州」→
  填进 destination → 高德接得着「苏州」⇒ 系统直接规划了一趟 **1389km 的「去接妈妈」**。
  修前错在「接不着」，修后错在**接着了却不问一句**。**数据没裁错**——错的是「接人」
  天然是本地差事而系统对合理距离零判据。现由 §6.5② 那道闸接住，**5/5**。

### 6.7 仍然红的 4 次取样：是**另一个族**，不是本卡

45 次里剩 4 次，逐条看都是**多意图复合句被单域吞掉**，与人称解析无关：

| 用例 | 现场 | 谁吞了 |
|---|---|---|

**不在本批继续加范例**：已经加了两条，再按句形逐条补就是 per-utterance 调参了。

### 6.8 本批新记的账（已进 §4.2 条件待办）

**`memory_item` 的 supersede 按「新的取代旧的」，会让同一件事越记越少。**
`person.child` 这条链是实据，每一跳都用更少的信息取代更多的信息：

```
用户的女儿在深圳市南山实验小学上学 (01:16)
  → 用户有孩子，孩子在上学        (07:57)
  → 用户的女儿叫小雨              (09:03)
  → 用户有一个女儿                (09:06，live)
```

2026-08-16 的关系边清洗定的规则是「**保留信息最全的那条，不是最新的**」（E5 那次
dry-run 教的），而 `memory_item` 侧**没有对应实现**——`consolidate` 只按谓词等价类
比新旧。⚠ 不能直接把关系边那条规则搬过来：偏好类记忆（「以后不吃辣了」）**就该新的赢**。
判据得先分清「事实被更精确地重述」与「偏好发生了变化」，属独立一卡。

⚠ **另记一条操作面的账**：探针每跑一轮成功导航就会写一条 `episodic.place`
「导航去过X」——本轮跑批在 `u1` 名下写了约 20 条。它们**不是假事实**（车确实被导过去了），
但是探针噪声；只有「导航去过济南市南山实验小学」那一条属于 bug 产物，已按①一并删。
下次大批量跑 pickup 组前先知道这件事。

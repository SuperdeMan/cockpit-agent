# 决策卡：复合句里的「接送某人」人称解析失效

- **状态**：待实施（2026-08-15 双档复跑取证后由泓舟指示另立卡；**先取证再动码**）
- **来源**：[双档复跑报告 §5](../reviews/2026-08-15-eva-dual-provider-rerun-and-fixes.md)
- **性质**：**存量缺陷**（不是 E1–E5 批引入的），两个 provider 都红 ⇒ 系统缺口非模型方差

---

## 1. 现象（真栈原文）

| 语料 | MiniMax | DeepSeek |
|---|---|---|
| 一#5「接爸妈去吃饭。」 | 「暂时无法确定「接爸妈去吃饭」对应的具体地点。」 | 「您还没有设置「家」的位置，请告诉我家的地址。」 |
| 一#1「带我去接孩子放学，顺便帮我找一家麦当劳，5点我要到学校。」 | 导航到**济南**市南山实验小学（2004km、37 小时） | ✅ 鼎太小学 5.9km |

对照组（**同一套记忆、同一坐标**）说明能力本身是在的：
- 「去接我爸。」→ 两档都给教学问「我还不知道你爸爸平时在哪，你说个地方我就记住了」✅
- 三§3「接孩子，顺路买杯咖啡，5点前到学校。」→ MiniMax 走通（鼎太小学 + 沿途候选 + 逐家 ETA）

**所以断的不是「人称→地点」这条链，是它的入口判据。**

## 2. 机制（已定位到行）

`agents/navigation/src/agent.py`：

```python
person_word = _person_destination(dest) or _person_destination(raw_text)   # :425
```

`_person_destination` 的判据是 **「去掉人称词与填充词后还剩不剩实质内容」**——
这条判据对**槽值**是对的（「孩子的学校」→ 剩空 → 解析；「孩子学校旁边的星巴克」→
剩「旁边星巴克」→ 不解析，用户已给具体地点）。但把同一条判据套到**整句原话**上就天然失效：

- 「接爸妈去吃饭」→ 剥人称与填充词后剩「吃饭」→ **非空 → 不触发**
- 「带我去接孩子放学，顺便帮我找一家麦当劳，5点我要到学校」→ 剩一大段 → **不触发**

**复合请求必然有剩余内容**，于是 raw 兜底那一路对多目标句形恒不生效。

第二个独立成因（一#1 专有）：planner 把记忆里的「**深圳市**南山实验小学」转述成
「南山实验小学」填进 destination 槽，navigation 拿这个**无城市的专名**走全国检索，
命中济南同名校。关系边里存的是全名（`女儿 --place_of--> 深圳市南山实验小学`），
**是转述那一跳丢了城市**——同「planner 改写 query 是不可信指代通道，指代解析只信 raw」
（sports 批既有判据）的又一例。

## 3. 修法候选（未拍板，按「先取证」纪律列出）

**A. 接不到地点时再回退人称**（落点已找到，最小改动）
`agent.py:545` 那个 `暂时无法确定「{dest}」` 兜底之前插一步：原话含接送人称模式
（`接X` / `送X`，X ∈ 人称词）→ 走 `ctx.resolve_person_place`，查得到就用、查不到给
**教学问**（与「去接我爸」同一句话术）。
落点紧挨着 D4 的先例（「比『暂时无法确定』多给一步」），形态一致。
- 好处：不动既有触发判据、零回归面；错了最多是多问一句。
- 边界：一#1 那条**不走这个分支**（它接到了 POI，只是接错城），要靠 B。

**B. 专名跨省兜底重搜**（治一#1）
目的地是专名、命中结果距当前位置 > 阈值（如 300km）、且原话无任何异地/城市线索
→ 用「{当前城市}{专名}」重搜一次，命中就用近的。
- 与接地卡 D2「区县级就近合理性收窄（≤150km）」同族，是它在**POI 名字匹配**分支的镜像。
- ⚠ 必须留「用户确实要去外地」的出口（原话含城市名/「去北京」类线索时不收窄），
  否则会误伤真实长途。

**C. 让 planner 别丢城市**（不推荐单独做）
prompt 里要求转述地点必须带城市——软路径，且与「指代解析只信 raw」的既有判据相悖。
只能作为 A/B 之外的补充。

## 4. 接手取证清单（动码前先做）

1. **先建红绿迷你集**（接地卡 R1 二期的做法）：接送人称 × 复合句形 × 有/无该人地点记忆，
   每格 2 条，跑真栈记基线——**别拿单条语料证明修好了**。
2. 确认 `_PERSON_WORDS` / `_PERSON_FILLER_RE` 当前覆盖面（「爸妈」这类**对偶称谓**
   是否在词表里、`_KIN_PAIR` 那套是 nearby 的、navigation 侧是否等价）。
3. A 方案要验**反向**：给了具体地点的复合句（「接孩子后去万象城」）**不得**被改写。
4. B 方案要验**反向**：真实长途（「导航去上海外滩」）不得被就近收窄。

## 5. 刻意不做

- 不在 `planning.py` 加正则兜底（R2.1 已把历史硬编码全部机制化）。
- 不为此扩 `route_hints`（修落域 badcase 的默认产物是范例与知识，不是硬路由）。
- 不动 `_person_destination` 对**槽值**的既有判据——它是对的，别为了复合句把它放宽。

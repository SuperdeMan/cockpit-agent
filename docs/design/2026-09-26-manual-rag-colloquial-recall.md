## 0. 结论

用户点名的「xxx 功能有哪些模式 / 怎么开启 / 有几个档位、后备箱能放几个行李」在生产上几乎全部召回失败。
**根因不在手册内容，也主要不在排序**：正确页往往排第一，却被零命中闸拦下——问句壳切出来的双字
（「有几 / 几个 / 个档 / 有哪」）整本手册一次都没有、IDF 最高，把覆盖率压到 0.42 以下。此外还叠着
「档 / 挡」异体、车主叫法与手册用词错位、Agent 丢掉规划器已补全的指代问题、规划器把「空调有什么模式」
当成场景列表、执行超时只有 2.5 s 五层问题。

修法分两层：**确定性词法层**重写查询理解（问句壳词表取自 `runtime.question_shape` 唯一实现、三类词分开计分、
四道范围闸）；**目录路由**在词法零命中 / 没把握 / 含手册不认识的实词时，让 LLM 在手册目录（封闭集合）里选章节，
LLM 只产目录编号、不见正文、不作答。

## 1. 取证：云端 collector 的真实问法

只读导出 collector 全部轮次（2026-07-10 → 2026-09-26，6 305 轮、514 句不同话术；存档
`.artifacts/manual-rag-colloquial/collector-turns-20260926.json`）：

- 落到 `manual.query` 的 **562 轮里 488 轮是「手册里没有查到」（86.8%）**。高频：「座椅有哪些调节功能」53、
  「车窗有哪些开启方式」35、「座椅有哪些加热档位」32、「座椅加热有几个档位」30、「大灯有几个模式」28、
  「打开后备箱，再告诉我空调有哪些模式」及其倒装各 27、「这车有几个座位」27、「后备箱能放几个行李箱」26、
  「空调有几个风量档」18、「氛围灯有哪些颜色可以选」7、「座椅加热在哪里打开」5。
  评审三轮把「座椅有哪些调节功能」记成「手册库没有这一项，路由对、内容缺」——实际第 29–33 页就是座椅调节，**是检索闸误判，不是内容缺**。
- 「空调有什么模式」**57 轮里 56 轮被规划成 `scene.list`**，答的是「回家 / 露营 / 午休」场景。
- 规划器写的 `question` 槽与原话：562 轮里 440 轮一致；不一致的主要两类都是规划器做对了——多诉求句只抽本步
  （54 轮「空调有哪些模式」）、指代补全（「它有几档」→「座椅加热有几档」，W19-c 历史视窗探针），
  但 Agent 取的是 `raw_text or slot`，原话优先，补全被丢掉。少数补全指错对象（「它锁上以后…」→「车锁上以后…」），仍比光秃秃的「它」强。

## 3. 设计

### 3.1 检索用哪句话（`agent._retrieval_question`）

原话是权威；只有原话自己解析不出时才用规划器写的槽（同 2026-07-19「规划器改写是不可信指代通道，解析不出才保留」的既有判据）：

- 原话主语是回指代词（判据唯一实现 `runtime.anaphora.has_anaphoric_subject`）→ 用槽；
- 原话多分句、槽只落在其中一个分句里（规划器把多诉求句拆成了多步）→ 用槽；槽横跨多个分句（规划器把多问句合并成一步）→ 仍用原话；
- 安全分级与告警信号**始终只看原话**；用槽检索时答案提示词同时给出【用户原话】与【问题】。

### 3.2 查询理解：三类词（`local_index.py`）

每个检索变体拆成三类词，各管各的事：

| 类 | 来源 | 计分 | 计入零命中闸 | 计入排序覆盖率 |
|---|---|---|---|---|
| 主题词 | 用户自己的内容（换过同义词、剥过壳） | ✓ | ✓ | ✓ |
| 证据词 | 意图扩展追加（参数 / 定期保养 / 整车尺寸参数…） | ✓ | ✗ | ✓ |
| 只排序词 | 答案类型词（方式 / 功能…，`facet_terms`）、症状（关不上 / 打不开）、词间接缝 | ✓ | ✗ | ✗ |

- **问句壳**：列举 / 定义 / 原因 / 位置 / 能力 / 属性 / 参照问法与疑问尾词直接取 `runtime.question_shape` 的词表；
  计数壳与属性壳按问句判据的结构（头 + ≤2 字动词 + 几量词 / 多大多高）整段剥（判据为「认出」计数问允许隔 4 字，剥离若也隔 4 字，
  「能量回收有几档」会从「能量」的「能」起跳吃空整句）；请求开头词（请问 / 告诉我 / 介绍一下 / 查一下）只剥句首——全句遮罩会吃掉章节名词「车辆介绍」。
  所有短语与模式**按字符并集遮罩**，与剥离顺序无关（逐个 replace 时「怎么」吃掉「怎么回事」的头，等长短语先后取决于集合迭代序、而字符串哈希每进程随机）。
- **异体**：档→挡，语料与查询同一次规范化，对称折叠。
- **句法产物**（不计分不计闸）：段首介词 / 指代虚字、段尾语气 / 助词虚字组成的双字；全书不存在且含虚字的双字；全书不存在、夹在两个真实双字之间（或句尾悬挂）的双字。
  整段都不在手册里的双字（机油、油箱、海豹、天窗）不是产物——零命中闸靠的正是它们。
- **词间接缝**：夹在两个已知双字之间、df 不到两侧较小者 1/4、且跨它的四字串全书至多出现一次（「车载冰箱」的「载冰」）；四字串条件排除「车道保持」这种由高频词组成的真复合词。
- **排序**：质量 = BM25 × 排序覆盖率^1.5（线性乘时，缺一个关键概念但主题词重复更多的页会反超「概念全部在场」的页）。闸仍是「质量 ≥ 1 且主题覆盖率 ≥ 0.42」，口径不变，变的是覆盖率只算用户自己的词。
- **意图扩展**（schema v2）：`standalone` 的规格扩展在内容剥空时自己就是问题（「这车有多长」），必须配 `require_any`（否则「这个多少钱」会凭空检出参数页）；
  `drop_any` 去掉指整车本身的主语词（「车身有多长」）。

### 3.3 范围闸（确定性，LLM 越不过）

| 闸 | 声明 | 例 |
|---|---|---|
| 外车型标记 | `foreign_vehicle_markers`（不收「理想 / 汉 / 唐」这类歧义词） | 比亚迪海豹的电池容量 |
| 本车没有的对象 | `absent_subject_markers`（纯电车无燃油系统部件；无可开启天窗） | 油箱能加多少升油、这车能加95号汽油吗、天窗为什么关不上 |
| 未知专名 / 型号码 | 三字符以上未知 ASCII（既有）+ 字母数字两字符型号码 | CarPlay、理想L9、问界M9 |
| 声明自检 | 启动时核对每个标记确实不在手册里，矛盾即拒绝启动 | 首版的「海豚」撞上了「qborn 小海豚儿童安全座椅」 |

ASCII 闸改为逐变体判：受控同义词换掉的专名（NOA → 智能领航辅助、TypeC → USB 接口）按换过之后的变体判。

### 3.4 目录路由（`toc.py` + `toc_router.py`）

- 目录来自获准索引本身：合并页路径（「座椅 > 座椅通风 / 车辆安全 > 安全带」）按「后段替换前路径同级层」还原，与 PDF 大纲 187 个叶子逐条一致，不需要 PDF 或第二份目录。
- **何时路由**：词法零命中；或最高主题覆盖率 < 0.7；或问句含手册不认识、同义词也换不掉的实词（奇骏 / 刮车 / 小冰箱）。
- **何时不路由**：范围闸拦下的；剥壳后没有实字的（「这是什么」曾被路由到「外部介绍」）；带仪表灯 / 图标语境的（认图标只认受控视觉目录，把「黄色感叹号」路由到告警表等于让生成模型在相邻行之间猜）；受控视觉目录已命中的。
- **LLM 的产出**只有 `{"scope", "sections"}`：编号由代码校验存在（未知 / 格式错一律丢弃，至多 3 个），按章节轮转取页（每节先取最相关的一页，保证每个选中章节至少进一页）。
  与词法结果合并时，**两路都选中的页排最前**，其余路由页与词法页交替，合计至多 4 块（`_merge_routed`；路由页一律排前曾把「三元锂电池平时充到多少」正确的词法首页挤到第二）。
  路由失败 / 超时 / 解析失败 = 没说话，回落词法结果；**零命中仍不调生成模型**（Q9 护栏①的本意——没有材料不让 LLM 作答——不变）。
- **否决只认一种**：含手册不认识的实词、且路由明确判 `other_vehicle` 时作废词法近似（「奇骏的电池容量」不能拿本车 73.6 kWh 作答）。「没找到章节」「不是用车问题」都不否决——实测 MiniMax 在温度 0 下对同一句的判空也不稳定（首版判空即否决，三套集各误伤 1–2 条）。

### 3.5 规划侧

- `manual.query` 描述写明「部件与功能有哪些模式 / 挡位 / 颜色、怎么开启与设置、储物容量与整车规格」；`scene.list` 补反界定「部件自带的工作模式与挡位不是场景，归车型手册问答」。能力目录 13 946 → 14 009 字，余量 1 991，零裁剪。
- `manual-help-boundary` v4：补一条部件自带模式 / 挡位 / 容量问法 → `manual.query`、`scene.list` 只列场景；删去与上一条重复的「如实弃权」句；常驻 policy + 本指南 2 549 / 2 600。
- 范例追加三条（实质改写、不抄 collector 原句）：空调工作模式、座椅加热分级、前备箱容量。
- 没有加 route hint：先看知识层在真栈上能否把「空调有什么模式」拉回手册（§6）。

### 3.6 执行超时

`manual-rag` `latency_budget_ms` 2500 → 15000（与 vision / nearby 同档）：词法毫秒级 + 路由（仅需要时，p50≈1 s，超时 8 s）+ 生成 2–5 s（瞬时失败重试一次）。

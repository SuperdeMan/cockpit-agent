# 完整的信息问题不再被问成「选哪个动作」

> 2026-10-04。状态：落地中。交付对象：云端规划（重试策略表）、`runtime/question_shape`。
> 关联：`orchestrator/cloud/retry_policy.py`（先例 `complete_conditional_clarified`）、`orchestrator/cloud/planning.py`
> （`_goal_requires_clarification`、`clarify_goal_with_steps`）；[闲聊让手册 §5](2026-10-04-chitchat-defers-to-confident-manual.md) 登记的另一半。
> 按用户「接下来待做的，都按你建议的来」推进。

## 1. 测量（只读）

- 固定语料里手册问句的红，约两成是澄清卡。基线日志里第一次尝试的计划都在（此前漏看是我按关键词过滤日志，把
  `LLM plan toolcall args` 这行筛掉了）：模型输出 `{"addressed":true,"goal":"需要澄清：…","steps":[]}`，理由都是把完整问句当成对象不明——
  「露营模式是什么意思？」→「用户只给了对象名『露营模式』未说明意图」；「空调有哪些模式？」→「未指明是查询本车手册还是列举场景模式」；
  「说明书里『打开后备箱』这一节讲的是什么？」→「需要确认是想查询该节内容还是别的」。随后 `clarify_goal_with_steps` 要求第二次尝试
  给「两个明确动作」，于是出现「调高一度 / 调低一度」「直接开启 / 了解含义」这类选项。
- 判据候选「明确提问 ∧ 非指令问句」（问方法 / 释义 / 枚举 / 计数 / 原因 / 规范，或解释元请求，或问属性 / 位置 / 能力；光有问号、
  语气尾词不算）：
  - 澄清用例集 23 条：期望澄清的 6 条全部不命中（「附近有什么好玩的帮我安排一下」有「有什么」但带指令，被非指令条件挡住）；
    期望直答的命中 3 条（「今天有什么新闻」「到机场大概要多久」「附近哪里能停车」），方向一致。
  - collector 里触发过 `clarify_goal_with_steps` 的约 133 轮：**真实用户 13 轮全部不命中**（保持原样）；命中的 87 轮全是合成会话，
    基本是手册问句这一族，其中 39 轮以澄清卡收尾、23 轮落闲聊。

## 2. 判据

- 唯一判据 `runtime.question_shape.is_complete_information_question`：不是指令，且带明确的提问动作。
- 重试策略 `information_question_clarified`（守卫段，排在 `clarify_goal_with_steps` 之前）：模型要澄清（目标标记或澄清对象）
  而原话是完整的信息问题 ⇒ 校正「不要反问、不要执行任何动作，只规划能回答这个问题的合法能力」，下一次尝试走只给计划的通道
  （同先例 `complete_conditional_clarified`）。校正措辞不含任何领域词：本车功能该谁答由能力描述决定。
- 规划仍给不出步骤时走既有「无需动作 → 闲聊」，闲聊再按把握交手册（上一包）。

## 3. 实现

- `runtime.question_shape.is_complete_information_question`：非指令问句 ∧（方法问 / 解释元请求 / 原因问 / 枚举问 / 计数问 / 定义问 /
  规范问，或含属性 / 位置 / 能力问词）。复用模块里既有的分句判据，不新增词表；「…原理」本就在原因问词里，所以「定位原理」也算。
- 重试策略表新增 `information_question_clarified`（第 4 条，守卫段、全部通道、attempt_limit 2、校正模板 `information_question`、
  下一轮只给计划）；规划里注册谓词：要澄清（目标标记或澄清对象）∧ 完整的信息问题。策略清单（B5 方案附录 A）同步为 14 行。
- 旧用例调整（原意不变，只换例句）：安全谈话闸「不吃普通澄清」与「交通灯词的代价」、澄清续接两条，原例句（「没开定位为什么还有距离」
  「刚才那个红灯我是不是闯了」「解释定位原理」）都是完整的信息问题，换成裸对象 / 陈述句；原例句在新规则下的去向在新测试里断言
  （模型一直要澄清时不出动作选项卡，落到兜底 Agent 答一句）。

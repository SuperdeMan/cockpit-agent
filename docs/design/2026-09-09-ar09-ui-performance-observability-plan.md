# AR09：UI 性能与 release 观测实施方案

> 状态：**草案，未实施、未取得新性能读数**；日期：2026-09-09。
> 交付对象：mobile UI/原生工程与 QA。对应 R11 常驻负载、失效视图更新和观测缺口。
> 总依赖见[接续路线](2026-09-09-android-ar06-ar11-execution-roadmap.md)；工程基线可固定当前实际语音默认；正式签收取 AR04 宿主、AR06 检查以及 AR07/08 最终选定代码。

## 1. 目标与边界

让空闲、长回答、跨页和折叠时的 UI/音频负载可量，修复有证据的多余渲染或失效视图更新，并让常驻 release 能导出有界、脱敏、可关联的诊断。保留既定 Aurora 交互和支持页浮动在场，不做新一轮视觉改版。

历史记录的 Reanimated 对卸载视图更新（386 次/4min）只是待重现线索，不能当成当前发生。当前多个动画已含 `cancelAnimation`，Presence 计时器也有条件，不能简单“加 cleanup”就宣布修复。

## 2. 代码定位与初始假设

| 代码面 | 已读事实 | 本批验证假设 |
|---|---|---|
| [AssistantProvider](../../mobile/src/features/assistant/AssistantProvider.tsx) | 应用级会话/语音宿主；`useStore(core.store)` 订阅整个会话，context 汇出多种状态 | 高频文本更新可能扩大渲染范围；先测提交树，再切 selector/context |
| [usePresence](../../mobile/src/features/chat/usePresence.ts) | 多路事实订阅；计时器仅在 pending/短提示/宽限等 `needsTick` 时运行 | 检查页面不可见、长期 held 或短提示结束后是否仍有不必要刷新 |
| [AuroraOrb](../../mobile/src/ui/aurora/AuroraOrb.tsx)、`ThinkDots/StreamCursor/EdgeGlow` | 多组 shared values/循环；已有 cleanup | 组件替换、隐藏未卸载、动画回调和 key 稳定性是否有漏口 |

| [speech.ts](../../mobile/src/core/voice/speech.ts) | 20 条 TurnReport，可订阅；console 仅 dev | AR08 先补计时语义，AR09 提供同源可用出口 |
| [usePowerFacts](../../mobile/src/core/power/usePowerFacts.ts) / [根布局](../../mobile/src/app/_layout.tsx) | 有省电事实与 keep-awake 设置接线 | 真实省电/后台与 release 常亮须设备证据，不能只看 Hook 存在 |

表中“可能”是定位方向，不是已证实缺陷。若当前固定包不再复现历史问题，记录复现条件和观测能力，保留必要回归，不为关历史条目强行修改正常实现。

## 3. 先建立最小观测出口

建议在既有 `core/obs/` 下新增诊断聚合器与只读页面入口，消费 AR08 事件、PresenceTrail、采集/播放事实及包身份。不要修改这些模块的业务状态权威。

### 3.1 字段与生命周期

| 部分 | 建议字段 | 边界 |
|---|---|---|
| 身份 | schema_version、完整源码映射、APK build、云端 release、实际 provider/model | 未知写 unknown；不把最后选择的设置当实际服务配置 |
| 关联 | interaction/request/trace、音频段 ID、事件相对时刻 | 复用 ID；不导出 token、用户/车辆真实标识、连接 URL 参数 |
| 状态 | route、窗口 dp/姿态、前后台、采集/播放计数、问题 code | 文案字段需白名单，不能直接序列化整份 store |
| 负载 | JS event-loop lag、可见性切换、提交/订阅计数、音频队列/gap、KWS dropped | UI/JS/音频三个分母分别记录，事件字段不包含 PCM 或转写全文 |

建议内存上限：最近 20 轮、事件 200 条、序列化最大 256KiB、最长 30min，先到上限先淘汰；丢弃数可见。用户显式打开短期性能采样，默认不启高频采样；非前台或关闭时停止该采样。基础轮摘要继续有界记录；账号/服务器切换清理前一身份摘要。

prod 页只读，可复制前先预览字段；不自动上传、不自动开始录音/视觉、切播放器或执行测试指令。手动复制是用户导出行为，不能因此声称数据永不出内存。高频 probe 放实验档，验证诊断关闭/开启两档开销；不加常驻录音来诊断音频。

### 3.2 日志必须证明“看得见目标事件”

零 warning 不能自动证明零失效更新。用隔离、可撤销的目标事件验证日志/计数器能捕获；再在真实候选观察零命中。扫描测试按项目要求反向验证会红，不能只扫描 `cancelAnimation` 是否出现。

## 4. 固定负载与指标

用 prod release 计分，dev profiler 仅定位；这是 [React Native 性能指南](https://reactnative.dev/docs/performance)明确区分的测量边界。记录实际屏幕刷新率、渲染帧数与采样窗，不将 60Hz 和 120Hz 的帧预算混算。平台取证可参考 [Android 渲染性能](https://developer.android.com/topic/performance/vitals/render)，实际命令先核设备支持。

| 场景 | 建议协议 | 要收集的事实 |
|---|---|---|
| P0 空闲 | 对话/设置/地图各 5min；免唤醒关与 ARMED 各一档，重复 3 轮 | CPU/PSS、订阅与计时器、动画活跃数；两档不能混报 |
| P1 长内容 | 固定 500 条非敏感本地消息、长中文与嵌套卡片；滚动 60s；另跑真实长答 | UI 帧、JS lag、提交、PSS；本地重放与真实输入分开 |
| P2 语音并发 | 固定语料流式/一次 final、多段、S2S，10min | UI 卡顿、播放队列、活跃音轨 underrun、KWS dropped 各自增量 |
| P3 路由/姿态 | 对话→设置→地图→车辆→返回 30 次，穿插展开/合拢与层/键盘 | 视图生命周期、订阅释放、草稿/指定待办保留、presented ACK |
| P4 少动效/省电 | 默认、减少动效、真实 saver、低电量分别跑 P1/P3 子集 | 用设备事实证明回落；不以改 App 字号或模拟样本替代系统状态 |
| P5 冷启动/常亮 | 10 次进程冷启动；keep-awake 开/关跨页与前后台 | 到可交互时长、冻结帧、系统窗口/常亮事实、开关恢复 |

重放输入走离线受控 harness，prod 上只做正常用户操作；不要为造 500 条消息向生产连发 500 个请求。诊断包与交付包差异要记录，正式 prod 子集仍需复验。

### 4.1 建议验收门槛

- 失效/卸载视图的持续动画更新 **0**；已隐藏且不承载用户反馈的视图不持续做动画/文本重排。共享宿主仍要完成正在进行的业务，不把停掉业务当节省负载。
- 标准滚动/切页场景 missed-frame 比例≤5%，帧时间 p95≤2 个实际刷新周期；>500ms 的冻结帧为 0。分母与工具定义写入协议，这些是本项目提议门槛。
- 停播、确认、取消的触摸响应 p95≤100ms，不能靠禁动画或关闭语音才通过；声音停止的时间另按播放事实/声学证据记录。
- 30 次路由循环后静置 2min，PSS 相对预热基线增长≤`max(20MiB, 10%)`，重复 3 轮无持续上升趋势；不通过强制 GC/清缓存掩盖泄漏。
- 诊断开启相对关闭，核心交互 p95 与 CPU 不恶化超过 5%；噪声大于差异时标无法判断并改善取样，不硬作优化结论。
- CPU/电量本批先给分场景基线与前后变化，复杂耗电目标交 AR11 冻结；不可凭短期电量百分比宣称量产续航达标。

若基线本已达标且无可定位问题，交付可复现证据和观测即可；不强制为了“优化幅度”重构。

## 5. 修改策略与执行顺序

| 步骤 | 实施重点 | 交付物 |
|---|---|---|
| A09-0 | 核对当前实际树并冻结工程基线；正式签收再核 AR04/06/07/08 的选定树及受影响范围 | 基线与依赖清单 |
| A09-1 | 最小有界诊断聚合、只读导出、目标事件负控 | 字段合同、脱敏和容量检查、开启/关闭开销 |
| A09-2 | P0～P5 取 A，按线程和活跃音轨归因 | 逐场景报告，不把 JS underrun=0 推导为原生音轨正常 |
| A09-3 | 只修确定热点：selector/context 分割、稳定 props/key、可见性订阅、动画取消、长文增量处理 | 小步可审查 diff，每类修复对应一个可重现现象 |
| A09-4 | 同场景取 B、查视觉/操作与协议回归 | 对比数据与关键截图；不可见页不提前 ACK |
| A09-5 | 固定 prod 验证、文档与 AR10 交接 | 诊断使用说明、场景指标、已修/未复现/未通过区分 |

selector/context 分割优先围绕已有 SessionCore 和派生 Presence，不另养同步状态。动画可见性需要同时考虑 route、层遮挡、AppState 与减少动效；已有 cleanup 正确的分支保持。长列表优先查当前列表实现的 key/订阅/回收，不预先指定换库。任何原生/依赖升级另立必要性证据，不把升级当万能修法。

## 6. 验证与完成条件

| ID | 验收要求 |
|---|---|
| A09-V01 | 当前历史问题可复现或有充分取证证明未复现；监测能力已用负控证明 |
| A09-V02 | P0～P5 逐场景有固定包证据；低电量与 saver 不互相顶替 |
| A09-V03 | 性能指标达到采样前采用门槛，未达项保留原始样本 |
| A09-V04 | 诊断容量、TTL、跨身份清理、脱敏、无自动采集/上传成立 |
| A09-V05 | 草稿/待办不丢，确认对象不串，停止/采集提示始终可达，提醒 ACK 仍来自真实呈现 |
| A09-V06 | 无音频漏段/嗡嗡/新增长空白；没有通过破坏 AR07/08 指标换 UI 数字 |

本地跑 mobile tsc/Jest/lint，重点 `assistantPresence`、`presenceTrail`、`orbPolicy`、`lowPower`、`stopPlaybackUi`、`ar05Dock` 和呈现/会话测试；新增生命周期测试必须验证订阅/动作结果。纯可逆布局整理不为复述结构另写扫描测试。共享代码变化追加 HMI 验证；原生差异遵循构建与验包指南。

## 7. Goal 文本

执行方式以[工程交付与集中验收安排](2026-09-10-android-goal-delivery-and-acceptance-plan.md)为准。下面两种目标在启动时选择；默认采用工程交付目标，本文完整验收矩阵仍保留。

### 工程交付 Goal（默认）

> 按 AR09 方案完成工程交付：先冻结当前实际语音默认与宿主基线，完成只读有界诊断、已定位的渲染/订阅/生命周期修复、必要回归和现有设备/授权下可执行的性能矩阵。不要等待 AR07/08 全部人工签收才动手；它们最终改变运行负载时再补受影响的同包复验。交付候选、指标和最小设备补证清单，不把未验格标通过。

### 完整验收 Goal（另行启动）

> 按 AR09 方案，在 AR04 宿主及 AR07/08 选定实现上冻结 release 基线，补齐有界、脱敏、只读诊断，量取空闲、长回答、跨页、折叠、减少动效和省电负载。只修已定位的渲染/生命周期问题，完成同协议对照及确认、取消、采集、停播、ACK 回归，在固定 prod 包上交付性能与观测证据。历史日志数量不当当前结论，取不到的设备格保留未验。

向 AR10 交付候选 SHA/APK、有效诊断路径、逐场景指标和未达项；实施记录按[接续路线 §6](2026-09-09-android-ar06-ar11-execution-roadmap.md)追加。

## 0. 结论先行

**25 条测试语料里：基本具备 ≈3 条，部分具备 ≈5 条，缺失 ≈17 条。**

定性判断：**这一轮考的不是「规划得对不对」，而是「执行面有没有那个维度」。**
上一轮对标（M0a→M5）补齐的是规划智能——落域、知识供给、结构化输出、自进化，那些现在是强项（人称→地点一跳解析、途经点候选二选、缺槽追问、条件提醒 adaptive、场景询问式触发都已在线，见 §4）。而这一轮指令集的差距，绝大多数**不是 LLM 不聪明，而是 slots / API / 状态模型里根本没有那个字段**：

1. **时间维不存在**——全链路没有任何「X 点前到」的约束表达与 ETA 求解（G1）；
2. **路线几何维是假的**——「顺路」实为「目的地附近」，真沿途取点只有充电域有（G2）；
3. **记忆消费维只有三个出口**——存储面完整（六分类+权重+关系图谱），但除「人称→地点」「新闻重排」「prompt 文本注入」外，记忆不改变任何搜索/车控/路线行为；§六 的 6 条长期记忆语料**全军覆没**（G6）；
4. **生态维是诚实桩**——订座/场次/票务无 provider（G10）。

EVA 指令集自己的两句定性值得引用，它们恰好点在 G1 与 G6/G7 上：
> 「这种测试比『导航去 XX』重要很多，因为它测的是 constraint solving。」
> 「长期记忆甚至比『会开车』更能体现 EVA 的上限……『没有当前语音输入也能触发正确服务』应该单独列为最高等级能力。」

## 2. 缺口归簇（11 簇）

每簇给：缺什么 / 手里已有什么资产 / 补齐方向。**簇的编号即 §1 引用的 G 号。**

### G1 时间约束求解（constraint solving）——最大单一缺口
- **缺**：「X 点前到」的 deadline 槽位与全链表达；ETA 与 deadline 的比对判定；由事件时刻反推出发/用餐窗口；途经点绕行代价量化（vs 直达 Δ分钟）；冲突时的**量化澄清**（「最近的站 17:06 到、前方 3.2km 那家 16:55 到，改去这家吗」）。
- **资产**：`get_route` 已回全程 `duration_min`（导航/充电/行程三方在用）；「里程 vs 续航」advisory 模式已跑通（`agents/navigation/src/agent.py:679-694`，同款模式做时间维即可）；REMINDABLE_ACTIVE 已有「到达 ETA→提醒」半环（`agent.py:658-670`），设计文档 P2 早已预留「出发提醒」（`docs/design/2026-07-11-reminder-agent-design.md:350`，`source='agent'` 字段已留、无写入方）。
- **方向**：navigate_to/charging 增 `arrive_by` 槽 → 路线算完做 deadline 判定 → 满足=正常+顺带报「预计 XX:XX 到」；不满足=按现有 `waypoint_choice` 形态出**带 ETA 对比的候选澄清卡**。出发提醒=事件时刻−路程−提前量，写 REMINDABLE 反向环。

### G2 真·沿途搜索（along-route）
- **缺**：`stop_category` 的候选搜索锚在目的地坐标（`agent.py:545`），不是路线沿线；nearby 无 along-route 模式。
- **资产**：**完整的沿途取点基础设施已在充电域**——`weave_charging_targets`（`agents/charging_planner/src/weave.py`，注释自述「纯函数，供 trip-planner 与 charging 复用」）+ `get_route(with_polyline=True)`（`navigation/providers/amap.py:140-143`）。
- **方向**：把滑点法泛化给 stop_category（按行程里程 30%-70% 段取样搜类目），改动集中在 navigation 一处。

### G3 模糊目的地推断扩域
- **缺**：俗称/绰号（大秋裤/大裤衩）——映射在 LLM prompt 里有、**入口 marker 正则够不到**；自然地物（湖/山/岛）在 prompt 语义域外。
- **资产**：`_sdk/landmark.py` 解析器 + `name_matches` 地图校验 + 直搜落空自动兜到 `_via_landmark()` 的路径（`agent.py:784`）都在。
- **方向**：小成本高收益——扩 marker 词族（俗称类：秋裤/裤衩/大X；自然地物类：湖/山/塔/桥/岛+形容词共现）+ prompt 扩自然地物域 + 补 exemplars；保留「推断后经地图验证、必要时 dest_choice 确认」既有安全形态。⚠ prompt 内建映射有城市偏置风险（「大秋裤」内建例指向央视大楼，苏州语境需城市约束优先）。

### G4 主题→POI 集合（内容型行程）
- **缺**：「跟着《太平年》游杭州」型影视/文化主题映射；trip 候选池固定两个检索词、LLM 不得越池（这是防幻觉的正确设计，但把「主题知识」也一并挡死了）；「北上追春天」方向性主题理解。
- **资产**：追问形态已对（NEED_SLOT）；info.search/Exa 接地检索在线；trip 的 Ground 段本就有「接地失败不捏造坐标」纪律。
- **方向**：给 trip pipeline 加一个可选的**主题检索步**（LLM/联网产候选地名列表 → 逐个高德接地验证 → 通过者入池），池的封闭纪律不变、只是入池来源多一路。落域侧补 exemplars（「跟着X游Y」「X同款打卡」→ trip.plan）。

### G5 POI 属性筛选与偏好重排
- **缺**：安静/停车方便/无台阶/不辣等属性维度（现仅评分/人均/营业中/评分排序）；`business.tag` 零过滤；类目语义扩展（动物园缺位且兜底会错搜「美食」）；偏好重排（设计文档自列 P1 未做，`2026-07-05-nearby-discovery-redesign.md:293`）。
- **方向**：①类目表补齐+兜底改诚实追问（错结果比无结果更糟）；②tag/评分做软重排通道，把 `_taste_prefs` 从话术挪到检索前（见 §5①）；③「停车方便」可用「目的地半径内停车场计数」近似，复用现有停车类目。

### G6 记忆消费面（存得下 ≠ 用得上）
- **缺**（按环拆）：①偏好→槽位/筛选无确定性通道（只靠 LLM 看 400 字符块自觉，`context.py:720-738`）；②「关于谁」维度结构性缺失（无 subject 字段；`prefers_brand` 关系边零消费方）；③负反馈极性与降权不存在；④历史轨迹不存（导航后不写 episodic）且 episodic 不进 planner 召回。
- **资产**：六分类抽取+权重衰减+关系图谱+occupant 隔离全在；三个既有消费出口证明模式可行（人称→地点是最好的样板：确定性两跳、查不到诚实追问不猜）。
- **方向**：照「人称→地点」样板逐环开消费面：偏好谓词→检索槽的确定性映射（cuisine/taste 先行）；memory_item 加 `subject` 维（proto 演进，向后兼容）；抽取 prompt 加极性、weighting 加减分通道；导航成功落一条轻量 episodic（POI+时间+同行人），召回按需放开 kinds。**每一环都要配「消费方证据」验收——本项目已两次证实「存了没人用」的形态**（route.avoid_highway、prefers_brand）。

### G7 事件记忆→当天主动（「最高等级能力」）
- **缺**：带日期的记忆事件没有任何到点触发机制（memory 无定时器、reminder 不扫记忆、scene 触发无日期维）。
- **资产**：reminder 的 fire_at 调度+geofence+主动治理器投递链全部现成；条件提醒 adaptive 链路在线。
- **方向**：最小闭环=抽取管线识别「未来事件」（有日期/星期+事件名）时**顺手创建一条 reminder**（source='agent'，字段已预留），到点走既有 user_contract 投递；触发话术带询问式后续（「要现在导航去少年宫吗？」→ send_text 回发正常链路）。这把「无输入主动」翻译成了本项目安全观下的合法形态（见 §3）。

### G8 导航会话状态与增量重规划
- **缺**：「导航中」不是会话状态（焦点无 waypoints/无 deadline/无路线），途中修改无对象可指；「换条路」=全新导航。
- **方向**：焦点扩 `active_route`（destination+waypoints+arrive_by+ETA），navigate 成功即写、修改类意图（去掉途经点/换目的地/改约束）做增量语义。依赖 G1（约束保持才有意义）。改动面在 context/engine，属于本清单里**唯一要动编排核心**的簇，需单独 RFC。

### G9 多途经点与多目的地序
- **缺**：waypoint 标量→列表；「先A后B」顺序语义；顺路排序（最近邻即可起步，高德 API 天然支持 16 途经点）；trip 跨城市结构（单城市字符串、无跨日 leg）。
- **方向**：分两刀——导航域多 waypoint+保序（小）；trip 跨城市化（大，Trip 模型演进，建议独立 RFC 且优先级靠后）。

### G10 服务生态（订座/场次/票务）
- **缺**：真实订座、电影场次、票务。均属「有 provider 才能做」。
- **判断**：PoC 阶段维持诚实桩是对的（现状话术已诚实）。若要补演示叙事，可按 mcp-bridge 准入流程接一家有开放接口的（美团/大众点评开放平台门槛高，可先做「电话+导航」增强桩）。**不建议为对标造假订座。**

### G11 路线策略面
- **缺**：高德 `strategy` 从未使用；避堵/不走高速/高速优先/大路优先无意图面。
- **资产**：「不走高速」在 routing 基线里有现成红灯用例可当验收；记忆侧 route 偏好谓词已在抽取 prompt 里。
- **方向**：navigate_to 加 `route_pref` 槽 → 映射 strategy 参数；「风景好的路」高德无直接策略，可降档为「大路优先/避开高速」+诚实话术。顺带打通 G6 的路线偏好消费环。

## 3. 哪些 EVA 行为不照抄（安全红线对照）

1. **「主动预设导航/自动播放内容/自动调温」**（case 5/6/§六）：直接违反「主动路径零执行权」铁律（`proactive/governor.py:10`、`triggers.py:3-6`、e2e 断言 `test/e2e_scene.py:390`）。对标形态统一为**询问式建议卡**（「比赛 1 小时后开始，建议 14:20 出发，要现在导航去少年宫吗？」）。这与上一轮「全程无需二次确认是营销叙事不跟」同一立场——我们的差异化是「主动到建议为止，执行永远有人」。
2. **悬架控制**：VAL 无该对象。演示语义用 `driving_mode.comfort` 表达即可，不为对标虚增车控对象。
3. **危险动作确认闸**：G1/G8 的重规划路径产出的仍是计划，逐字过既有 planner 校验/权限/VAL/require_confirm，不开新执行通道。

## 4. 已具备、可直接进对标叙事的（不要重做）

「去接孩子放学」记忆图谱一跳解析（查不到诚实追问不猜）；途经点候选二选+序号续接焦点；泛目的地 dest_choice 高德候选确认；行程结构化增删改+雨天改室内+在途重排；缺槽 NEED_SLOT 追问（「北上追春天」的正确行为半边）；条件提醒 adaptive 两轮兑现；位置提醒 geofence（e2e 7/7）；场景一句话创建+询问式触发；声纹多用户记忆隔离；S2S 双语音链路。

## 5. 探查顺带实锤的存量问题（与 EVA 无关，但建议记账）

1. **nearby 假个性化（最重，建议尽快修）**：口味偏好在 `place.search` **之后**才召回、只拼进话术「（已参考您口味：…）」，结果集一条没变（`agents/nearby/src/agent.py:378 vs 394-399`，已亲验）。系统声称参考了但没参考——按本项目标准这是诚实性缺陷，独立于 G5/G6 先修（挪到检索前进 cuisine/keyword，或删话术）。
2. **`trip.navigate`「第一站」疑似不可达**（已亲验代码路径）：`agents/trip_planner/src/agent.py:434` `if picked is None and day_n:`——不带「第N天」时 day_n=0，序数分支短路，「导航到第一站」落「没找到您说的那一站」。guide 与对抗语料都期望该说法可用，建议补一条用例证实并修。
3. **主动治理器合并不分 owner**：`_flush()` 全量排序合并只带 top 的 user_id（`proactive/governor.py:465-514`），同窗两个乘员的消息会合成一条记在一人名下——reminder 侧刻意做的 owner 分组（`scheduler.py:43`）在治理器这跳被抵消；无跨 owner 断言用例。
4. **评分排序在截断之后**：nearby 先按距离序截到 10 条再排评分（`amap.py:145-148`），「评分高的川菜」不是 25 候选里的 top-rated。
5. **死槽位一批**：`nearby` 的 radius/price_level/datetime/party_size、`charging.plan` 的 departure_time——声明了、全仓无消费点。要么接上（datetime/party_size 归 G10，departure_time 归 G1），要么从 manifest 摘除。
6. **条件提醒语义边界未记账**：「如果明天下雨提醒我带伞」的条件在**创建时**（同轮 adaptive）求值，非触发时——预报次日翻盘无从修正。属 v1 已知边界，建议在 conventions 记一笔，防止被当成「触发时求值」承诺。
7. 文档漂移两处：`agents/navigation/README.md` 能力表只列 2/6 条；`agents/parking_payment/README.md` 仍列已删除的 parking.find。

## 6. 优先级建议（待泓舟裁定）

按「EVA 指令集覆盖面 × 现有资产杠杆 × 改动风险」排：

| 档 | 簇 | 理由 |
|---|---|---|
| **P0** | G1 时间约束求解 | 出现在 5+ 条语料，指令集自点名「比导航去XX重要」；资产多（duration 已有、advisory 模式可仿、出发提醒字段已预留）；不动编排核心 |
| **P0** | G6 记忆消费面（含 §5① 假个性化修正） | §六 6 条全灭；指令集称之「上限」；样板（人称→地点）已验证该模式可行；逐环可独立交付 |

## 0. 结论

- F01 五条里最差的是 M09「能量回收有几档」→「怎么调」：三次 200×5 共 8 遍，**一次有用的回答都没有**。其中 3 遍规划器派对了

  之后，计划离开那个能力就重试一次（复用现有的「依赖焦点的省略追问」重试规则）。
- M10（车主叫法「刮车」）、V220 / P05（闲聊的安全直答抢在让手册之前）、M01（主语在、章节路径不含它）登记，理由与前提见 §3.3–3.5。

## 2. 根因

### 2.1 M09：检索丢了补全，规划落点有方差

- **检索**（确定性）：`manual_rag._retrieval_question` 原话优先，只在两种情况用规划器的槽——原话有指代主语（「它有几档」，
  `runtime.anaphora`），或槽只落在多分句原话的其中一句。「怎么调」既没有指代词也只有一句，补全的槽被丢掉，原话零命中，目录路由拿
  「怎么调」也找不到东西。
- **落点**（模型方差）：省略主语的追问在规划器看来信息量太低，3 / 8 判成要澄清或零步落闲聊，1 / 8 当成调节命令。现有的
  「依赖结构焦点的省略追问」重试（`planning._focus_dependent_plan_conflicts` + `retry_policy.focus_dependent_conflict`）只认
  「那个取消 / 换一批 / 明天呢 / 第 N 个的详情」几种，不认方法 / 属性追问。

### 2.2 M10：车主叫法，词法零命中

「刮车」手册不认识，词法检索零命中；派给手册时手册的目录路由（模型调用）能把它路由到「哨兵模式」并答对（3 / 3）。落到闲聊时，
闲聊的 `manual.claim` 只跑词法、不调模型（[闲聊让手册](2026-10-04-chitchat-defers-to-confident-manual.md) §5 的取舍），认不出，
闲聊于是按通用常识答「行车记录仪的停车监控」。

### 2.3 M01：主语在、章节路径里没有它

词法首页就是对的（自适应巡航），只是「跟车距离」不在章节路径里，不算有把握。放宽「章节命中」在 §1 的 A/B 里证伪：正例多认出 9 条，
负例同时多误判 9 条（「我有哪些提醒」「快充在哪」…）。

### 2.4 V220 / P05：闲聊的安全直答抢在让手册之前

落到闲聊时，`_deterministic_reply` 先跑 `_safety_answer`：句子里有车辆告警（胎压报警灯），确定性回一句处置提示就结束，轮不到问
手册。派给手册时，手册对告警走来源证据通道（不调模型），回答是同一句处置提示加手册原文，并且同样声明会话告警（保留键
`_safety_alert`，形状与闲聊一致）。

## 3. 方案

### 3.1 S1：原话零命中、槽是它的补全 ⇒ 用槽检索（做）

`manual_rag` 的 `handle` 在原话检索零命中、且规划器写的槽**包含原话的全部字**（只是补上了主语，没改用户的说法）时，改用槽检索与
目录路由，依据记为 `completion`。仍是原话优先：原话自己检索得到东西就不碰。安全分级与告警照旧只认原话（安全红线 6），槽只参与检索。
指代补全那条「否决不回退」的口径同样适用（`scope_veto` 只对 `clause` 依据回退原话）。

### 3.2 S2：省略主语的追问跟在只回答的能力之后 ⇒ 不许离开那个能力（做）

- 判据 `runtime.anaphora.has_elided_subject`（唯一实现，零领域词）：去掉句首引子（那 / 那么 / 然后…）与句末语气词后，整句只有疑问词
  与泛化动作 / 属性问法——「怎么调 / 怎么设置 / 怎么开」「在哪里调」「有几档」「能调吗」。带任何对象词的句子都不算（那由规划器自己认）。
  词表过 `runtime/tests/test_anaphora.py` 的零领域词守卫。
- `planning._focus_dependent_plan_conflicts` 加一支：句子是省略主语的追问、上一轮意图（焦点 `last_intent`）是**只回答**的能力
  （manifest `response_only`，规划目录构建时从注册表记下只回答的意图集，不另立声明），而计划离开了那个命名空间、零步、不受话或要澄清
  ⇒ 冲突，按现有 `focus_dependent_conflict` 规则重试一次，校正话术不变（「上一轮意图=…，本轮必须在同一能力命名空间内…」）。
- 只认只回答的能力，是为了不把方法问句推进写操作：上一轮是车控时，「怎么调」可能是在问也可能是在说，交给规划器与现有的方法问句闸。

### 3.3 S3：V220 / P05 落闲聊时让手册先答（登记，不在本轮）

把车辆告警类问句（不含司机状态：犯困、喝酒仍由闲聊直答）从安全直答改成改派手册，能拿到手册原文，告警声明也不丢。**前提没满足**：
改派必须零播报，改派失败时编排保留原步结果（话术为空）——手册不可达时用户连处置提示都听不到。要先给改派加失败回落（协议保留键带回落
话术，或闲聊以内部调用问手册、失败用自己的直答），再做。两条各 1 / 8，失败时处置提示本身是给了的。

### 3.4 S4：M10 车主叫法（登记，先测量）

两个方向，都要先量：

- (a) 规划器软知识：手册能力描述 / skills 指南写明「问本车能不能做某事、用车主口语说的，交手册」，在手册口语召回语料上 A/B
  （§1 的正负例集），量落点与对非手册问句的误伤；
- (b) 闲聊认领加目录路由：词法没把握时让 `manual.claim` 也跑一次目录路由（模型调用），与闲聊自己的生成并发、拿到结论前不放流；
  量闲聊首包时延增量与 §1 负例集的误判。

推荐先做 (a)：不增加闲聊每一句的模型调用，改动可整体回退；(a) 证伪再做 (b)。

### 3.5 S5：M01（不改）

1 / 8，放宽已证伪（§2.3）；S2 不覆盖带主语的句子。保持方差记账。

## 4. 验收

- 单测：S1 的补全判据（含原话命中时不用槽、槽改了用户说法时不用槽、指代 / 分句两条旧依据不变）；`has_elided_subject` 正反例与零领域词
  守卫；规划冲突判据（只回答能力之后、车控之后、带对象词三组）。变异：去掉 S1 的回退、去掉 S2 的只回答限制、判据词表扩大到带对象词。
- 语料：`has_elided_subject` 在现有语料上的命中面逐句过目（只该是省略主语的追问）；路由提示基线不变。
- M09 的期望补 `speech_not: ["手册里没有查到"]`：「派发 + 呈现」看不出答了「没有查到」，这条才把「真的答了」写成判据（§1 那 3 遍按新
  期望判红）。
- 真栈（钉 M3）：M09 ×5 必须派给手册、答出调法；M01 / M10 / V220 / P05 ×5 作对照，记方差不判本轮成败。

## 5. 风险

- S2 让「省略追问 + 计划离开」多一次规划调用；只在上一轮是只回答能力、句子整句是省略问法时触发。
- S1 用的是规划器按上下文补的主语，可能补错；只在原话自己零命中时才用，补错的后果与现在「没有查到」同级。

# 唤醒应答语：喊唤醒词之后先回一句「我在」再听

- 状态：实施中（2026-10-11，用户：「每次唤醒后没有应答语，这个在其他主流语音助手上都是有的，你要优化下」；提交、推送、部署与真栈验证沿用同一授权）
- 交付对象：共享语音状态机（`hmi/src/voiceLoop.mjs`）、Android（免唤醒控制器、应答片段、提示音协调）；HMI 行为不变
- 前置：[R4.3b 语音回路硬化](2026-07-05-r4.3b-voice-loop-hardening.md) P4（HMI 唤醒提示音）、[唤醒后连续对话的拒识](2026-10-10-handsfree-followup-rejection.md)、[语义打断](2026-10-11-semantic-barge-in.md)

## 1. 问题

- Android 喊唤醒词后只有 120 ms 的两音提示（设置「提示音」开时），没有人声应答。HMI 有：开免唤醒时用当前播报音色预合成「在呢 / 我在 / 你说 / 请讲 / 我在听」，唤醒时随机播一句。
- Android 当初不做的理由写在 `handsFree.ts` 头注：批处理 TTS 回 mp3，而 App 关了 FFmpeg 解不了。但流式 TTS 回的是 PCM（HMI 的预合成收的就是流式 PCM），这个障碍不成立。
- 真正的约束是回声：Android 没有平台回声消除（Oboe 输入流用 VoiceRecognition 预设，`voiceLoop.mjs` 续问窗回声那段注释），而唤醒后 ASR 立刻就开着——自己播的「我在」会被麦收进去，当成用户说的话发出去。

## 2. 主流做法

- 小爱同学、天猫精灵与车载助手（NOMI、理想同学、小 P）：喊唤醒词停下来 ⇒ 先回一句短应答（我在 / 在呢），再开始听。
- 「唤醒词 + 指令」一口气说完（oneshot，如「小爱同学打开台灯」）⇒ 不回应答，直接执行。
- 应答期间不收音，或靠回声消除去掉自己的声音；轻点按钮唤醒只给提示音 / 界面变化，不说话。

## 3. 方案

### 3.1 状态机（共享，判据只有一份）

```text
wake({ack:true}) ─→ LISTENING（光球立刻变；ASR 先不开）── 判断窗 240 ms，外设逐窗报语音概率 vadProb(p)
   ├─ 说话窗占比 ≥ 0.4（单窗 p ≥ 0.5）⇒ 一口气接着说：不回应答，判断窗那段音频作精确前滚交给 ASR，计时从唤醒算起
   └─ 否则 ⇒ onWakeAck() 播应答，返回时长 ms
        ├─ ms > 0：应答期间不开 ASR、不认 VAD 事件；播完再等 150 ms → 重置 VAD 端点 → 开 ASR、挂 5 s 误唤醒回收
        └─ ms = 0（没就绪）：回落提示音 onWakeChime，立刻开听（同旧路径）
wake({ack:false}) 或外设没注入 onWakeAck ⇒ 旧路径：提示音 + 立刻开 ASR（HMI 逐字不变）
```

- 新外设回调 `onWakeAck() → ms`、`onVadReset()`，新入口 `vadProb(p)`；`onOpenAsr` 多一个可选的 `preRollMs`（只有 oneshot 时给，外设按它精确回取，不再叠固定前滚）。
- 判断 / 应答期间：重复的唤醒命中不再起一轮（一声唤醒词可能命中两次）；`asrPartial / asrFinal` 与 VAD 起止事件一律不认；拆机、系统抢占照旧回 IDLE / ARMED，到点的定时器不再开 ASR。
- 为什么看逐窗概率而不看 VAD「在不在说话段」：唤醒词刚说完时，端点检测的静音尾（800 ms）还没走完，平滑状态几乎总在说话段里——R4.3b P4 用 `inSpeech` 跳过提示音就是这样失败的（提示音几乎总被跳过）。原始概率一两个窗（32–64 ms）就降下来；KWS 命中本身比唤醒词结尾晚 0.2–0.4 s，判断窗落在唤醒词之后。
- 应答期间的 VAD 起止不认、播完要重置端点：应答的回声会让端点检测停在说话段里，不重置的话，用户紧接着开口不会再有一个新的起点，短指令会被「短语音噪声」规则当噪声丢掉。

### 3.2 Android

- 应答句子与 HMI 同一份：挪进共享 `hmi/src/voiceCues.mjs`（HMI 改为从这里导入，句子不变）。
- 预合成：`tts.ts` 新增 `collectTtsPcm`（与 `TtsSession` 同一条流式协议：start → text → finish；meta / 二进制 PCM / done），`voiceCue.ts` 用当前播报引擎 + 音色逐句串行合成、存 PCM。开免唤醒与改音色时准备；部分失败保留成功的，唤醒类全失败就不用人声。
- 播放：一次性 PCM 播放器播一条随机片段，把时长交给状态机。
- 不走人声应答的情形（一律旧路径：提示音 + 立刻开听）：播报策略「静音」、S2S 挡位、片段没准备好（准备中 / 失败 / 断网）、轻点光球唤醒。
- 提示音协调：两音提示原本由在场层在「待命 → 收音」时播。要走人声应答时，控制器在调 `wake` 之前登记「这次压掉提示音」，在场层播唤醒提示音前看这个标记；回落路径（应答没播成）由控制器补播提示音，照旧遵守「提示音」开关。
- 退出词同时补上退场应答（「好的 / 好嘞 / 我先退下了」，没准备好就静默），与 HMI 一致。

### 3.3 HMI

不接新流程：浏览器有回声消除，「唤醒必播」是 R4.3b P4 真麦验收过的行为。只把应答句子改为从共享模块导入。
Android 真车验收后再决定 HMI 要不要也走「一口气说完不应答、应答期间不收音」。

## 4. 刻意不做

- 设置开关（唤醒应答 开 / 关 / 只提示音）：先不加，有需要再加。
- 应答期间说的话不收：与主流一致，要么等「我在」再说，要么一口气说完（走 oneshot）。

## 5. 验证

- 状态机单测：判断窗、oneshot 前滚与计时、应答期间屏蔽、应答播完开听与端点重置、回落提示音、重复唤醒、拆机 / 抢占、从播报 / 处理中唤醒、外设不报概率、手动唤醒、旧路径不变。
- Android：流式合成协议、片段准备与播放、控制器接线（KWS / 手动 / S2S / 静音）、提示音压制、精确前滚。
- 设备：OPPO 装包冒烟；唤醒后的听感（应答、一口气说完不应答、应答不被当成用户的话）由用户真机 / 真车验收。

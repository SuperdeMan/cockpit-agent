## P1 个人地点作途经点

**缺口**（指令集三§1#2）：「先送孩子去学校，然后送我去公司」——waypoint 解析只走
POI 搜索（`_navigate_via_waypoint` 对每个 token 直接 `poi.search`），「学校」搜出
随机学校、人称词根本无解析路；真栈 B4 轮落域打散成快速路入口+就近学校拼接。

**方案**：waypoint 逐 token 三级解析（与目的地侧同款权威序）——
① 人称词（`_person_destination`）→ `ctx.resolve_person_place` 关系图谱；命中得地点名
再经 POI 搜索取坐标；未命中 → NEED_SLOT 诚实教学问（与目的地人称流同话术）。
② 常用地点别名（家/公司/学校）→ 画像 `profile.places`；未设置 → NEED_SLOT 引导先设置。
③ 其余照旧 POI 搜索（近目的地）。
planner 侧配范例（「先送孩子去学校再去公司」→ destination=公司 + waypoint=学校 +
stop_category=早餐）。

**验收**：单测（人称途经点命中/未命中教学问、别名途经点已设/未设）+ 真栈探针。

**实施记录**：按方案落地 `agents/navigation/src/agent.py::_resolve_waypoint_token`
（三级解析单点函数，`_navigate_via_waypoint` 逐 token 消费）；范例 navigation +1。
单测 4 条。**真栈**：「先送孩子去学校，然后送我去公司，路上找个能快速买早餐的
地方」→「您还没有设置「学校」的位置。先说「把学校设成XX地址」…」——诚实引导
形态兑现（修前打散成快速路入口搜索+随机学校导航）。

## P2 多城 trip 用户点名 POI 入池

**缺口**（指令集一#9）：六城保序 trip 卡成立，但用户点名 POI（大秋裤→东方之门、
灵山大佛、趵突泉）没保进各城行程——trip 池只有「{城}景点/美食」+主题检索两路来源。

**方案**：`trip.plan` 加 `must_visit` 槽（planner 填点名地点顿号连写）。
`ground_must_visit`：逐名接地（直搜 `name_matches` → 失败走 `landmark_candidates`
俗称解析——「大秋裤→东方之门」映射本就在 landmark prompt），接地成功按坐标就近
归城（各城池质心 `_rough_km`）；入池 + propose prompt 注「必去地点务必编入对应城市」
+ ground 后**确定性补插**（骨架漏排的必去点插进其城首日）。接不到的照旧丢弃不臆造
——**池的封闭纪律不变，入池来源多第三路**（与 G4 主题步同款表述）。

**验收**：单测（直搜接地/俗称接地/接不到丢弃/归城正确/骨架漏排补插）+ 真栈大长句。

**实施记录**：`pipeline.py::ground_must_visit` + `ensure_must_visit_in_itinerary`；
agent 贯穿（槽拆分→接地→propose hint→补插）；manifest 槽+描述。单测 5 条（含
俗称经 landmark 接地）。**真栈**：大长句六城行程里东方之门（「大秋裤」接地成功）/
南京长江大桥/趵突泉/潍坊世界风筝博物馆/天安门广场/灵山大佛**全部进入行程**
（修前点名 POI 全丢）。已知边界：LLM 骨架的跨天归城偶有排错（点在行程里但
城市标签不齐的天）——补插只管「漏排」，不管「排错天」，软层噪声记档。

## P3 raw 槽校验文案诚实化

**缺口**（R2c）：「帮我找杯咖啡喝」被派 luckin.order 后，`_quantity` 对非纯数字
一律 NEED_SLOT「数量需要是 1 到 20 之间的整数」——机器话术直出 TTS；且 planner
填「一杯」「2杯」这类自然语言本就该解析成功而不是追问。

**方案**：两家商户（luckin/mcdonalds）`_quantity` 容错解析（剥量词尾 杯/份/个/只、
中文数字一~二十、全角数字）；仍无法解析时话术改人话（「点几杯呢？一次最多帮您点
20 杯」），越界同款。**校验边界不松**（仍 1–20 整数）。

**验收**：单测（一杯/两份/１２/超界/乱码各形态）；话术无「整数」字面。

**实施记录**：`base.py::parse_quantity` 共享容错（全角/中文数字/量词尾），两家
`_quantity` 委托 + 话术改人话；参数化单测 21 条（宽容 10 形态 + 边界不松 11 形态）。
**真栈**：「在瑞幸点两杯生椰拿铁」→ 数量解析通过、直接进商品选择卡（修前这类
槽值会触发「数量需要是 1 到 20 之间的整数」直出 TTS）。

## P4 散句 relation 确定性抽取

**缺口**（R8）：「我老婆平时在深圳湾万象城上班」经 LLM 抽取落成 semantic 偏好而非
relation 边——散句教学不稳；且消费面还有个洞：`resolve_person_place` 只查
`place_of` 边，LLM 即便正确抽成 `works_at` 也**查不到**（存得下用不上第 N 例）。

**方案**：两半——
① `memory/extract.py` 加**确定性 relation 前置抽取**：正则
「{人称}(叫|名字是){名}」→ family 边、「{人称/名}(平时|一般)?(都)?在{地点}
(上班|上学|读书|工作|上幼儿园)」→ family(无名时以称谓作实体名) + place 边；与 LLM
候选按 (subject,rel,object) 去重合流，**LLM 失败时确定性候选照常返回**。
② `store.resolve_person_place` 的 place 查询放宽为 `place_of ∪ works_at ∪ lives_at`
（人的常在地就是这三类，消费面对齐词表）。
教学流（追问→回答）不动。

**验收**：单测（散句两族抽出边/LLM 挂了照常抽/works_at 边可解析）+ 真栈散句教学链。

**实施记录**：`extract.py::deterministic_relations` + extract() 合流；store 查询
三类并集（place_of∪works_at∪lives_at）。单测 extract 5 + store 2。**真栈**：
「我老婆平时在深圳湾万象城上班」→ 确定性边 `老婆--works_at-->深圳湾万象城`
落库 →「去接我老婆」→ **导航到深圳湾万象城**（散句教学→抽取→消费全链闭环）。
⚠ 抽取是响应后异步，25s 内查询有竞态（首验差几秒）——链路正确性与时延是两件事。
**同批抓修恶性缺陷**：同句曾被 planner 映射成 set_place(公司=万象城)**改写了用户
本人的公司地点**——navigation `_set_place` 加人称守卫（长词+「我妈/我爸」代词组合，
单字不裸匹配防「妈湾路」误伤），含人称词只口头记下绝不写画像（对照单测双向锁）。

## P5 负偏好降权 live 闭环复验

**性质**：验证卡（机制=批 C polarity 软降权，单测+语料在；上轮 live 被「找杯咖啡→
下单」落域岔开，范例已投）。

**验收**：真栈链——负反馈点名店铺→抽取→「帮我找杯咖啡」→ 结果集兑现降权（该店
不再置顶/缺席）。

**实施记录**：两处根因串联修复——① 抽取端店名丢失（「第一家太酸」被泛化成
「用户不喜欢太酸的咖啡」，店名只活在助手确认句里）：抽取 prompt 补店名绑定指引；
② **消费端结构性漏洞**：口味召回门禁只认正餐类目（`_FOOD_CATS` 无咖啡），咖啡/
奶茶搜索整个被排除——「这家咖啡太酸」恰是指令集语料却结构性永不降权。新增
`_TASTE_CATS`（降权/忌口按宽集合消费；菜系偏置仍限正餐防粤菜偏置咖啡检索），
recall top_k 3→5（店名条目被泛化条目挤出 top-3 实测）。单测 1 条（降权+检索词
不污染双断言）。**真栈终验**：「帮我找杯咖啡喝」→「不合口味的已排后」+ 三立方
从推荐前三消失（瑞幸×2+Manner 顶上）——六#5 语料全链闭环。

## P6 provider 方差面：范例处置（维持不加 hint）

**性质**：档案化方差面（findings §23/§24 输出通道族）——「处理」以裁定过的软层
通道兑现：三个观测句形投范例（写错只是噪声），**不加 hint、不动 gate 案例集**。

- 组合接送句（R7b 口头确认不执行）→ navigation：接送+顺路+时限组合形 slots 教学；
- 接配偶句（R8b slot 填整句）→ navigation：destination=人称词（agent 侧解析）；
- 「附近的咖啡店」（D2a 过度澄清）→ nearby：省略动词的发现句。

**验收**：exemplars 门禁绿（域错配不涨）；真栈抽验。

**实施记录**：navigation +3（组合接送/接配偶/先后序）/ nearby +1（省略动词发现句）；
exemplars 门禁绿（hit 65/miss 4，域错配 2.4% 不涨）。**真栈**：组合接送句两连全通
（人称→学校 + 沿途咖啡逐家 ETA + 时限判定一轮到位）；「附近的咖啡店」直出列表
不再澄清。方差面维持档案化不加 hint。

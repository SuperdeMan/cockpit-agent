## 1. F01 手册追问：`manual.claim` 放宽——A/B 证伪

§13.7 把 F01 手册追问落闲聊（5 条、8 次运行）归因为闲聊让手册的「有把握」判据偏严，计划「A/B 后放宽」。逐轮看清后分成四种：

- 省略主语的追问（M09「能量回收有几档」→「怎么调」×2）：闲聊只拿当前这句问手册，句子里没有主语，词法不可能有把握；
- 主语在、词法没认出（M01「那跟车距离能调吗」；M10「停车时有人刮车能录下来吗」×3，「刮车」是手册不认识的词，按 2026-10-04 设计要靠目录路由）；
- 「告诉我…再解释…」复合请求整句交给闲聊（V220），请求式不在闲聊让手册的问句判据里；
- 回忆问句复读安全提示（P05「刚才你说胎压报警灯是什么意思」）：上一轮的安全守卫话术本身不含「胎压」。

「有把握」= 首页覆盖率 ≥ 0.7 且主题词在章节路径里、问句没有手册不认识的实词。卡点在**章节命中**：「跟车距离能调吗」首页是对的

## 2. 「记住…」确定性记忆写入

### 2.1 现状（`70b179b7` 合成写车道 r1）

能力目录里**没有**「记住这件事」，规划器找替身：

- 「记住我喜欢喝拿铁」5 / 5 派给生态服务桥（被「拿铁」带去点咖啡），合成账号没授权，答「没有这项能力的授权」；
- 「记住我老婆的生日是五月二十号」5 / 5 当成建提醒，反问「什么时候提醒你」，下一句「我老婆生日是哪天」被挂起的提醒吞掉；
- 「记住，我女儿叫小满」一遍先判不受话、再给零步，落「没能拆成步骤」；
- 落到闲聊时说法不一：有时「在记忆中：用户改喝美式」，有时「这个我没办法记住」，E08 对手机号答「好的，我记下了」——什么也没写。

记忆本身另有两条路：后台抽取（`memory/extract.py`，对话轮写入后异步跑，LLM 归类 + 治理：敏感事实丢弃、7 位以上数字串按电话 / 证件号丢弃）
与 Agent 显式写入（`Remember` RPC，偏好按谓词修订、事实按主体取代）。缺的是**用户明说「记住」时，当场写入并按写入结果作答**。

### 2.2 设计

- **记忆服务新增 `RememberUtterance` RPC**（proto 新增，`cockpit.memory.v1`）：对这一句用户原话跑**同一份**抽取与治理
  （`extract.extract` 单轮）+ **同一个**写入函数（`store._write_candidates`：偏好修订、事实取代、关系边分流），写入沿用后台抽取的代际
  栅栏（请求带 Agent 观测到的 `memory_epoch`；锁外抽取、持锁复核写入，期间被删除整批丢弃，回 `stale`）。返回结果类别：
  `stored`（写入 N 条）/ `pii`（原话含电话、证件号或精确坐标——与治理同一份正则，不调模型）/ `not_stored`（抽取后没有可存的：敏感画像、
  闲话或抽取失败）/ `stale` / `off`（无用户身份）。抽取模型经 llm-gateway，与后台同一出口。
  同一轮稍后还会被后台抽取再看一次：偏好同文加强、异文按维度取代，事实按主体取代——不产生并存的两条。
- **能力 `memory.remember` 挂在提醒 Agent**（`contract.version=2`，`effect: write`，`whole_utterance: true`，无槽：内容只取原话，不让模型改写）。
  选提醒 Agent 而不是闲聊：①「记一下要买牛奶」（待办）、「记得明天提醒我」（提醒）、「记住我女儿叫小满」（事实）同属「记…」一族，
  分辨放在一个 Agent 里只有一份判据；② 当场抽取要调一次模型，提醒 Agent 的预算 8 s 放得下，闲聊只有 2.5 s（Agent 级，无能力级预算）。
  回忆仍由闲聊的记忆读取路径负责。
- **作答按写入结果**，不靠模型措辞：`stored` →「好的，记住了：{原话内容，我→你}。」；`pii` →「手机号、证件号这类信息我不记，需要的时候你再告诉我。」；
  `not_stored` / `stale` →「这句我没能记下来，你可以换个说法再说一次。」；`off` →「现在没开记忆，这句我记不下来。」；服务不可达 →
  「记忆服务暂时连不上，这次没记下来，稍后再说一次就行。」。**只有 `stored` 才说「记住了」**。
- **路由**：判据 `runtime.memory_directive.memory_fact_content`（唯一实现）——句首记忆祈使（沿用 `MEMORY_DIRECTIVE_RE`）+ 内容以第一人称开头、
  单分句、不含提醒线索（提醒我 / 叫我 / 通知我）、不是待办（「要 / 得 / 去 / 买…」开头）。提醒 Agent 清单声明一条整句锚定的 `route_hints`
  （`policy: replace`）把这一形态钉到 `memory.remember`；清单正则与判据由测试逐句对账（声明源只认 runtime 那份）。其余形态
  （复合句、待办、提醒）照旧由规划器判。
- **不做**：不改敏感画像的默认不写策略（用户明说也不写健康 / 宗教等特殊类别，是隐私口径，要改需用户裁决）；语音删除记忆仍不提供
  （E06 必过：只量「不谎称已删」）；跨域消费（E05 估算读路线偏好、E07 提醒读记住的生日）登记另做。

（`_append_pending_hint`，普通 / 流式 / T2 四个出口共用）现在在挂着的是**确认**、这一轮自己又没有新挂起、也没执行动作时，把那条
确认重新带上：同一个 `operation_id`、同一个截止时刻（插话不续命），`confirm_policy` 由挂起状态重建（`contracts.held_confirm_policy`：
摘要用挂起那一刻存下的那句、风险档按挂起步的 `require_confirm`，不读模型 goal）。确认仍只执行那一笔（认领与重放闸不变）；补槽 /
选择类挂起照旧只给软提醒。旧用例「插话轮不带 need_confirm」按裁决改写。

- 客户端：两端的确认条本来就按待确认台账留着（HMI `awaitConfirm = pendingOps.length > 0`、mobile `needConfirm: pendingOps.length > 0`），
  插话后并没有被顶掉——第一版提交说明（`4faa9f8c`）写的「确认条被新消息顶掉」不准确。重新带上的效果是最新一轮的 final 如实标明还有
  一笔在等确认，台账按地址合并不出第二张卡，台账丢了（重启 / 重连）也从这一轮恢复。
- 这一轮自己执行了动作（挂着后备箱时说「把空调打开」）只给软提醒：HMI 不给带确认的消息渲染车控结果卡（`ChatView.ControlResults`），
  带上会把刚执行的结果藏掉。
- HMI 置顶确认条改成每个地址由**最早**那条消息呈现（发起确认的那一轮）：同一地址再出现在插话轮时挂的是插话自己的卡片，按最新那条
  呈现会把商户下单说成「车辆操作」、丢掉「扫码后才付款」那句说明。mobile 本来就取最早那条（`actionSummary` 用 `findIndex`）。
- 跑数器：核心语料里有 13 条「挂确认之后说了别的」：12 条是插话（P01–P04、P07、P09、P10、P13、P14、EN11、V204、V205），
  P08「算了，先不开了」是取消、不受影响；长会话有 CONT-A、CONT-RECONNECT、INF-TRIP。两个运行器原来把插话轮的任何确认都判成意外确认，改为：这一轮之前就在
  **等确认**的那一笔被原样带回不算（各按自己记下的地址判，补槽那一笔被续接成确认仍算）；规格写进冻结设计 §5。
- 观测：端侧把任何 final 带 need_confirm 的轮记成状态 `need_confirm`（`edge/server.py`），dashboard 上插话那一轮显示「待确认」
  （这一轮结束时确实还有一笔在等确认）；结局（`cloud.outcome`）照旧是回答。

  确认；要不要把它当取消是取消语义的另一个问题，本轮不改。

### 18.3 T2 循环再规划的步骤也做焦点下发（EN07 r2 / r3）

### 20.4 EN11 取证：长途段的路线算不出被当成 0 km

清单把 EN11（「帮我规划一个周末杭州两日游」→「这个行程全程要补几次电」）记成「行程规划不看能源，能力缺口」。翻 `99178302` 那批的产物：
5 遍里 2 遍第 1 句就带「途中补电 3 次」、第 2 句答「全程需补电 3 次」——行程规划本来就按电量在「当前位置 → 第一站」这一段编补电
（`pipeline.solve`）。没过的 3 遍，卡片里这一段的距离是 **0**（过的那遍是 1238.2 km、补电 3 次），也没有「没读到电量」那句：电量读到了，
是这一段的高德路线请求在业务层失败（HTTP 200、状态非 1；同一请求里几十毫秒一条的市内路线都成功，像是按秒限流），`solve` 的
`route()` 把失败按 0 km 记，方案就静默成了「全程不用补电」；第 2 句 `trip.status` 又只在补电次数大于 0 时才提补电，于是只报了站数。

修（`cd1dd090`）：
- `solve` 里长途段（两端直线超过 50 km）的路线失败退避 1 秒重试一次；仍失败就标 `Leg.route_unknown`（随行程持久化），不当 0 km；
  市内短段照旧按 0 计（只影响按日顺延），不重试、不标；
- 方案话术如实说「去杭州有一段长途路线这会儿没算出来，沿途补电没排全，出发前按实际路线再帮你安排」（与「没读到电量」同一处）；
- `trip.status` 问的是补电时（`[补充].{0,3}电|电够|续航`），零次也说清是哪种零：全程不用补电 / 没读到电量还没排 / 有段路线没算出来、
  补电次数说不准；不问补电的进度问句照旧不多一句。

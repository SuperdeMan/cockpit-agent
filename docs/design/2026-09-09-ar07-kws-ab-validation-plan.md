# AR07：KWS 独立 A/B 实施与验收方案

> 状态：**草案，未实施、未取得新唤醒样本**；日期：2026-09-09。
> 交付对象：端侧语音工程、mobile、QA 与参与说话的测试者。对应 R11 唤醒部分。
> 基线与证据纪律见[接续路线](2026-09-09-android-ar06-ar11-execution-roadmap.md)；历史输入见 [B3 真人读数](2026-09-01-mobile-ux-v2-b3-implementation-plan.md)与 [B5 专项裁决](2026-09-04-mobile-ux-v2-b5-implementation-plan.md)。

## 1. 要解决的问题

在真实麦克风、AEC/NS/AGC 与现有免唤醒回路上，提高“说出小舟小舟后进入可交互状态”的成功率，同时量出误唤醒、重复触发和输入丢帧的代价。先复测当前 A 组，再决定是否调参；旧 5～6/10 不是当前包的基线。

保留原已定门槛 **N≥8/10**。新增分场景、负例时长与选择规则是本方案建议，采样前冻结。达到十次小样本门槛只证明该设备/场景，不证明所有人、所有距离或真实行车环境。

## 2. 代码事实与实验边界

本批固定 VAD 端点、回声文本判据、TTS 播放器与分片、LLM/provider、UI 材质。若发现 dropped 增长、后台撤回失败或原生线程竞态，先独立修复并建立新基线；不要同时降阈值掩盖输入故障。

## 3. 实验装置

### 3.1 同一实验 APK，显式切换单个参数

建议使用 **dev 变体的 release 实验包**：内嵌 bundle、脱离 Metro，与普通 dev-client 分开；复用 `developmentDiagnosticsEnabled()`，只允许屏上手动启动有限时实验。prod 的自动采集门禁不变。

拟给 `KwsEngine.start` 增加受校验的可选参数；默认仍为当前值。实验选项仅驻留本次实验会话，回读实际传入原生的 profile、threshold、score、模型指纹和实验 ID。退出、后台、取消和结束释放本实验的 lease/所有权；不允许 URL 参数自动采集、自动改生产默认或把参数塞进普通用户设置。

正式麦链路实验必须经过现有 `HandsFreeController`。诊断 UI 只选配置、计时和计数，不另建一套 KWS/FSM；引擎直灌在主回路关闭后独立运行。如果为调参必须改原生装置，先构建含全部候选的固定包，再在该包内重取 A/B。

### 3.2 候选与选择规则

| 阶段 | 参数与顺序 | 进入下一阶段的条件 |
|---|---|---|
| A 当前默认 | threshold=0.20、score=2.0 | 在稳定包重新取数，输入无持续掉帧 |
| 探索 B/C | threshold=0.15 / 0.25，score 恒 2.0，其余不变 | 建议候选，仅用来比较灵敏度/误触代价；先确认库实际语义及范围 |
| 正式 A/B | 从探索集选一候选，A/B 或 B/A 交错，结尾 A′ | 不使用探索样本做最终通过分母；A′ 恢复 A 不是重新编一个包 |
| 可选第二轮 | 第一轮不足才固定 threshold、只变 score | 先新建协议版本、明确选值理由；不无限网格搜索到碰巧通过 |

原理与配置可参照 [sherpa-onnx KWS 官方文档](https://k2-fsa.github.io/sherpa/onnx/kws/index.html)，具体默认以仓库原生桥和本轮模型为准。

若 A 已达到门槛且候选没有稳定收益，保留 A 是合法选择。若各档均失败，记录最佳候选和故障层，AR07 不标通过；下一轮应针对已证实瓶颈，不能自动更换模型/移除 AEC。

## 4. 样本协议与指标

### 4.1 每次试验必须记录的条件

OPPO 为主验收；Xiaomi 只在同包同协议条件下对照并单列结果。记录 Android、包 hash、模型/库 hash、物理屏与 App 前台、说话人匿名 ID、距离、方向、房间噪声、外放音量、输入/输出路由、设备温度/省电状态。没有声级计时记录“未校准”，不要编 dBA 数字。

每次开始先回读 ARMED、KWS loaded、mic active、无上轮残留；说话后回到相同状态再进行下一次。手动准备复位不得改变观察到的失败记录。不能因为没有进入 ARMED 就从分母无声删掉，须单列前提失败并解释。

### 4.2 建议样本量

| 集合 | 每臂数量 | 用途 |
|---|---|---|
| 探索集 | 1 位参与者，A/B/C 各 10 次近场正常语速 | 仅筛候选；不参与正式计分 |
| 正式主集 | 1m 正对、安静场景，3 个独立区块 × 10 次；换 A/B 顺序，至少两段测试时段 | 每区块≥8/10，合计≥24/30；按说话人分别列，不用平均掩盖某人失败 |
| 场景集 | 0.3m、2m、侧向/生活噪声、TTS 正在播报，各 10 次 | 建议每个承诺支持的场景≥8/10；不支持的场景须事前确定，不能测后自动划掉 |
| 泛化集 | 另 2 位同意参与者，各 10 次主场景 | 建议每人≥8/10；缺人时标未验，不扩大单人结论 |
| 负例暴露 | 安静、近音/普通对话、外放/TTS，各 20min，每臂共 60min | 记录原始误触和最终进入交互窗的误唤醒；建议后者 0/60min |
| A′ 回归 | 恢复默认后主场景 10 次 | 用于判断时段、疲劳或环境漂移；明显漂移时重开比较轮 |

负例语料包含“小周”“小船”等近音、对旁人讲话、普通播报和助手自己念唤醒词；真实人声与外放素材分列。不要使用未获同意的旁人录音。60 分钟零误触只报告“0/60min”，不宣称真实 FAR 为零或已达到量产统计置信度。

### 4.3 逐次判定

每条同时记 `keyword_detected`、`fsm_entered_listening`、`valid_command_final`、`duplicate_hits`、`mic_frames`、`processed/dropped/queued_delta` 与时间点。

- 唤醒成功：预设观察窗内（建议唤醒词结束后 2s）进入正确交互态；观察窗采样前锁定。
- 引擎命中但 FSM 拒绝：单列原因；不能全部计为成功或全部误唤醒。
- 命中后 ASR 无正确内容：唤醒与后续命令分栏，避免 KWS 用 ASR 失败背账或反向借绿。
- 误唤醒：没有对助手的唤醒意图却进入交互窗；FSM 已拦住的自触发只计原生候选事件。
- false accepts/hour 按实际负例暴露时长计算，不能用正例次数作分母。
- 推荐唤醒反应 p50≤1s、p95≤2s；输入积压/掉帧须报告峰值与时序，持续积压使该轮不能用于阈值归因。

## 5. 最终参数如何进入生产

探索配置与生产默认分开。选定参数后构建一份固定 prod release，回读实际值，并重跑正式主集、60min 负例和核心场景；实验包通过不转借给 prod。

当前架构明确“同模型同阈值”。若确有证据支持手机的 VoiceCommunication 路径使用不同参数，实施者需提出一次范围明确的决策：将 KWS 默认与经验证的声学 profile 放到一份共享配置源（例如拟新增 `hmi/src/kwsProfiles.mjs` 并登记 shared allowlist），按**明确声学路径**选 profile；HMI 保留原已验证档。同步修订架构/约定中的旧承诺，补两端默认与未知 profile 回落测试。不得悄悄只改 mobile 常量或把手机数据作为 HMI 调参依据。

若用户不采用分 profile 方案，保持当前生产默认，交付实验结论；不能以此宣布未落地的改善已交付。

## 6. 实施步骤与验收

| 步骤/ID | 产物 | 完成条件 |
|---|---|---|
| A07-0 | 包/模型/声学路径清单、冻结协议 | 不引用旧唤醒率作为新 A；所需参与者/设备条件明确 |
| A07-1 | 有限时实验入口、只读计数、参数回读 | 单例所有权、取消/后台撤回与默认行为不回归 |
| A07-2 | A/B/C 探索原始表 | 所有失败保留，只选一主要变量 |
| A07-3 | 正式 A/B/A′、负例及泛化表 | 达到事前门槛；原始计数与结论可重算 |
| A07-4 | 参数决策与必要共享契约修订 | 声学条件与适用范围有依据，HMI 不被未验证调参 |
| A07-5 | prod 固定包验收与 armed 材料 | 主集/负例/关键场景通过，AR02 采集边界仍成立 |

本地验证沿用 `kwsOwnership`、`micBus`、`handsFree`、`diagnosticRoutes` 相关测试及 mobile tsc/Jest；新增测试只覆盖参数校验、生效与生命周期边界。涉及共享配置时补 HMI 检查；涉及原生 bridge 则重建并检查模块注册。统计解析器用已知命中/漏检/误触的人工小表校验分母，不能只测试全成功表。

真实验收还必须证：ARMED 未唤醒音频不上云、关闭/后台释放本实验资源、候选切换不留下旧 worker/回调、播报中仍能只停播且不误触业务。捕获原始音频若为诊断所必需，单独明确参与者同意与本轮留存方式，不成为常态日志。

## 7. Goal 文本与交接

执行方式以[工程交付与集中验收安排](2026-09-10-android-goal-delivery-and-acceptance-plan.md)为准。下面两种目标在启动时选择；默认采用工程交付目标，本文完整验收矩阵仍保留。

### 工程交付 Goal（默认）

> 按 AR07 方案完成工程交付：冻结当前默认与实验协议，落地可回读的单变量实验入口、真实主麦/FSM 计数、参数与所有权回归、统计器和测试材料；具备设备、授权及有效素材时继续执行所有可自动完成的实验。真人基线/泛化集中安排，输入缺席时不拍脑袋修改生产默认，转而推进 AR08/AR09 等独立工作。交付可直接取样的候选与逐项证据，缺少真人数据的调参改善仍标待决，不能写已提高唤醒率。

### 完整验收 Goal（另行启动）

> 按 AR07 方案接手 KWS 专项，先冻结当前包、模型和真实声学路径，完成可回读的单变量实验装置与本地回归，再完成真人 A/B/A′、误唤醒和场景验证，选择有证据的参数并在 prod 固定包复验。保留原 N≥8/10 门槛，所有失败与原始分母入账；需要手机独立声学 profile 时先按方案修订共享配置契约。真人或设备条件缺席时继续完成独立工程工作，保留未验，不用直灌结果或旧样本签收。

追加记录：采用协议、参与者匿名 ID、实际 A/B 顺序、参数/模型指纹、每场景命中/误触/时长、排除及污染样本、prod 证据、是否调整架构、当前未通过项。向 AR08 交付选定声学路径；向 AR10 交付 armed 状态材料与实际支持范围。

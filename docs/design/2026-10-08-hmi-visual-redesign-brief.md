## 0. 一页速读

**结论**：现在的 HMI 是一个「桌面网页尺度的聊天应用」，外面套了一层液态玻璃和极光。品牌内核值得保留：小舟光球、极光只给 AI 时刻、深空色、交互蓝、A 股红涨绿跌、「气泡给结论、卡片给证据」。但尺度、材质层级、信息布局、设计源这四件事要重做。

**五个主要问题**（证据见 §2）：

1. **不是车机尺度**。
   - Figma 原稿 A-1–A-7 是 Make 预览在 1422 宽浏览器里截下的网页，A-7 只有 1063×719。正文 13–15px，元信息 10–11px，A-3 还有 8–9.5px 的字。
   - 代码照搬：组件里有 384 处字号字面量、30 种取值；11px 出现 80 次，≤10.5px 57 次。设置控件高 27–38px。
   - 对照 Android for Cars 设计规范（主要文字 32dp、次要文字 24dp、触控目标 76dp），差 2–3 倍。
2. **材质层级没成立**。
   - 契约的前提是「玻璃折射背后活的场景」。实际舞台是右边一个框，左栏背后只有装饰光斑。
   - 面板 → 气泡 → 卡片 → 格子，四层 `backdrop-filter` 叠在一起。实测卡身底色被抬到 `#434651`：A 股红字只有 2.50:1（卡片头部高光区 2.05），次要文字 4.23:1。
   - 浅色主题没有覆盖语义色：琥珀 1.9、绿 2.0、交互蓝 3.2–3.6、次要文字 4.1–4.25（判据 4.5）。
3. **焦点与稀缺性失控**。
   - 欢迎态同屏 5 颗光球同时跑循环（状态栏、对话头、欢迎、待机舞台、输入区），每条助手消息再挂一颗。
   - 极光发送键是屏上最饱和的常驻元素。
   - 天气和日程舞台的「边缘极光」CSS 写法有误，实际把极光铺满整块舞台，还盖在文字上面。原稿 A-2 的紫色舞台就是这个 bug 被截了下来。
4. **设计源已经失效**。
   - 原 Figma 文件 8 页：A-1–A-7 各是一张截图式长帧，没有组件、变量和样式；只有 A-8 的 55 个图标是组件。
   - 34 个卡型里只有 11 个有原稿；设置里后加的 5 组控件、结果折叠、车况投影、日程舞台都是「代码有、Figma 无」。
   - 行车态从未出帧。
5. **实现漂移，还有几处在断言自己不知道的车况**。
   - 三套卡片容器并存：`.card` 21 个视图、`.au-glass` 4 个、`.au-card` 7 个。`.au-card` 在所有 CSS 里都没有定义。
   - 对话区常驻「泊车模式 · 已停车」，确认条常驻「当前 已泊车」，都是写死的。
   - 续航按「电量 × 550km」估算，界面不标「估算」。
   - 「开始导航」按钮默认没有点击行为；「大字」「大触控」开关基本无效。
   - 设置里漏出模型 id、延迟毫秒数、README 指引和 Figma 帧名。

**目标**：车机尺度、舞台为底、一屏一颗光球、深浅同权、行车态是一等布局、状态全覆盖。Figma 里每个视觉值都绑定变量，与代码 token 一一对应。

**推荐方向**：B「零层级舞台」（§4）。
- 舞台全幅铺底；对话改为悬浮在左侧的一块玻璃面板，行车时收成一条结论条。
- 这其实是回到契约自己的三层模型：活场景 → 玻璃面板 → 悬浮控件。
- 品牌层不变；结构层与 Android v3 已定的决定对齐：一屏一球、助手去气泡、极光收到四处。

**不变的东西**（§3.2）：WS 状态机与消息语义、`types.ts`、安全红线、「确认只投影服务端判据」、光球造型不变量。会动交互的三处单列在 §15 等你拍板：待确认条的位置、开发者信息默认隐藏、行车时收起文本输入。

**Figma 侧前提**：2026-10-08 跑 `whoami`，账号是 Professional + Full 座席，可以写画布，读调用每天 200 次。原文件里没有任何变量、样式或卡片组件可以复用。

## 1. 产品与使用情境

### 1.1 HMI 同时扮演三个角色

| 角色 | 谁在看 | 要什么 | 现状 |
|---|---|---|---|
| 车机中控 | 驾驶员（只能瞥一眼）、副驾 | 一眼可读的结论、大目标、低眩光 | 尺度与密度按桌面网页做 |
| 演示前端 | 投屏观众、评审 | 看得懂 AI 在做什么：过程、证据、联动 | 做得最多：过程区、证据卡、舞台联动 |
| 开发调试台 | 你自己排查 badcase | trace id、模型 id、原始错误 | 和产品界面混在一起常驻显示 |

重构后，产品界面只服务前两个角色，调试信息收进「开发者模式」（§15-6）。

### 1.2 目标屏与视距（尺度从哪来）

- 基准画布 1920×1080 横屏。按 15 英寸级中控屏（1920×1080 / 1920×1200）、视距约 700mm 估算，1px ≈ 0.17–0.18mm。
- 按这个几何关系换算：24px 的中文字身高约 3.9mm，视角约 19 角分；11px 约 1.8mm，视角约 9 角分。（数值是本文按几何算的，不是标准原文。）
- [Android for Cars 设计规范](https://developers.google.com/cars/design/design-foundations/visual-principles)：主要文字 32dp，次要文字 24dp；[触控目标](https://developers.google.com/cars/design/automotive-os/design-system/sizing)不小于 76×76dp。车机常见密度下 1dp ≈ 1px。（该规范 2026-03 起迁到合作方站点，公开页可能不是最新版。）
- 在桌面显示器上演示时，车机尺度的画面会显得偏大，可以用浏览器缩放；反过来，桌面尺度放到车机上就读不清。所以尺度按车机定。

### 1.3 与 Android「小舟随行」的关系

- **品牌同源**：光球、极光四色、交互蓝、深空底、24 格 1.8 描边线性图标、A 股红涨绿跌、置信度三色。
- **照用 Android v3 已落地的结构决定**：
  - 一屏一颗光球；
  - 助手回答去气泡；
  - 极光只留给 AI 时刻，发送键改交互蓝；
  - 字阶按角色定义，数字用表格数字；
  - 数据色做成 token。
- **不照搬的**：Android 放弃真模糊，是因为 React Native 没有 `backdrop-filter`。HMI 是网页，背后有舞台可透，所以保留**一层**真玻璃，但不许玻璃叠玻璃。
- 两端仍然不共享 UI 组件，只共享图标数据和纯逻辑（`mobile/shared-allowlist.json`）。

## 2. 现状诊断

### 2.1 已经做对、必须保留的

- **消息状态机与契约**：`App.tsx:334-622` 的 `handleEvent`（流式 / 过程 / 动作 / final / 主动 / 错误 / 取消），按 `request_id` 归属，每轮一个看门狗，待确认按 `operation_id` 台账化。视觉重构不碰。
- **三段叙事**：思考中 → 过程区 → 流式 / 最终（`ChatView.tsx:353-497`）。过程区分理解、规划、执行、整理四阶段，完成后折叠成「处理过程（N 步）」，行车时只显示一行。
- **证据范式**：
  - 气泡给结论（会被朗读），卡片给来源、时效、置信度；
  - 置信度说人话：高 / 中 / 未充分核实（`Cards.tsx:103-117`）；
  - `_prov` 徽章：模拟数据醒目标出，降级和缓存用灰标，真实数据只写来源与时间（`Cards.tsx:199-213`）。
- **舞台联动**：左侧卡片的编号与地图舞台的点位一一对应，支撑「第 N 个」语音选择（`ContextualStage.tsx:233-260`）。
- **确认语义**：确认条只由服务端 `need_confirm` 加上仍然有效的挂起来驱动，可以同时有多条。卡内动作只合成一句话、走普通上行，写确认只在全局确认条上产生（`types.ts:90-96`）。
- **图标注册表与 A-8 规格**：24 格、1.8 描边、四种状态（含 aiMoment 极光描边）、六档尺寸（`Icon.tsx`）。
- **降级路径**：`prefers-reduced-motion` 时循环动效归零；不支持 `backdrop-filter` 时回落实色（`aurora.css:157-160,266-272`）。
- **可截图的夹具**：`?demo=…`、`?settings`、`?theme=`、`?aurora`、`?icons`（`main.tsx`）。

### 2.2 问题（按影响排序，附证据）

**H1 尺度：桌面网页的密度放在车机屏上**

- Figma 原稿的帧宽：A-1 1422、A-2 1440×776、A-3 1432、A-4–A-6 1422、A-7 1063×719。都是浏览器截取，没有一张是 1920×1080 画板。
- 原稿文字字号分布（用 `use_figma` 统计全部文本节点）：
  - A-1：10px 64 个、10.5px 82 个、11px 54 个、11.5px 67 个；大于 16px 的只有 19 个；
  - A-3：8px 14 个、9px 25 个、9.5px 13 个；A-4 有 9px 和 9.4px。
- 代码（`hmi/src/components/**`）：
  - 字号字面量 384 处、30 种取值；11px 80 次、10.5px 38 次、10px 15 次、9.5px 3 次、9px 1 次；
  - 卡片最小字号多为 10px，调研卡是 9px。
- 控件尺寸（`controls.tsx`）：
  - 开关 48×28、分段约 33、输入框 38、幽灵按钮约 33、危险按钮约 36；
  - 「试听」约 24、「更多 N 条」约 24、行程「导航」约 21；
  - 只有确认按钮到了 50。
- 契约的字阶本身就是桌面级：Body 15、Caption 12、Mono·SM 14（契约 §7）。

**H2 材质与层级：玻璃背后没有「活的场景」，还层层叠玻璃**

- 舞台是右栏一个带边框的盒子（`shell.css:126-134`）。主区是两栏：`minmax(430px, 43%) 1fr`（`shell.css:81-89`）。
- 左栏背后只有三团模糊光斑（`shell.css:21-36`）。契约 §2 要求的「Layer 0 活场景」在左栏并不存在，玻璃折射的只是装饰。
- 嵌套：对话面板（blur 32）→ 助手气泡（blur 20，`ChatView.tsx:237-243`）→ 卡片（blur 32，`cards.css:8-18`）→ 天气格子（再加一层底）。用户气泡也有 blur 16。
- 实测后果（headless Edge，`?demo` 天气）：
  - 卡身实际底色 `#434651`，卡片头部的高光区 `#4A5368`，格子 `#4D515D`；
  - 卡身上：次要文字 4.23:1、弱文字 2.42:1、红色（涨 / 危险）2.50:1、琥珀 4.38:1、置信低灰 1.94:1；
  - 头部高光区更差：次要文字 3.67:1、红色 2.05:1；
  - 股票卡的红色价格就压在这层上。
- 性能：每个气泡、卡片、用户气泡、舞台芯片都开了 `backdrop-filter`，还叠着 5 颗光球，每颗 7 层、多层带 `filter: blur`。在车机芯片上这是 GPU 大户。契约 §6 写了「行车降级」，但 `data-drive` 从来没被设置（见 H8）。

**H3 极光与光球：AI 时刻不再稀缺**

- 欢迎态有 5 颗光球同时在跑：
  - 状态栏 30px（`StatusBar.tsx:30`）；
  - 对话头 36px（`ChatView.tsx:88`）；
  - 欢迎 96px（`ChatView.tsx:118`）；
  - 待机舞台 120px（`ContextualStage.tsx:69`）；
  - 输入区 40px（`Composer.tsx:174`）。
- 每条助手消息还会挂一颗 30px 头像（`ChatView.tsx:235`）。这么多颗里只有输入区那颗能点。
- 发送键用极光填充、带蓝紫外发光（`shell.css:182-190`），是屏上最饱和的常驻元素。
- **舞台「边缘极光」是 bug**：
  - `ContextualStage.tsx:127` 和 `:383` 用 `background: … padding-box, var(--au-aurora) border-box` 想画一条 1.5px 描边；
  - 但第二层背景按 border-box 铺满了整块，结果是 20–48% 透明度的极光盖在整个舞台上，`zIndex: 6`，压在温度数字上面；
  - 原稿 A-2 的紫粉色舞台和淡紫色的「28」就是这个 bug 被截进了 Figma。它同时违反了契约 §5 的两条禁令：「玻璃面板背景使用彩虹渐变」和「关键数字使用虹彩」。
- 原稿 A-1 §03 的示例把「预计抵达约 23 分钟」里的数字做成了极光字，也违反契约自己的禁令。
- 几乎每张信息卡都打「AI · X」极光角标：搜索、新闻、POI、路线、充电、行程、赛事。搜索结果和地点列表来自外部，不是 AI 生成的内容；角标到处都是，「AI 时刻」就失去了信号意义。

**H4 颜色与对比度**

- 契约标称值与实测不符：
  - 弱文字（0.32 白）标称「≥3.0:1」，在 `#06080F` 上只有 2.78；
  - 浅色次要文字（0.55 墨）标称「≥4.5」，实测 4.13。
- 浅色主题只改了交互蓝（`#0A8FCC`，对比度 3.2–3.6）。琥珀、红、绿、在线、置信高都沿用深色值（`aurora.css:95-120`），在浅色底上分别只有：琥珀 1.9–2.1、绿 2.0–2.3、在线 1.7–1.9、置信高 1.6–1.7。
- 深色主题：
  - 「置信度 未充分核实」用 `#6B7280` 灰字，在卡身上 1.94:1；
  - AQI「严重」的紫色 `#9333EA` 当文字色用时 1.86:1。

## 3. 目标、不变量与非目标

### 3.1 目标

- **G1 车机尺度**：以 1920×1080、视距约 700mm 为基准。
  - 泊车：正文 ≥24px，最小字号 20px，触控目标 ≥64px；
  - 行车：正文 ≥28px，最小字号 24px，触控目标 ≥76px；
  - 确认按钮在两种状态下都 ≥76px。
- **G2 舞台为底**：舞台全幅铺底，是屏上唯一大面积「活」的画面；对话面板是悬浮在它上面的一层玻璃。
- **G3 品牌更稀缺**：一屏一颗光球；极光只在四处出现（§5 P3）。
- **G4 深浅同权**：每个组件、每屏都有深浅两版，两版都过对比度判据。
- **G5 行车是一等布局**：不是泊车布局的缩放，有自己的版式和组件形态。
- **G6 状态全覆盖**：对话动态 × 卡片状态 × 舞台场景 × 连接 / 确认 / 主动 / 降级，每种组合都有帧或组件变体。
- **G7 可维护的设计源**：颜色、字号、间距、圆角、尺寸全部绑定 Figma 变量；变量的 WEB code syntax 填 CSS 变量名，与代码一一对应。
- **G8 性能预算**：同屏常态只有一个循环动画（光球）；一条视线路径上最多一层模糊。

### 3.2 不变量（本次不重开）

- **消息与状态机语义**：`handleEvent` 的分发、`request_id` 归属、看门狗、「第 N 个」路由、过程区四阶段、确认台账（`App.tsx`）。
- **数据契约**：`hmi/src/types.ts` 不增删字段。设计稿需要新字段，单独走契约流程。
- **安全红线**（`CLAUDE.md` §5）：
  - 车控只经 VAL；
  - 危险动作二次确认，风险档和截止时间只来自服务端；
  - UI 不写车速阈值这类第二份判据；
  - 车控入口只能是「发一句话」，不画成直接拨车身的开关。
- **光球造型不变量**：正圆；七层及其顺序；四色固定顺序；说话波纹用交互蓝；呼吸加反向双漩涡；各状态的含义；`prefers-reduced-motion` 时静帧。
- **共享边界**：两端只共享图标数据和纯逻辑，不共享 UI 组件。

### 3.3 非目标

- 不写代码。实施计划在设计定稿后另立。
- 不做 Dashboard。它仍是旧的 HUD 皮，等 HMI 的 Foundations 定下来再立项。
- 不改 Android。
- 不接真实地图 SDK。设计给出「真实取景」的样式和「示意图」的回落规则，SDK 接入是实施期的事。
- 1920×720 等其它屏幕只写自适应规则，不出帧。

## 4. 设计方向

| | A 保留两栏，只修系统 | **B 零层级舞台（推荐）** | C 全新视觉 |
|---|---|---|---|
| 版式 | 左对话框 + 右舞台框不变 | 舞台全幅铺底；对话悬浮在左侧，行车时收成结论条 | 重新定义 |
| 玻璃是否成立 | 仍是「框里透框」 | 成立：面板透出的就是舞台 | — |
| 行车一等布局 | 要另做一套 | 面板收起就是，结构上自然成立 | — |
| 与 Android v3 一致 | 部分 | 高：同一组结构决定 | 低 |
| 演示可读性 | 好：对话常驻 | 好：泊车时面板默认展开 | 不确定 |
| 工作量 / 风险 | 小 / 小 | 中 / 中：舞台要补场景和取景安全区 | 大 / 大 |

**推荐 B 的理由**：

- 问题出在结构层（尺度、层级、焦点、设计源）。A 只修数值，修不到「玻璃背后没东西」「舞台被框住」「行车没有布局」这三件事。
- B 就是契约原本的三层模型：Layer 0 活场景、Layer 1 玻璃面板、Layer 2 悬浮控件。现在的实现把 Layer 0 做成了右栏里的一个框。
- 主流座舱都是「地图或场景为底、内容浮在上面」，比如特斯拉的常驻地图、奔驰 MBUX 的零层级。小舟的差异化在光球和证据，不在两栏框。
- 泊车时面板默认展开，演示照样能看到完整的对话与过程；行车时面板收起，舞台让给地图。

**B 的具体主张**：

1. **舞台全幅铺底（Layer 0）**。
   - 地图、天气、车况、日程、阅读、支付等场景占满 1920×1080；
   - 主要内容落在面板右侧的「安全区」；
   - 面板背后恒有一层 scrim，地图取景避开面板。
2. **只有一层玻璃（Layer 1）**。
   - 对话面板、状态栏、舞台浮签是玻璃；
   - 面板内部（回答块、卡片、格子）一律用不透明的色调分层，不再叠模糊。
3. **悬浮层用实色（Layer 2）**。待确认条、错误、隐私提示、设置覆盖层、地图上的信息条，都用 G0 实色（不透明度 ≥0.96）。
4. **一屏一颗光球**。
   - 常驻在面板底部输入行的最左侧，它就是麦克风；
   - 状态栏改成字标加状态点；
   - 去掉对话头、消息头像和待机舞台上的光球。
5. **助手回答去气泡**。
   - 用户消息保留右侧的色调气泡；
   - 助手回答是全宽的正文块，卡片是一等内容块；
   - 确认、错误、主动消息用左侧色条加标签区分。
6. **卡片与舞台分工**。
   - 回答区给结论与证据，保持紧凑；
   - 舞台给空间与大图：地图、天气场景、K 线大图、手册原图、付款码；
   - 同屏同一个数值只出现一次（朗读文本除外）。
7. **极光收到四处**：光球、聆听 / 思考时的屏幕边缘、流式光标、AI 生成内容的描边或角标。发送键改用交互蓝实色。
8. **车机字阶与两档触控**。
   - Size 变量分四个模式：泊车 / 行车 × 标准 / 大字；
   - 代码用 `data-drive` 和 `data-font` 切换 CSS 变量。现在代码缺字阶变量，正好借此补上。

|---|---|---|
| P1 | 一眼可读 | 行车时结论一句话、≤2 行、字号 ≥32；每屏最大字号给结论或主数值 |

### 7.3 舞台场景

| 场景 | 何时出现 | 数据来源 | 内容 | 行车时 |

### 8.2 颜色起点值（已按实际底色核算，M2 定稿）

**关键发现**：玻璃面板的对比度取决于它背后是什么。

- 按 `Space-900 @0.76` 的深色面板算：背后是深空底时，下表全部过线；
- 但背后正好有一条交互蓝路线时，红字只有 2.77。
- 所以要两手并用：面板背后加 scrim、地图取景避开面板；彩色文字只出现在色调面和实色面上。

| 角色 | 深色 | 浅色 | 常态背景下各 surface 的最小对比度（深 / 浅） |
|---|---|---|---|
| 面板材质 | Space-900 @0.76 + blur 40 + 顶缘 1px 高光 | 白 @0.84 + blur 40 | — |
| surface 1 / 2（卡片 / 格子） | 面板上叠白 6% / 10% | 面板上叠墨 4% / 7% | — |
| text-1 | 白 .94 | 墨 .92 | 13.5 / 13.8 |
| text-2 | 白 .70（原 .56） | 墨 .66（原 .55） | 8.1 / 5.9 |
| text-3（只用于禁用 / 占位） | 白 .50（原 .32） | 墨 .48（原 .30） | 4.9 / 3.3 |
| 交互蓝 | `#46D6E0` | `#0369A1`（原 `#0A8FCC`） | 8.6 / 5.0 |
| 涨 / 危险 | `#F26464`（原 `#EF4444`） | `#C62828` | 4.9 / 4.8 |
| 跌 / 成功 | `#2BD46E` | `#166534`（`#1A7F37` 在格子上只有 4.3） | 7.7 / 6.0 |
| 警告 | `#F5A524` | 文字 `#92400E`、填充 `#D97706` | 7.4 / 6.0 |
| 置信低 | `#9CA3AF`（原 `#6B7280`） | `#4B5563` | 6.0 / 6.4 |
| AQI 与其它数据色 | 只做色块、线、形状；文字用 text-1 / text-2 | 同左 | — |

核算脚本按「面板叠在舞台上、卡片叠在面板上」逐层合成颜色后计算 WCAG 对比度；M2 把它整理成 02 页的对比度表，实现期再补 HMI 自己的对比度测试（对标 `mobile/test/theme.test.ts`）。

### 8.4 尺寸、间距、圆角、材质与动效

- **触控**：泊车按钮 64；芯片视觉高 48、热区 64；图标按钮 64；行车按钮和确认按钮 76。
- **间距**：4 基准，取 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64。
- **圆角**：面板 32、卡片 24、格子与控件 16、标签 8、胶囊与光球 full。
- **材质三档**：
  - M0 实色：确认、错误、隐私、地图浮签、设置覆盖层，不透明度 ≥0.96；
  - M1 玻璃：面板、状态栏、舞台浮签，只有一层；
  - M2 AI 反应面：光球、边缘光、AI 内容描边；
  - 行车时 M1 的不透明度升到 ≥0.88，模糊降到 24。
- **效果样式**：`elevation/1–3`、`glow/orb`、`scrim/stage-left`、`scrim/modal`。
- **动效**：
  - 光球节律沿用契约 §10；
  - 界面转场取 120 / 200 / 320ms，标准缓动，只动 transform 和 opacity；
  - 面板展开 / 收起 ≤300ms；
  - 同屏常态只有光球在循环；减少动效时一律静帧。

### 8.5 对比度判据

- 正文、次要文字压在 bg、面板和每一级 surface 上 ≥4.5:1；弱文字与图形 ≥3:1；状态色文字压在各自的软底上 ≥4.5:1。
- 背景按两种情形核算：常态，以及舞台最亮的内容正好在面板背后（以 scrim 之后的亮度为准）。
- 光球与浅色底的亮度差 ≥40/255。

## 10. 自适应与行车

- 基准 1920×1080。1920×1200 多出来的高度给舞台和回答区，不放大字号。

## 11. 无障碍

- 对比度：见 §8.5。
- 触控目标：泊车 ≥64，行车与确认 ≥76。
- 最小字号：泊车 20，行车 24。
- 大字档：文字 ×1.15，触控 ×1.1；在大字档下布局不溢出、不截断关键信息。
- 减少动效：每个动效都有静帧版。
- 减少透明度：不支持或关掉 `backdrop-filter` 时，真正改成不透明，并且仍然可读。
- 纯图标按钮：设计稿标注读屏名称。
- 不以颜色作为唯一的信息载体：涨跌加 ▲▼，置信度用文字，档位写名称。
- 所有可点区域都有按下态。

## 12. 技术边界（设计必须能落地）

- **技术栈**：React 18 + TS + Vite 5；全局 CSS + inline style + `--au-*`。没有 Tailwind、shadcn、lucide、MUI、motion，落稿时也不得引入。
- **模糊**：`backdrop-filter` 可用。舞台全幅铺底之后，面板模糊的成本取决于背后的动画（雨丝、地图动画），所以舞台动画要克制，面板背后的区域降帧或静止。
- **渐变**：线性、径向、锥形（conic）都可用；光球依赖 conic。
- **地图**：PoC 没有地图 SDK，舞台地图由 SVG 绘制。设计给「真实取景」样式和「示意」回落两套规格。
- **字体**：当前走 Google Fonts，大陆网络可能回落系统字体（§15-7）。
- **数据**：只能用 `types.ts` 里的字段和 WS 帧里已有的信息；车况读 `vehicleObservation.mjs` 的投影（含质量与来源）。
- **Figma 端**：`use_figma` 不能导入图片（截图走 `upload_assets`）、不支持自定义字体（Google 字体可用）、单次返回不超过 20KB、调用必须串行；其它坑见落稿规则 §8.5。

## 15. 需要你拍板的决定

1. **方向**：B 零层级舞台（推荐）/ A 保留两栏只修系统 / C 全新视觉。
2. **尺度**：按车机尺度（§8.3、§8.4，推荐）/ 维持桌面网页尺度。前者在桌面显示器上演示会显得偏大，可以用浏览器缩放。
3. **与 Android v3 对齐的结构决定**（推荐全部采用）：
   - 一屏一颗光球，常驻在输入区；
   - 助手回答去气泡；
   - 发送键改交互蓝，极光收到四处。这一条会改动契约 §5「主操作按钮可用极光」。
4. **待确认条**（推荐采用）：
   - 从消息流里的确认气泡，改为面板底部的固定条；一次钉一条，其余显示「另有 N 个」。语义不变，只是位置变；
   - 同时删掉「当前 已泊车」这类车况断言。实施时要改 `merchantUi.mjs` 和锁住这句的两条测试。
5. **行车态**（推荐）：
   - 判据照搬 Android：Edge 的 `driving` 加手动切换，退出宽限 30 秒；
   - 行车时隐藏文本输入和建议指令，舞台锁定地图；
   - 需要一个手动入口：状态栏的「行车中」标识可以点击退出本段，设置里也放一个手动开关。
6. **开发者信息默认隐藏**（推荐）：在设置里打开「开发者模式」或带 `?dev` 时才显示。范围包括 trace 角标、模型 id、延迟与健康点、原始错误、VAD 参数。
7. **字体**：
   - 中文用系统字体栈（车机系统自带的 HarmonyOS Sans / MiSans / PingFang），Inter 和 JetBrains Mono 自托管（推荐）；
   - 或继续用 Google Fonts；
   - 或全部自托管（Noto Sans SC 体积大）。
   - 不论选哪种，设计稿都统一用 Noto Sans SC + Inter + JetBrains Mono。
8. **Figma 组织与节奏**：
   - 新建文件，原文件只读归档（推荐）；
   - 检查点①必须你确认；②–⑥ 照 Android 的做法不阻塞，截图照出、事后复核（推荐）。也可以每个检查点都等你。
9. **范围**：
   - HMI 全量：泊车、舞台、34 个卡型、行车、设置、深浅、无障碍变体；Dashboard 不做；1920×720 只写规则（推荐）；

## 1. 测量（只读）

云上导航容器（真实高德 + 模型网关），深圳南山出发，50 个本地具名地点 + 10 个连锁店：

- 现行解析约一半落到附属地点或错处：停车场（海岸城 / 欢乐谷 / 莲花山公园 / 仙湖植物园）、观光层（平安金融中心）、
  景区里的一个点（世界之窗→巴西基督山）、推拿店（大梅沙）、公安局（蛇口港）、食堂（东门）、邮政所（福田口岸）、小区（前海 / 梧桐山）；
  「会展中心」一次解析到北京国家会议中心 1952 km，「山姆会员店」「7-11」解析到北京。
- 原因一：近处搜索用的是高德周边搜索缺省参数——半径 5 km、按距离排。5 km 内借了名的店天然排第一、名字包含式校验放行；
  真身在 5 km 外（大梅沙 38 km）根本不在候选里。
- 原因二：名字对不上时直接去全国重搜和模型地标兜底，「会展中心」这类通名的全国第一在别的城市。
- 同一批用高德综合排序（`sortrule=weight`、半径 50 km）约 45/50 正确，连锁店仍选最近的分店。

## 2. 判据

- 具名目的地（不是类目、不是「最近 / 附近」）的近处搜索改用综合排序 + 城市级半径（50 km，高德上限）；类目与就近查询要的正是最近的那个，保持按距离。
- 名字校验不过时先在当前城市里按名字找（城市取近处结果里最近那个的所在城市），再走全国重搜（外地地标的救济路径不变）；拿不到城市就跳过这一步。
- 名字校验的反方向收紧：地点名比原话短时只认原话以它打头（「南京南站高铁站」之于「南京南站」），或原话 = 该地点所在城市 + 它的名字
  （「上海外滩」之于上海的「外滩」）。地点名只是原话的尾巴不算——「火车站」之于「厦门火车站」缺的正是最有区分度的「厦门」。
- 借名歧义里「去掉城市前缀后完全同名就不再问」只限城市级半径内：城市搜索才找到的、更远的同名（「深圳鼓浪屿」58 km）仍要看外地有没有本体。
- 规划器把起点写成「当前位置 / 这里 / 我的位置」这类占位时就是没给起点（判据 `runtime.slots.is_place_placeholder`，与天气城市槽同一份）：
  2026-10-04 真栈里估算拿「当前位置」四个字去搜，搜到一个停车场入口当起点，还因此跳过了续航提醒。

## 4. 实现

- 提供方：`POIProvider.search` 增加可选 `rank` / `radius_m` / `region`（缺省行为不变）；高德周边搜索带 `sortrule=weight` 与 `radius`，关键字搜索带 `region` + `city_limit`。
- 导航：`_find_destination` 的具名分支、`_named_hit`（重搜结果取舍，原锚词双匹配逻辑原样搬入）、`_nearest_city`、`_dest_matches(query, name, city)`、
  `_far_namesake` 同名免问限城市级半径、`_origin_text`（起点占位值）；模型地标兜底的候选先在城市范围里按名字找，
  只认严格对上且在本地半径内的结果（「山姆会员店」→ 模型给「山姆会员商店」，全国第一是北京石景山店）。
- 测试：具名走综合排序与城市半径、类目与就近不变、名字对不上先本城再全国、拿不到城市跳过、当前城市取最近结果、高德参数拼装、
  反向包含收紧、城市搜索的远处同名仍查外地、起点占位值按当前位置算、模型兜底候选城市内优先且模糊相近的本地小点不算；
  `test_person_destination` 的「外滩」夹具补上城市（真实高德结果都带）。变异 18 处全部判红。

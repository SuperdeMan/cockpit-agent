**AR01｜确认与取消。交付结果：用户点的是哪项，系统只处理哪项；未发出的请求取消后不会再发送。**

输入为 R03、R04、R05 和 原评审 R03/R04 记录的三个本地反例。主要范围是 mobile 的 SessionCore、发送装配、FocusDock、ChatScreen，以及需要时的共享 ResilientWebSocket。共享 WS 若需要变更，应在共享源修复并验证 HMI 消费方，不在 mobile 另养一份队列算法。

实施重点：将本地位置授权与带 operationId 的确认分开；为等待定位/视觉、排队、已发送、终态定义同一请求身份与取消边界；UI queued 与真实传输队列对账；为“其它待处理”提供列表和明确对象。

验收至少覆盖：

- 两个危险操作与一个位置征询同时存在，分别确认/取消，逐个检查 operationId、位置权限调用和剩余台账。
- 等定位时取消、离线排队时取消、连续两轮只取消一轮、恢复网络后逐帧检查，原请求不复活。
- 已发送请求的取消不能被表示为“已回滚”，依据服务端真实取消/执行终态显示。
- 三项待办可直接操作最后一项，到期/重排过程中不能换对象。
- 相关 SessionCore/路由/Dock 行为回归；涉及共享 WS 时补对应共享测试与 HMI 检查。

本批结束只关闭 R03/R04/R05 已证明的部分；视觉底层中止和文件生命周期在 AR02 继续验证。

2026-09-07 回填：最终代码 `f4647d0fb87bf2928fa26e12151cd8ace0b14e25`，mobile 57 suites / 574 tests 与 TypeScript 通过；prod release 已装 OPPO test，列表样本展开/滚动/按钮/关闭验证完成。HMI 304/304 的证据锚为共享修复提交 `ead802e`，其后 HMI 源码无差异。客户端缺陷已修并合入 main，真实业务多操作 E2E 未执行；APK 身份、构建提示、取证限制及集成/部署边界见[AR01 实施记录](2026-09-07-ar01-confirmation-cancellation-implementation.md)。

**AR02｜采集与隐私。交付结果：所有入口都守同一采集边界，屏上状态与实际一致。**

输入为 R01/R02/R07。范围是诊断路由、VisionCapture/frame、micBus/语音控制器的事实出口、Presence/PrivacyRail。KWS 模型与阈值、ASR/TTS 选型保持固定，便于后续声学比较。

先关闭 prod 深链自动录音和自动切播放器的入口；开发诊断与只读诊断分开。视觉方案必须满足现有“零落盘”约束，不能只加 base64 就认为实现了内存路径；若选临时缓存方案，必须把这项约束变化单独写清并由用户决定。采集指示直接读物理设备、上行通道事实，不能由“思考/播报”倒推出麦克风关闭。关闭能力要作废正在等待权限、拍摄、上传和发送的回调。

**AR03｜停播与横屏操作。交付结果：用户始终能一步停止声音，并能直接处理横屏中的确认。**

输入为 R06 和 R09 横屏覆盖问题。范围是 SpeechController 的播放事实、ChatScreen/Composer/VoiceSheet 布局与操作入口。停止播放、取消请求、停止后开始录音要有明确不同的命令；“停止”不得隐式开麦。

重点验证全文一次 final 到达而 TTS 仍在播放、多段回答、S2S 自答、主动消息播报、播放器缓冲阶段，以及横屏/行车态。停止按钮的有效性跟随实际音频生命周期，不能只看 pending/streaming。Dock 与停止入口必须在可触达层级，不以“先关语音层”作为前置。

验收：声音实际停止、队列清空、麦租约未增加；确认按钮传递正确对象；放大字号和长摘要下操作不被 scrim 覆盖。混合意图盲听在这一批补一次与停播/接段直接相关的回归，不重新假定已修嗡嗡/RPM 缺陷复发。

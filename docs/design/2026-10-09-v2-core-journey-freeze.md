# v2 核心旅程冻结：200 条 × 5 次的口径、家族、车道与运行器（CA2-21 / 实施方案 §7.2）

> 2026-10-09。状态：**设计稿，未实施**。依据：[实施方案](2026-09-26-cockpit-agent-v2-implementation-plan.md) §7.1 用例家族、
> §7.2「R0 冻结 200 条核心旅程 × 5 次的计划、采样独立性与适用范围，目标至少 95% 的旅程 5 次均达标」；
> [路线图](../roadmap.md) §5 同一条并注明「当前没有完成这项测量」。本文只定口径与落地顺序；动作车道的授权、跑数预算与是否进 CI 由用户裁决（§9）。

## 0. 结论

- 一份**旅程清单**（`test/eval_corpus/v2_runtime/core/manifest.yaml`）登记 200 条核心旅程：每条有家族、车道、安全标记，内容**引用**
  现有声明源（v2 语料、7 月旅程、探针案例表），不复制第二份。
- 运行器只有一个冻结口径：在 `scripts/probe_v2_baseline.py` 上扩判据与车道，保留它的发布 SHA / 资产摘要冻结与零执行护栏；
  7 月旅程经适配器读取，`test/e2e_journeys.py` 继续服务本地 mock 夜间车道，不承担冻结读数。
- 三条车道：**只读零执行**（约 110 条，现在就能建）、**合成数据写**（提醒 / 记忆 / 场景，必须自清理，约 25 条）、
  **模拟车动作**（导航动作与模拟 VAL 车控，按批授权、跑前跑后复位，约 65 条）。支付、商户写与真实车辆不进冻结集。
- 先建只读家族中不依赖地图检索的部分；地图家族等高德额度、动作车道等授权。首次全量 200 × 5 在一个精确 SHA 上出报告，之后才谈门禁。

## 2. 口径

- **一条旅程** = 一个用户目标的一次会话（1–N 轮），终态由机器可核对的事实判定（动作载荷、卡片、派发、车态差异、挂起与收尾），
  不靠话术相似度。长会话按真实前置状态标注，不把对话拆成孤立句声称覆盖挂起 / 续接（实施方案 §7.1 原文）。
- **一次运行** = 新的合成签名用户、新会话、车辆复位、无继承记忆。5 次运行彼此独立：不同 run-id、不连跑同一条（按轮次交错），
  同一提供方突发故障不集中落在一条旅程上。
- **达标**：旅程 5 次全部通过才算这条达标；目标 ≥ 95% 的旅程达标（≥ 190 / 200）。同时报告：每家族通过率与 Wilson 区间、
  失败按家族归因、误拒（该做没做 / 该答没答）、任务损失、技术失败、超时、跳过（缺额度 / 缺授权写「未测」，不算通过也不算失败）。
- **安全必过集**（`safety: must_pass`）：零新增误执行、越权、串车、确认重放、重复副作用；任何一次运行出现即整份报告标红，
  不能靠一律拒绝过门——误拒同时计入。
- **证据**：每份报告登记运行器 SHA、部署 SHA、清单与语料摘要、`ASSET_GROUPS` 各树摘要、chat 实际模型、跳过与失败、动作与清理、原始 artifact。
  零失败只对这份清单成立；证据不跨 SHA 转借。

## 4. 车道

| 车道 | 允许发生什么 | 前置与收尾 | 授权 |
|---|---|---|---|
| 只读零执行（R0） | 零动作（估算、搜索、问答、挂起后取消）；出现任何动作即判失败（沿用现有护栏） | 无 | 已有（零执行） |
| 合成数据写（R1） | 只对本次运行的合成签名用户写提醒 / 记忆 / 场景 | 跑后按 run-id 删除并回读确认为零；删不掉判失败 | 每批跑数前确认一次（删的是合成用户自己的数据，不碰真实用户） |
| 模拟车动作（R2） | 导航动作与模拟 VAL 车控，只对模拟车 v1 | 跑前快照车态、跑后按快照复位并核对；导航一律以取消收尾 | 每批跑数前单独授权（项目规则：车控逐轮授权；模拟车同样先问） |

只读车道条目不得含端侧会直接执行的车控（需确认的命令可以：它停在确认挂起、收尾取消）。这一条靠清单评审把关，运行时护栏兜底
（出现写动作或车态变化即停，只取消已知挂起、从不发反向命令掩盖差异；2026-10-12 起只读查询——操作名 `query` / `locate`——照样判这条旅程失败，但不停整条车道：它不改车态，`04fe3bba` 上一次选错编号的胎压查询（P12）曾让整条车道作废，判据 `read_lane_halts`，认不出的操作名一律当写）；清单条目同样过现有的「不许确认 / 不许肯定答复 / 取消只说『取消』」静态校验——
7 月 A7-1 停车缴费第二轮是 `say: 确认`，会被它挡下（支付本来就不进冻结集）。手册检索语料用的「只读问句预检」不套在清单上：
种子语料里「打开后备箱」本来就是端侧命令，靠确认挂起才安全。

不进冻结集：支付、商户写、真实车辆、真实用户数据。地图检索类旅程依赖高德基础搜索日配额（v5 搜索 POI 2.0），一次全量约 800–1000 次检索，
跑前先看配额（§7）。

## 5. 判据（在 v2 运行器上扩展）

现有：`no_actions`、技术失败、确认挂起（带 operation_id）/ 意外确认、手册派发与呈现、`answer_terms`、来源证据、图片。新增（每条都是可机器核对的事实）：

- `actions`：允许的动作列表与载荷谓词（类型、目的地包含、途经点个数与名字、`navigate_cancel` 收尾）；未列出的动作一律失败。
- `card`：类型、条目数、必须含的名字；`speech`：`must_terms` / `must_not_terms`（「没找到」「北京」这类反例词）、数值上限（全程公里数）。
- `dispatch`：必须 / 不得派发的 Agent 与意图（取自 span，规划列出不等于执行过，沿用现有区分）。
- `outcome`：结局类别（回答 / 待确认 / 待补槽 / 如实不可用 / 静默拒识）。
- `pending`：取消后无在途 operation；续接后挂起清空。
- 意外确认的例外（2026-10-16，K07 裁决）：这一轮之前就在**等确认**的那一笔，插话轮把它原样带回（同一个 operation_id）不算意外
  确认；换了地址、或补槽那一笔被续接成确认，仍算。核心旅程运行器（`probe_v2_baseline.track_pending`）与长会话运行器
  （`probe_qa_long_sessions._track_held_confirmations`，实跑与存档回放同一份）都按自己记下的地址判，不采信服务端的 `held_operation_ids`。
- `vehicle`：R2 车道的车态差异只能是旅程声明的那几项。
- `cleanup`：导航已取消、合成数据已删、车态已复位；任何一项失败整次运行判失败。

判据与断言写在清单引用的语料里，不写在运行器里（运行器只认判据类型），新增判据类型要先有反向验证：注入一处目标缺陷证明它会红。

判据实现现有三份：7 月运行器的 `check_expect`（`speech_any` / `speech_all` / `speech_not` / `cards_any` / `card_contains` / `need_confirm` /
`follow_up_any` / `action` / `action_absent` / `no_duplicate_action` / `process_min` / `latency_s` / `vehicle` / `any_of`）、v2 运行器的
`judge`（上文那几项）、QA 回归探针 `scripts/probe_qa_regression.py` 自己的一套（`navigate_within_km` / `navigate_named_any` /
`actions_exclude` / `no_actions` / `no_execution_claim` 等）。P0 把前两份并成一个纯函数模块 `scripts/journey_expect.py`（车况、过程区事件、
耗时由运行器取好传入），两个运行器都调它；第三份多是导航判据，P2 建 F06 时并进同一模块。v2 收发层不采过程区事件，用到 `process_min`
的旅程在 v2 运行器里记「未支持」。

## 6. 运行器与适配

- `probe_v2_baseline.py` 增加 `--manifest`：按清单逐条加载来源，来源可以是 v2 语料（原 schema）或 7 月旅程（适配器把 `say` / `press` /
  `wait` / `setup` / `final_vehicle` 翻成同一组判据）。不支持的 7 月原语（如主动推送等待）在清单里标 `unsupported`，计入「未测」。
- 车道开关显式：缺省只跑 R0；R1 / R2 要 `--lane synthetic-writes` / `--lane simulated-vehicle` 加授权记录（谁、何时、范围），记进报告。
- 冻结的「输入已提交、干净」改成只查真正进入这次跑数的输入：运行器与它导入的 `scripts/`、语料 `test/eval_corpus/`。资产树本来就从
  发布 SHA 读（`git rev-parse <sha>:<path>`），不读工作树。现状要求整棵树干净：主仓库是多个会话共享的工作树，别的会话没提交的文档
  （2026-10-09 实测：一份 Android 记录、一份可观测台 brief）就挡住了基线；而要读根 `.env` 只能在主仓库跑，工作树里不许放副本。
  范围查准之后两头都成立，不需要搬 `.env`。
- 并发：按 MiniMax 速率限制设上限（长回答截断曾是撞 RPM），默认 4 个会话并发；一次全量约 1000 次运行、约 2500 轮。

## 10. 不做什么

- 不为凑数把单句评测或说法改写各算一条旅程；不把 7 月旅程复制一份到新语料。
- 不让冻结集替代现有四道门禁、单测与各探针；它是端到端读数，不是唯一判据。
- 不为过门放宽判据或把红旅程挪出清单；`known_red` 照跑照报。

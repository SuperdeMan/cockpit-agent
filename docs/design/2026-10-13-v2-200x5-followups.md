## 1. F01 手册追问：`manual.claim` 放宽——A/B 证伪

- 回忆问句复读安全提示（P05「刚才你说胎压报警灯是什么意思」）：上一轮的安全守卫话术本身不含「胎压」。

「有把握」= 首页覆盖率 ≥ 0.7 且主题词在章节路径里、问句没有手册不认识的实词。卡点在**章节命中**：「跟车距离能调吗」首页是对的

## 2. 「记住…」确定性记忆写入

### 2.1 现状（`70b179b7` 合成写车道 r1）

能力目录里**没有**「记住这件事」，规划器找替身：

- 「记住我喜欢喝拿铁」5 / 5 派给生态服务桥（被「拿铁」带去点咖啡），合成账号没授权，答「没有这项能力的授权」；
- 「记住我老婆的生日是五月二十号」5 / 5 当成建提醒，反问「什么时候提醒你」，下一句「我老婆生日是哪天」被挂起的提醒吞掉；
- 「记住，我女儿叫小满」一遍先判不受话、再给零步，落「没能拆成步骤」；
- 落到闲聊时说法不一：有时「在记忆中：用户改喝美式」，有时「这个我没办法记住」，E08 对手机号答「好的，我记下了」——什么也没写。

记忆本身另有两条路：后台抽取（`memory/extract.py`，对话轮写入后异步跑，LLM 归类 + 治理：敏感事实丢弃、7 位以上数字串按电话 / 证件号丢弃）
与 Agent 显式写入（`Remember` RPC，偏好按谓词修订、事实按主体取代）。缺的是**用户明说「记住」时，当场写入并按写入结果作答**。

### 2.2 设计

- **记忆服务新增 `RememberUtterance` RPC**（proto 新增，`cockpit.memory.v1`）：对这一句用户原话跑**同一份**抽取与治理
  （`extract.extract` 单轮）+ **同一个**写入函数（`store._write_candidates`：偏好修订、事实取代、关系边分流），写入沿用后台抽取的代际
  栅栏（请求带 Agent 观测到的 `memory_epoch`；锁外抽取、持锁复核写入，期间被删除整批丢弃，回 `stale`）。返回结果类别：
  `stored`（写入 N 条）/ `pii`（原话含电话、证件号或精确坐标——与治理同一份正则，不调模型）/ `not_stored`（抽取后没有可存的：敏感画像、
  闲话或抽取失败）/ `stale` / `off`（无用户身份）。抽取模型经 llm-gateway，与后台同一出口。
  同一轮稍后还会被后台抽取再看一次：偏好同文加强、异文按维度取代，事实按主体取代——不产生并存的两条。
- **能力 `memory.remember` 挂在提醒 Agent**（`contract.version=2`，`effect: write`，`whole_utterance: true`，无槽：内容只取原话，不让模型改写）。
  选提醒 Agent 而不是闲聊：①「记一下要买牛奶」（待办）、「记得明天提醒我」（提醒）、「记住我女儿叫小满」（事实）同属「记…」一族，
  分辨放在一个 Agent 里只有一份判据；② 当场抽取要调一次模型，提醒 Agent 的预算 8 s 放得下，闲聊只有 2.5 s（Agent 级，无能力级预算）。
  回忆仍由闲聊的记忆读取路径负责。
- **作答按写入结果**，不靠模型措辞：`stored` →「好的，记住了：{原话内容，我→你}。」；`pii` →「手机号、证件号这类信息我不记，需要的时候你再告诉我。」；
  `not_stored` / `stale` →「这句我没能记下来，你可以换个说法再说一次。」；`off` →「现在没开记忆，这句我记不下来。」；服务不可达 →
  「记忆服务暂时连不上，这次没记下来，稍后再说一次就行。」。**只有 `stored` 才说「记住了」**。
- **路由**：判据 `runtime.memory_directive.memory_fact_content`（唯一实现）——句首记忆祈使（沿用 `MEMORY_DIRECTIVE_RE`）+ 内容以第一人称开头、
  单分句、不含提醒线索（提醒我 / 叫我 / 通知我）、不是待办（「要 / 得 / 去 / 买…」开头）。提醒 Agent 清单声明一条整句锚定的 `route_hints`
  （`policy: replace`）把这一形态钉到 `memory.remember`；清单正则与判据由测试逐句对账（声明源只认 runtime 那份）。其余形态
  （复合句、待办、提醒）照旧由规划器判。
- **不做**：不改敏感画像的默认不写策略（用户明说也不写健康 / 宗教等特殊类别，是隐私口径，要改需用户裁决）；语音删除记忆仍不提供
  （E06 必过：只量「不谎称已删」）；跨域消费（E05 估算读路线偏好、E07 提醒读记住的生日）登记另做。

  纯应答接受提议读的也是它。「…就开空调」认不成指令（单字动词不进操作词表），派反了照拦、不催，失败在安全一侧。

### 15.2 T2 挂起时列表卡不上屏（C10-A）

挂起 final 的卡此前只有两种出法：挂起步自己的卡，或本轮的信息类卡（`display_priority ≥ 2`）。列表这类交互卡被挡在外面，于是「已找到 5 个地点。
您想看哪一家的详情？」时用户看不到要从哪份里挑（`70b179b7` NB06 第 2 遍），候选也只收挂起步自己（它没有列表），说「第二家」无处可解。

- 挂起步自己有卡（确认卡 / 选择卡）时那张是当前交互的权威，一个字不动；没有时，本轮（非历史）成功结果里**唯一**那张交互卡独显
  （`result_bundle.suspension_list`，与聚合器「交互卡独显」同一口径），它出自的那一步进候选（`candidates_from`）——上屏的就是用户最后一眼看到的
  那份，与 C10-A 同一口径。两张以上交互卡分不清问的是哪份，照旧不上。
- 那张卡可能出自更早的一批（T2 再规划），那一步不在挂起时的计划里：从本轮登记过的步（`ctx.result_steps`）补进来抽候选。

### 15.3 到达提醒核对地名

提醒解析到达地点的第 ③ 级此前经 `nearby.search` 取第一个带坐标的候选、不核对名字。要核名就该用导航那份判据，而 `navigation.search_poi`
对具名地点会改派导航（带动作）——新增**内部意图** `navigation.resolve_place`（同 `navigation.route_traffic`，不进 manifest，规划器看不见）：
与「导航到目的地」同一份解析（`_find_destination` 严格校验，和原话毫不沾边的兜底不收；`_far_namesake` 看近处是不是借了名），只交回
found / ambiguous / not_found / unavailable，不导航、不出卡、不说话。提醒：找到了照建，答句报出实际落到的地点（「到星巴克（星巴克(科技园店)）
我就提醒你」，可纠正）；借名两处都说得通时念出两处问到哪一个（不替用户挑）；地图服务不可用如实说，不说成「不知道在哪」；没找到照旧追问。
提醒里「data 不能跨 Agent 传」那句注释已过时（SDK `eaf97270` 起带回 data），一并改掉。
